# 安装说明 · GPT 核心版

> **状态**：旧那套（12 个脚本）已归档，不再参与运行。
> **现在只有两个脚本要装。**

---

## 一、装两个脚本

| 顺序 | 文件 | 作用 |
|---|---|---|
| 1 | `gpt_core/gpt_core_all.js` | GPT 提供的核心（9 个文件拼接，源码未改） |
| 2 | `okh_app/okh_app_all.js` | 应用层（配置、存档、钩子、调试） |

**顺序不能反。** 应用层要用 `window.OKHBackground`。

> 分开的源文件仍保留：`gpt_core/` 下 9 个，`okh_app/` 下 5 个。
> 改完源文件后要重新拼接成 all 版。

装完刷新页面，控制台跑：

OKH_APP.init()

## 五、怎么工作

```
AI 回复
  ↓
MESSAGE_RECEIVED 钩子
  ├─ AI 报了 <time elapsed="30"> 且跨时段 → 推进
  └─ 或每 3 条消息 → 推进 60 分钟
  ↓
GPT 的 advance()
  ├─ 检查保护期（ordinaryGraceMin = 120 分）
  ├─ 按 priority 给空闲角色选行动
  ├─ 检查事件、节点
  └─ 产出新状态
  ↓
应用层补两件事（GPT 核心没有的）
  ├─ 驱动力向基线漂移 + need 每轮 +2
  └─ 生成台账与监听
  ↓
存进变量池 okh_gpt.world
  ↓
下一轮 AI 生成时，世界书读到 {{getvar::okh_gpt.ledger}}
```

## 六、世界书怎么配

配两条就够：

### 条目 1 · 当前局势

```xml
<当前局势>
{{getvar::okh_gpt.ledger}}
</当前局势>
```

常驻（constant: true），插入位置 at_depth。

内容长这样：

```
【第 2 天 · 午后】
在场：妮丝（去喝一杯）、古兰
近况：
· 领主府放出消息，说要招几个手脚勤快的女仆，工钱给得比镇上高出一截。
```

### 条目 2 · 待演绎事件

```xml
<近期发生的>
{{getvar::okh_gpt.pendingText}}
</近期发生的>
```

**这一条很重要**——GPT 的队列是为了「让 AI 把这些事演出来」。

如果不配这条，事件只在后台发生，AI 不知道。

## 七、和旧版的差别

| 项目 | 旧版（已归档） | 现在 |
|---|---|---|
| 文件数 | 12 个 | 2 个 |
| 决策算法 | 效用打分 + 加权随机 | **priority 排序取最高** |
| 阶段推进 | corruption 自动推导 | **节点推进**（已配 3 个） |
| 活动占用 | 无 | **有**（120 分钟保护期） |
| 幂等 | 无 | **有**（同消息不重复） |
| 检查点 | 无 | **有**（可回滚） |
| 底线 | 内建 | 用 `allowed` 钩子实现 |
| 驱动力漂移 | 内建 | **应用层补的** |
| 数值翻译 | 有（36 条） | **没有了** |

### 两个要注意的地方

**① 数值翻译没了**

旧版会把 `corruption: 35` 翻译成「她开始找理由晚归」再给 AI 看。

现在直接给 AI 看数字（如果进了提示词的话）。

**台账里目前没有战斗数值**，只写「谁在哪、发生了什么」，所以暂时不影响。但角色心智那条如果要接，需要重新做翻译。

**② 决策可预测性变高**

GPT 用的是 priority 排序取第一个匹配。同样的状态，永远做同一件事。

要恢复随机性，得在每次推演前重建 config，给 priority 加扰动。这是待办。

## 八、出问题怎么查

| 现象 | 原因 | 怎么办 |
|---|---|---|
| `OKH_APP` 未定义 | 应用层没加载 | 检查 `okh_app_all.js` 是否启用 |
| `OKH_APP.init` 不存在 | 版本不对 | 重新拼接 |
| `world 初始化失败` | gpt_core 没加载 | 检查顺序 |
| 状态全 0 | 没初始化 | 跑 `OKH_APP.init()` |
| 时间不动 | 钩子没挂 | `OKH_APP_HOOK.attach()` |
| 事件不触发 | 时间没到 | `OKH_APP_DEBUG.queue()` 看队列 |
| 角色总做同一件事 | priority 排序的特性 | 见第七节② |
