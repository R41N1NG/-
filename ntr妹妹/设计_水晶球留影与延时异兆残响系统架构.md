## 一、延时反馈核心算法与状态机流转

### 1.1 三态生命周期（State Machine Lifecycle）

每个隐秘残响（`echo`）在后台引擎中遵循严格的时间推进与状态流转：

```
 [隐秘事件发生] (EventTime)
       │
       ▼
 ┌──────────┐  时间推进未达门槛 (Time < RevealTime)
 │  latent  │ ─────────────────────────────────► 表面平息无波，仅在现实留下隐微破绽
 └──────────┘
       │
       │ 时钟跨越门槛 (Time >= RevealTime)
       ▼
 ┌──────────┐  HUD 外观异化
 │  alert   │ ─────────────────────────────────► 晶球泛起暗影流光，提示“球体深处浮现未辨残影”
 └──────────┘
       │
       │ 玩家主动在画廊点击查阅
       ▼
 ┌──────────┐
 │ unveiled │ ─────────────────────────────────► 展开客观白描切片，激活白天的针对性行动胶囊
 └──────────┘
```

### 1.2 延时揭示公式（Delayed Reveal Formulas）

为避免即时告警带来的“机械打地鼠”出戏感，残响揭示统一遵循**「隔日魔力凝露」**算法：

$$\text{RevealMin} = \text{EventMin} + \Delta T$$

- **常规定量延迟（固定步长）**：
  $$\Delta T = 14 \times 60 = 840 \text{ 分钟（14小时）}$$
- **隔日对齐延迟（推荐：自然日锚定算法）**：
  夜间隐秘事件（通常发生于当日 21:00 ~ 24:00）统一沉淀至**次日午后魔力回流点（次日 14:00，即 $\text{NextDay}(14:00)$）**方才显影。
  
  *数学推导*：
  $$\text{TargetDay} = \lfloor \text{EventMin} / 1440 \rfloor + 2$$
  $$\text{RevealMin} = (\text{TargetDay} - 1) \times 1440 + 14 \times 60$$

*设计意图*：事件发生后，当事人早已在次日清晨穿戴整齐、强装镇定地与主角打照面；直到次日下午主人查阅水晶球时，才猛然获悉昨夜暗处的真相，制造出强烈的认知落差。

## 五、状态机结算管道（分模块契约）

1. **事件发生层（`okh_events.js` / `okh_nodes.js`）**：
   当特定隐秘事件结算时，生成一条 `echo` 记录压入 `playerState.memories`，初态标记为 `latent`，计算出对应的 `revealedAtMin`。
2. **时钟推进层（`okh_turn.js` / `okh_app_time.js`）**：
   在每次时间推进结算中，扫描全部 `latent` 残响：
   若 `world.timeMin >= echo.revealedAtMin`，原子更新状态为 `alert`，并在回执诊断中记录一条轻量提示。
3. **前台表现层（`okh_app_hud.js`）**：
   读取 `playerState.memories`，若存在 `alert` 状态条目，即时渲染水晶球微光动效与红点角标。
4. **查阅回执层（`okh_app_parse.js`）**：
   玩家在状态栏点击查阅某条残响时，前端申报 `<echo_read id="..." />`，状态机将其置为 `unveiled`，并可在白天解锁针对性探查的行动胶囊。
