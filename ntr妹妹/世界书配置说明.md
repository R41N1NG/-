# 世界书配置 · 把系统算出的东西喂给 AI

> 这一步不做，系统算得再准，**AI 也看不见，玩家更感觉不到**。
> 装完脚本后必须配这个。

---

## 一、为什么要配

现在的链路是这样断的：

```
脚本推演 → 写进变量池 → ❌ 断在这里 → AI 什么都没看到
```

世界书就是那根线——它的作用是**把变量池里的东西，注入到 AI 每次读的上下文里**。

配好之后：

```
脚本推演 → 写进变量 → 世界书读变量 → AI 看到 → 玩家感觉到
```

---

## 二、配三条就够

### 条目 1 · 【当前局势】台账

| 项 | 值 |
|---|---|
| 触发方式 | 🔵 **常驻**（constant） |
| 插入位置 | `at_depth`（中景） |
| 内容 | 见下 |

```xml
<当前局势>
{{getvar::okh.ledger}}
</当前局势>
```

**这是最重要的一条。** 它让 AI 每轮都知道：现在第几天、什么时段、谁在场、最近发生了什么。

脚本会生成类似这样的内容：

```
【第 3 天 · 夜晚】
在场：古兰（抱臂站着）、妮丝（金发双马尾）
近况：
· 奥萝拉去接了份工，忙到很晚才回来。
· 妮丝在集市上摆了半天的摊。
· 塞西莉亚在教堂坐了一整夜。
```

### 条目 2 · 【角色心智】× 每个角色

每个角色一条，**关键词触发**（名字出现才加载）。

| 项 | 值 |
|---|---|
| 触发方式 | 🟡 关键词触发 |
| 关键词 | 角色名、外号、别称 |
| 插入位置 | `at_depth`（比台账略深） |
| 内容 | 见下 |

```xml
<角色档案_奥萝拉_心智>
{{getvar::okh.char_d1_aurora}}
</角色档案_奥萝拉_心智>
```

**注意变量名**：`okh.char_d1_aurora`，前面的 `okh.` 不能少——脚本写入时自动加了这个前缀。

这个变量里装的是「原始心智描述 + 当前状态」，比如：

```
性情柔顺，说话轻声细语，遇事先道歉。背负家中债务，靠做女仆的微薄薪水撑着。

【近期状态】她开始找理由晚归，说辞一次比一次顺。
```

**AI 看到的是描述，不是数字。** 这是故意的。

### 条目 3 · 【行为约束】（可选但建议）

| 项 | 值 |
|---|---|
| 触发方式 | 🔵 常驻 |
| 插入位置 | `at_depth`（较浅，权重高） |
| 内容 | 见下 |

```xml
<角色行为准则>
上面【当前局势】里出现的人，是这一时段真实在场的人。
不要凭空让不在场的人出现，也不要让在场的人无故消失。
他们最近做了什么，写在该角色的【近期状态】里——那是他们的真实状况，不是传闻。
不要替玩家角色做决定，也不要替 NPC 说出玩家没听到的话。
</角色行为准则>
```

这条很短，但**能防住最常见的两种崩坏**：凭空冒出不在场的人、AI 替玩家做决定。

## 三、变量名对照表

配世界书时容易写错变量名，对一下：

| 想显示什么 | 变量路径 | 谁写的 |
|---|---|---|
| 当前局势台账 | `okh.ledger` | `turn.runTurn` 每次推演后写 |
| 某角色心智 | `okh.char_d1_{角色id}` | `translate.writeCharD1` |
| 在场名单（原始） | `okh.present` | `turn.runTurn` |
| 当前时段 | `okh.sys.phase` | `turn.tick` |
| 累计分钟 | `okh.sys.total_min` | `turn.tick` |

**角色 id 是英文的**：`aurora` / `nise` / `eileen` / `cecilia` / `gulan`。
不是中文名——变量名里用中文可能出问题。

## 四、配完之后怎么验

### 第一步：确认变量有值

控制台跑：

```js
__OKH__.modules.turn.runTurn({ force: true })
console.log(__OKH__.modules.core.read('ledger', ''))
```

应该打印出台账内容。**如果是空的，说明还没跑过推演。**

### 第二步：确认世界书能读到

随便发一句话给 AI，然后看它的回复里有没有体现出「谁在场」。

或者更直接——在控制台跑：

```js
console.log(getvar('okh.ledger'))
```

能看到内容，说明变量在。

### 第三步：看 AI 反应

发一句「我去找奥萝拉」，如果：
- AI 说她在教堂 → ✅ 通了
- AI 说她在旅店 / 不知道她在哪 → ❌ 台账没生效

## 五、常见问题

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 台账一直是空的 | 没跑过推演 | `__OKH__.modules.turn.runTurn()` |
| AI 看不到在场信息 | 条目没设常驻 | 勾上 constant |
| 角色心智是空的 | 变量名写错 | 检查 `okh.char_d1_xxx` 的拼写 |
| AI 提到不存在的人 | 缺【行为约束】条目 | 配上第三条 |
| 台账内容不更新 | `<time>` 没解析到 | 看 AI 有没有输出 `<time elapsed="...">` |
| token 吃太多 | 台账太长 | 脚本已限制近况最多 3 条，改 `buildLedger` 的 `slice(-3)` |

## 六、和范例卡的对接说明

这套配置**没有新增任何东西**，全是范例卡已有的机制：

| 我们用的 | 范例卡的哪一部分 |
|---|---|
| `constant: true` 台账 | 动态台账层 |
| `at_depth` 插入 | 通用插入位置 |
| `{{getvar::...}}` 宏 | 变量宏注入 |
| 关键词触发的角色条目 | 角色双轨条目 |

唯一的区别是：**变量是我们脚本写的，不是 LLM 申报的**。

但 AI 不知道这个区别，它看到的只是文本。

## 七、配完之后的效果

配之前：

> 你：我去找奥萝拉。
> AI：你在教堂找到了奥萝拉，她正在祈祷。

配之后：

> 你：我去找奥萝拉。
> AI：你推门进去时，教堂里只有塞西莉亚一个人坐在长椅上。她抬起头，
> 说奥萝拉今天一早就去了领主府，到现在还没回来。

**差别在于：后者知道奥萝拉真的不在教堂，而且知道她去哪了。**

这就是系统算出来的东西，通过世界书，变成了 AI 知道的事。
