## 一、全局运转总章程（所有角色统一遵循）

1. **三源驱动数值变动**：
   - 角色的专属数值与通用好感度，均随着 **「时间推移」**、**「系统/世界事件」**、**「玩家行动（交互申报）」** 三条途径发生改变。
2. **数值达标触发节点事件与互斥校验**：
   - 当某一项专属数值或多项数值组合（专属数值、好感度等）达到设定门槛时，触发对应的**节点事件（`NODES`）**；所有事件与节点须声明合法 `mode` 与非空 `text`（`interaction` 事件的待选结局统一通过 `outcomes` + `<event_resolve>` 落地）。
3. **节点事件与交互选择分离**：
   - 角色不再使用独立抽象的堕落度数字条，而是**直接由节点事件严格单向推进其通用堕落阶段（`stage`：`0 → 1 → 2 → 3`，要求 `toStage > fromStage`）**；停留在当前阶段的挽回或应对选择归入 `mode: 'interaction'` 事件，不复用升级节点。
   - 现行数据结构版本为 `SCHEMA_VERSION = 2`，应用层按变更同源性拆分为 [`okh_app_data.js`](奥森德/src/app/okh_app_data.js)（数据）、[`okh_app_rules.js`](奥森德/src/app/okh_app_rules.js)（业务规则）、[`okh_app_time.js`](奥森德/src/app/okh_app_time.js)（跨日结算）、[`okh_app_migrate.js`](奥森德/src/app/okh_app_migrate.js)（存档迁移）与 [`okh_app_config.js`](奥森德/src/app/okh_app_config.js)（装配器），由 `OKH_APP.migrateSchema()` 对旧版存档执行非破坏式增量迁移。
4. **回执时间线默认语义（防跨午夜时间倒置）**：
   - 对话中仅对已挂起待决事项的应答（`<event_resolve>` / 节点完成）默认落在 **本轮起点 `start`**；本轮新发生的里程碑与叙事事实（`<prologue_step>`、`<move>`、`<bond>`、`<room>`、`<activity>`）统一默认落在 **本轮终点 `end`**，同时全标签支持可选 `at="start|end|N日 HH:MM"` 在 `[fromMin, toMin]` 时间窗内精确穿插结算。交互事件的 `outcomes` 支持选项级 `when` 适用条件与显式 `allowCancel` 门禁；旧活动未知 `releaseRule` 迁为 `manualRelease` 时保留 `migratedFromReleaseRule` 并登记于 `bg.migrationReport` 与台账提示，须由 `<activity op="finish|cancel">` 手动释放。
5. **阶段门控解锁进阶事件**：
   - 角色的部分进阶剧情与特定 NSFW 事件存在严格的阶段门槛，**只有当堕落阶段解锁到相应程度后才会出现**。

/** 计算女性角色当前互斥好感阶段（不设节点，随 affection 实时派生） */
function getAffectionTier(val) {
  if (val >= 90) return 'love';      // 阶段四 · 爱恋 (90~100)
  if (val >= 70) return 'intimate';  // 阶段三 · 亲密 (70~89)
  if (val >= 40) return 'friendly';  // 阶段二 · 友好 (40~69)
  return 'ordinary';                 // 阶段一 · 普通 (0~39)
}
