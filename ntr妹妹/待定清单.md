## 一、节奏参数

> 位置：`7_okh_turn.js` 的 `RHYTHM`

| 参数 | 当前值 | 含义 | 需要决定 |
|---|---|---|---|
| `everyMessages` | **3** | 每几条 AI 消息强制推进一次 | 多久推进一次？ |
| `minutesPerTick` | **60** | 每次推进多少游戏分钟 | 一次推进多久？ |
| `useAITime` | true | AI 报了时间是否优先用它 | 信不信 AI 报的时间？ |

### 影响

| 改小 | 改大 |
|---|---|
| 世界变化快，一天可能过得很快 | 节奏慢，玩家能细看每一段 |
| 玩家离开一会儿回来，变化大 | 变化平缓，但可能"没感觉" |

### 需要主人回答

1. **一个时段应该对应多少条对话？**
   - 现在：3 条 = 1 小时 → 一个时段（4 小时）≈ 12 条
   - 可能想要：3 条 = 半天？10 条 = 1 小时？

2. **AI 不报 `<time>` 的时候怎么办？**
   - 现在：用固定的 `minutesPerTick`
   - 还是：完全不信 AI，一律按固定节奏走？

## 二、行为参数

> 位置：`4_okh_agency.js` 的 `CONFIG`

| 参数 | 当前值 | 含义 | 需要决定 |
|---|---|---|---|
| `inertiaPerRepeat` | **0.25** | 做过的事，下次权重 +25% | 人多固执？ |
| `inertiaCap` | **4** | 惯性最多叠加到几倍 | 会不会一直做同一件事？ |
| `idlePerTurn` | **0.15** | 久没做的事，权重 +15% | 人多善变？ |
| `idleCap` | **6** | 闲置补偿最多几倍 | 冷门行为会不会突然冒出来？ |
| `noiseRange` | **0.20** | 随机扰动 ±20% | 人多不可预测？ |

### 怎么判断调得对不对

跑 `__OKH__.modules.debug.simulate(20)`，然后 `debug.status()` 看行为分布：

| 现象 | 说明 | 调法 |
|---|---|---|
| 每人只做 1~2 件事 | 惯性太强 | 降 `inertiaPerRepeat` 或 `inertiaCap` |
| 行为完全随机，不像人 | 噪声太大 | 降 `noiseRange` |
| 冷门行为从不出现 | 闲置太弱 | 升 `idlePerTurn` |
| 该做的事不做 | 闲置太强 | 降 `idleCap` |

**没有标准答案，得试出来。**

## 三、阶段阈值

> 位置：`2_okh_schema.js` 的 `STAGE_THRESHOLD`

| 阶段 | 当前阈值 | 含义 |
|---|---|---|
| `anomaly`（异常） | corruption ≥ **30** | 开始做"不太对"的事 |
| `sinking`（沉沦） | corruption ≥ **55** | 主动隐瞒、越界变常态 |
| `subjugated`（臣服） | corruption ≥ **80** | 底线大面积消失 |

### 需要决定

1. **三个阶段够不够？** 要不要加"挣扎期""回光返照"之类？
2. **阈值该是多少？** 现在 30/55/80，跨度 25。
   - 收紧到 25/50/75 → 变化更快
   - 拉开到 30/60/85 → 中间停留更久

## 五、角色数值（5 个全部待确认）

> 位置：`10_okh_data.js` 的 `ROSTER`

### 当前填的（**全部是肥鱼按设定粗估的**）

| 角色 | 驱动力 |
|---|---|
| 奥萝拉 | duty 70 / shame 65 / fear 50 / need 75 / loyalty 60 |
| 妮丝 | pride 80 / curiosity 75 / lust 40 / fear 30 |
| 艾琳 | pride 95 / duty 70 / fear 45 / shame 55 |
| 塞西莉亚 | duty 85 / loyalty 80 / shame 70 / need 60 |
| 古兰 | pride 75 / duty 90 / fear 20 / loyalty 85 |

### 需要主人逐条确认

这些数字决定了**她是什么样的人**。

举例，奥萝拉的 `need: 75` 意味着"很缺钱"，所以她会频繁去打工。如果实际设定里她没那么窘迫，这个数就该降。

| 要确认的 | 说明 |
|---|---|
| 每个角色的驱动力数值 | 0~100，决定行为倾向 |
| 每个角色的 `baseline` | 回归基准，一般等于初始值 |
| 每个角色的行动池 | 从 19 条里挑几条，挑哪几条决定她能做什么 |
| 每个角色的底线 | 哪些事绝不做、什么时候解封 |

### 特别要确认的三条"永不解除"底线

现在配的是：

```js
奥萝拉：    never_abandon（永远照顾孤儿）
妮丝：      never_abandon（永远欺负哥哥）
塞西莉亚：  never_abandon（永远不放弃孤儿）
古兰：      no_public_shame（永远不失态）
艾琳：      无（她的底线都会解封）
```

**这五条是角色的人设锚点**——堕落到什么程度都保留。要不要保留、保留哪条，需要主人定。

## 六、行动措辞

> 位置：`10_okh_data.js` 的 `ACTION_LIBRARY`

19 条行动的 `label` 和 `narration` 现在是通用措辞：

```
work_shift  →  label: '去做工'        narration: '去接了份工，忙到很晚才回来。'
pray        →  label: '去祈祷'        narration: '一个人待了很久，出来时神色平静了些。'
serve       →  label: '去侍奉'        narration: '陪着坐了一晚上，回来时脸色不太好。'
```

### 需要决定

1. **这些措辞合不合世界观？** 比如 `serve` 的 narration 够不够隐晦？
2. **要不要给不同角色不同的措辞？**

现在所有人共用一套叙述。但奥萝拉"去侍奉"和塞西莉亚"去侍奉"，场景应该不一样。

**当前系统做不到**——所有角色用同一条 `narration`。

如果要区分，需要加一个机制：角色可以覆盖行动文案。

```
现在的做法：action.narration 全局共用
可能的做法：npc.actionOverrides[actionId].narration 个体覆盖
```

**这是个待定的扩展点。**

## 九、确认流程

建议按这个顺序，一项一项来：

```
① 先定节奏
   推进频率、每次推进多久
   → 改 RHYTHM

② 再定角色
   五个人（或更多）的驱动力、行动池、底线
   → 改 ROSTER

③ 再定行为参数
   用 debug.simulate(30) 试，看行为分布合不合理
   → 改 CONFIG

④ 再定阶段阈值
   多快算"沉沦"
   → 改 STAGE_THRESHOLD

⑤ 最后定事件
   一个个写，写一个测一个
   → 改 EVENT_LIBRARY
```

**不要一次全改。** 改一项跑一次测试，出问题能立刻知道是哪项。
