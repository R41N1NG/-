## 三、状态栏

### 3.1 正则要替换成什么

正则会把 `<status_bar>...</status_bar>` 整块替换成两个空容器：

```html
<div class="okh-hud" data-okh-hud></div>
<div class="okh-watch" data-okh-watch></div>
```

**脚本会自动往这两个容器里填内容**（每 1 秒刷新一次）。

## 四、正则管道

酒馆 → 扩展 → Regex → 新建，**全局生效**。

### 正则 1 · 状态栏渲染

| 项 | 值 |
|---|---|
| 名称 | `[界面] 奥克赫斯 HUD` |
| Find | `/<status_bar>[\s\S]*?<\/status_bar>/g` |
| Replace | `<div class="okh-hud" data-okh-hud></div>` |
| 作用范围 | 仅格式显示（`markdownOnly: true`） |
| 不要勾 Prompt | ✅ |

> **为什么替换成空容器**：数据由脚本从变量池读，比从 XML 里解析更稳。

### 正则 2 · 流式隐藏

| 项 | 值 |
|---|---|
| 名称 | `[流式] HUD 隐藏` |
| Find | `/<status_bar>(?!.*<\/status_bar>)[\s\S]*$/s` |
| Replace | 空 |
| 作用范围 | 仅格式显示 |

> 打字机还没打完 status_bar 时，不让玩家看见原始 XML。

### 正则 3 · 草稿清洗

| 项 | 值 |
|---|---|
| 名称 | `[界面] HUD 草稿清洗` |
| Find | `/<status_bar>[\s\S]*?<\/status_bar>(?=[\s\S]*<status_bar>)/g` |
| Replace | 空 |
| 作用范围 | 仅格式显示 |

> AI 偶尔一次输出两个 status_bar，这条保留最后一个。

### 正则 4 · 标签清理（可选）

如果 AI 输出了多余的 `<content>` 标签：

| 项 | 值 |
|---|---|
| 名称 | `[界面] content 标签清理` |
| Find | `/<\/?content>/g` |
| Replace | 空 |

## 六、和世界书的对接

主人的世界书条目，只需要确认一件事：**有没有用到下面这几个变量**。

### 6.1 系统产出的变量

| 变量名 | 内容 | 谁用 |
|---|---|---|
| `okh_gpt.ledger` | 世界台账（时间、在场、近况） | 「当前局势」条目 |
| `okh_gpt.pendingText` | 待演绎事件文本 | 「近期发生」条目 |
| `okh_gpt.watch` | 监听快照（JSON） | 调试用 |
| `okh_gpt.world` | 完整世界状态（JSON） | **不要注入提示词** |

### 6.2 如果世界书没写变量

把对应条目内容改成：

```xml
<当前局势>
{{getvar::okh_gpt.ledger}}
</当前局势>
```

```xml
<近期发生的>
{{getvar::okh_gpt.pendingText}}
</近期发生的>
```

### 6.3 如果世界书已经写好了

那就检查三件事：

| 检查 | 为什么 |
|---|---|
| 有没有引用不存在的变量 | 引用了会显示空白 |
| 有没有把 `okh_gpt.world` 写进去 | 几 KB 的 JSON 会吃爆 token |
| 角色的 id 对不对 | `aurora` / `nise` / `eileen` / `cecilia` / `gulan` |

## 七、验收步骤

### 第一步 · 脚本层

```js
OKH_APP.status()
```

看到五个人的表 → 通过。

### 第二步 · 界面层

发一句话给 AI，看有没有出现：

```
❖ 第 1 天 · 上午                    06:00
📍 断剑与麦酒
👥 妮丝　古兰　爱德
```

出现 → HUD 通了。

### 第三步 · 推进层

连发 3 条消息，看时间有没有变。

或者控制台跑：

```js
OKH_APP.step(240)
```

看 `OKH_APP.status()` 里的时间变没变。

### 第四步 · 台账层

```js
OKH_APP.ledger()
```

看到格式化文本 → 可以喂给世界书了。

### 第五步 · AI 层

发一句「我去找奥萝拉」，看 AI 的回答里：
- 有没有说她在哪
- 说的位置和 `OKH_APP.status()` 里的一致吗

**一致 → 世界书生效了。**

## 八、已知问题（组装后会遇到）

| 现象 | 原因 | 临时处理 |
|---|---|---|
| HUD 一直是"第 1 天" | 钩子没挂上，或没推进 | `OKH_APP.step(60)` 手动推 |
| 在场的人不对 | 位置没同步 | 见下面 |
| AI 说的人不在场 | AI 没读台账 | 检查世界书条目有没有引用变量 |
| 监听面板看不到 | CSS 默认 `display:none` | 取消注释那行 |
| 刷新后数据丢失 | `getvar` 不可用 | 看 `OKH.OKH_APP_WORLD.store.mode` 是否为 `tavern` |

### 位置没同步的问题

玩家说"我去教堂"，但系统里 `playerLocation` 还是 `inn`。

**原因**：`advance` 的 `front.playerLocation` 参数，我们从来没传过。

**临时处理**：控制台手动改：

```js
const w = OKH_APP.world()
w.playerLocation = 'church'
OKH_APP.save(w)
```

**正式修复**：见 `缺口清单.md` 的 I2，要解析 AI 输出的 `<move>` 标签。
