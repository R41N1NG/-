## 一、设计边界（系统做减法）

1. **不做**负重、耐久、装备属性词条、独立商城界面，也不将已有的 `-2 金` 实物 `<bond>` 拆分为“先买后送”两步。
2. **权责分离**：
   - **已注册物品（`ITEM_CATALOG`）** 严格由后台事件、跨日结算与 `<economy op="buy_supply">` 原子增删，禁止模型凭空刷取或篡改。
   - **玩家自添的非注册物品** 后续交由外部变量扩展（MUV）写入；本状态机在数据结构校验、效果结算与手札渲染上提供 `custom: true` 兼容槽位，只展示与保护、不附加后台数值效果、不误删覆盖。

---

## 二、数据结构契约

存放位置：`world.playerState.inventory`（数组，默认开局含 `[{ id: 'supply', count: 10 }]`）。

1. **已注册物品记录（最小真源）**
   ```js
   { id: 'supply', count: 10 }
   { id: 'alice_ledger', count: 1 }
   ```
   名称、分类（`quest` / `supply`）、说明、堆叠上限与单价全部由 `OKH_APP_DATA.ITEM_CATALOG[id]` 单源查表提供。

2. **外部扩展（MUV）兼容记录**
   ```js
   { id: 'custom:silver_ring', name: '银纹指环', category: 'supply', count: 1, desc: '集市摊位购得的小饰品。', custom: true }
   ```
   - `custom` 必须为 `true`；
   - `id` 不可与 `ITEM_CATALOG` 任一已注册 ID 冲突，且数组内不可重复；
   - `name` 须为非空字符串，`count` 须为正整数，`category` 可选 `'quest' | 'supply'`（缺省按 `'supply'` 渲染）；
   - 本状态机的 `itemsAdd` / `itemsRemove` 仅操作已注册物品，绝不修改或删除 `custom: true` 条目。

## 四、公式推导与跨午夜互斥过夜结算

### 4.1 经济定价锚点推导
- 旅店「断剑与麦酒」全队包宿费用 = **5 金 / 晚**；
- 常规满编小队人数 = 玩家 1 人 + 同行 4 人 = **5 人**；
- 令单人单日补给单价 = `5 / 5 = 1 金 / 份`，则：
  - 5 人队非旅店过夜成本 = `5 × 1 = 5 金`，与旅店宿费持平，既不会虚高，也堵住刻意夜宿镇上逃避旅店房费的套利漏洞；
  - 开局荒原 5 人小队自带 **10 份** = 刚好支撑 `10 / 5 = 2` 晚行程（若中途救下爱德变为 6 人，第 2 晚即触及补给紧缺边界，贴合开局文本的旅粮紧张基调）。

### 4.2 在场人数公式
$$\text{partySizeHere} = 1 + \left|\{\, n \in \text{world.npcs} \mid n.\text{monitored} = \text{true} \land n.\text{alive} \neq \text{false} \land n.\text{location} = \text{world.playerLocation} \,\}\right|$$

### 4.3 跨午夜过夜互斥矩阵（杜绝房费与补给双扣）

| 午夜所在条件 | 旅店宿费结算 | 补给消耗 | `supply_shortage` 旗标 |
|---|---|---|---|
| `playerLocation === 'inn'` | 走原旅店 5 金 / `inn_free_pass_today` / `inn_arrears` 结算（流亡或封爵免扣） | **0 份** | 若原为 `true` 则自动清回 `false` |
| `player_barony_granted && playerLocation === 'manor'` | 0 金（自家领主山庄） | **0 份** | 若原为 `true` 则自动清回 `false` |
| 其他任意 `playerLocation !== 'inn'` | **0 金**（当日未用 `inn_free_pass_today` 跨日作废） | 扣除 `min(当前补给, partySizeHere)` 份 | 若 `当前补给 >= partySizeHere` 置 `false`；若不足则扣至 `0` 并置 `true` |

> **补给不足处理**：仅扣至 `0` 并置 `world.flags.supply_shortage = true`，在手札与隐藏台账标出「补给不足」供叙事承接；不附加额外扣血或强扣好感惩罚，防止艾琳荒原流亡线被死锁。镇内购入补给或回旅店过夜后自动解除。

## 五、老存档迁移策略（`schemaVersion: 2 → 3`）

在 [`okh_app_migrate.js`](奥森德/src/app/okh_app_migrate.js) 执行幂等迁移：
1. 补全 `world.flags.supply_shortage = false`（若缺失）；
2. 补全 `world.playerState.inventory`（若非数组，未抵镇前传存档补 `[{ id: 'supply', count: 10 }]`，已抵镇存档初始化为 `[]`）；保留既有合法 `custom: true` 条目；
3. 自动补齐进行中的剧情证物（若已持有则幂等跳过）：
   - `flags.alice_evidence_secured && !flags.alice_rescued` → 补 `alice_ledger`（1 份）；
   - `npcs.aurora.flags.aurora_eileen_intel_given && !flags.eileen_signal_fired && !flags.baron_purged` → 补 `manor_intel_note`（1 份）；
   - `flags.player_barony_granted` → 补 `barony_patent`（1 份）。
