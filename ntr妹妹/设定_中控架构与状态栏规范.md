## 一、 双层闭合契约 (Dual Enclosure Specification)

每一轮大模型的生成，必须严格遵循物理双层闭合结构：

```xml
<content>
这里是纯文学叙事正文。描写环境、对话、动作、感官反馈与表面神态。
</content>
<status_bar>
这里是纯结构化数据申报标签，文末输出且仅输出一组，供中控脚本解析与下一轮上下文接力。
</status_bar>
```

---

## 二、 状态栏字段清册：【内外分离 · 暗线心智机制】

遵循主人的核心裁定——**“NPC 内心标签客观存在，对玩家物理屏蔽，但必须让 LLM 保持可见”**。

这构成了极其精妙的**“双向信息隔离”**工程：
* **大模型视角（可见）**：LLM 在每轮生成文末输出 `<npc_mind>`，并在下一轮对话的历史上下文视界中读取该标签，从而能够牢牢锚定 NPC 的暗线算盘、阴谋或真实好恶，保证心智绝不遗忘；
* **玩家视角（不可见）**：前端 Regex 渲染引擎在将 `<status_bar>` 转化为可视化 HTML 卡片时，**直接过滤、剥离 `<npc_mind>` 字段**，玩家在屏幕上只能看到客观环境与生理指标，绝无法透视 NPC 内心。

### 模型申报输出格式模板（唯一契约 · 2026-11-07 修订）：

```xml
<status_bar>
  <time elapsed="30" end="1日08:30" />
  <move to="4F_Corridor" noise="silent" />
  <door state="reverse_locked" />
  <injury level="1" type="scratch" />
  <heal target="player" item="急救绷带" />
  <loot item="压缩饼干" />
  <eliminate target="npc_04" cause="异种袭击" />
  <acquire_key fragment="b1_power" />
  <focus npc="npc_01" />
  <npc_mind>[≤30字·暗线信标: 该NPC此刻的真实算盘、防备、恶意或谋算；UI端物理隐藏，仅在上下文内供LLM接续心智]</npc_mind>
  <threat_radar>[≤30字·走廊与天井传来的客观声音、抓挠与阴影动静]</threat_radar>
  <supply_radar>[≤30字·白昼某处传来的沉闷落地撞击声]</supply_radar>
</status_bar>
```

**格式纪律**：
1. `<status_bar>` 每轮**有且仅有一个**，位于正文之后；
2. `<time>` 为必填项，`elapsed` 为相对耗时（整数分钟，1~1440），`end` 为落幕时刻（`M日 HH:mm`），供漂移校验；中控的 `elapsedMinutes` 只从此处取料，取料优先级见《规范_真源裁定表》第二节第 3 条；
3. 动作类标签（`move`/`door`/`injury`/`heal`/`loot`/`eliminate`/`acquire_key`）**按事实发生才输出**，未发生即缺省，严禁输出空标签凑数；
4. 旧 `<elapsed>`、`<end_time>`、`<location>`、`<health_delta>`、`<stamina_delta>`、`<inventory_change>`、`<focus_npc>`、`<door_state>`、`<shelter_state>` 及独立 `<time_block>` 块**一律作废**，位置改由 `apt_mvu.player.room_id` 与 `world.nodes` 台账承载，增减改由 Reducer 计算。

## 四、 前端五重 Regex 工业级流水线

| 管道标识 | 匹配目标 | 替换行为与工程职能 |
| :--- | :--- | :--- |
| **`[界面] 状态栏渲染`** | `/<status_bar>[\s\S]*?<\/status_bar>/g` | 替换为 HTML 宿主容器，跨域调用中枢脚本挂载 HUD 面板，**在渲染逻辑中物理屏蔽 `<npc_mind>`** |
| **`[流式] 状态栏流式隐藏`**| `/<status_bar>(?!.*<\/status_bar>)[\s\S]*$/s` | 流式打字时隐藏未闭合标签，防止玩家在生成过程中窥探到 XML 内的 `<npc_mind>` 或杂乱源码 |
| **`[界面] 状态栏草稿清洗`**| `/<status_bar>[\s\S]*?<\/status_bar>(?=[\s\S]*(?:<status_bar>|<content>))/g` | 物理清洗思维链或多阶段输出残留的废弃旧状态栏 |
| **`[微调] 提示词上下文视界`**| 自定义规则（按需） | 保留最近 1~2 轮的 `<status_bar>` 供模型读取 `<npc_mind>` 锚定暗线动机，更早历史则定期压缩净化 |
| **`[界面] 开局机缘网关`** | `/<apt_gateway>[\s\S]*?<\/apt_gateway>/g` | 第 0 楼挂载初始身份、出生点与随身工具选择面板 |

## 五、 Tavern Helper 变量池与单一真源 (Variables Pool)

**2026-11-07 修订**：本工程的变量命名空间统一收拢为 `apt_mvu`（详见[《规范_真源裁定表.md》](规范_真源裁定表.md) 第一节）。此前的 `apt_*` 扁平变量降级为**只读派生视图**，脚本读取时按下列路径取值，禁止直接写入：

| 旧扁平名（只读派生） | 真源路径 | 说明 |
| :--- | :--- | :--- |
| `apt_time_min` | `apt_mvu.system.total_min` | 绝对分钟真值，第 1 天 06:00 起算 |
| `apt_phase` | `apt_mvu.system.phase` | 宏观相位 `day` / `night` |
| `apt_player_hp` | `apt_mvu.player.hp` | 玩家健康值 0~100 |
| `apt_player_sta` | `apt_mvu.player.stamina` | 玩家耐力值 0~100 |
| `apt_player_loc` | `apt_mvu.player.room_id` | 当前物理节点 ID |
| `apt_player_shelter` | `apt_mvu.player.shelter_room` | 绑定的避难所房号，未绑定为 `null` |
| `apt_player_inventory` | `apt_mvu.player.inventory` | 背包数组，长度上限 6 |
| `apt_survivors` | 由 `apt_mvu.npcs` 派生 | 不落库，读时统计 `alive === true` |
| `apt_empty_rooms_crates` | `apt_mvu.world.items` 过滤 `status !== "looted"` | 派生视图 |

> 状态栏渲染、世界书台账注入、Reducer 结算三处**必须读同一份 `apt_mvu`**。任何脚本若发现自己需要写入第二份副本，说明口径已偏离本规范，须回到裁定表核对。
