## 一、系统定位

### 1.1 解决什么问题

不做这个系统，角色只会「等玩家来推」：

- 玩家不找奥萝拉，她就永远在小镇站着
- 玩家不去赌场，妮丝就永远不会被诱惑
- 整条堕落线全靠玩家手动触发，一旦玩家分心，世界就静止

做了这个系统，角色会**在后台自己过日子**：

- 奥萝拉缺钱 → 自己接领主府的活 → 次数变多 → 底线退让
- 妮丝闲不住 → 自己跑去赌场 → 被摸 → 好奇大于反感
- 玩家三天不理她们，回来时世界已经变了

### 1.2 三条设计原则

| 原则 | 含义 | 反面 |
|---|---|---|
| **确定性** | 同样的状态 + 同样的种子 = 同样的结果 | 每次刷新随机跳变，角色像精神分裂 |
| **渐进性** | 一次只跨一小步，不许一夜崩坏 | 一个回合从圣女变娼妇 |
| **可解释** | 每步决策能说出「为什么」 | 黑箱，出问题时查不出原因 |

### 1.3 不做什么

- ❌ 不生成正文小说（那是 AI 的活）
- ❌ 不替玩家做决定
- ❌ 不直接改玩家角色（伯里）的状态，只提供他被观测到的信息

## 二、核心设计

### 2.1 时间模型

```
世界时间 = 第 N 日 · 时段
时段：清晨 / 上午 / 午后 / 傍晚 / 夜晚 / 深夜
```

**推进规则**：每 `3~5` 个对话回合推进一个时段（可配），或由剧情事件强制推进。

> 为什么不用「回合」而用「时段」：酒馆是对话驱动的，一个对话回合可能只是说了一句话。用时段做单位，世界的变化节奏才和叙事节奏对得上。

### 2.2 角色模型（三层）

```
┌─────────────────────────────────────┐
│  第一层：阶段（Stage）                │  状态机，决定行为库的上限
│  正常 → 异常 → 沉沦 → 臣服            │
├─────────────────────────────────────┤
│  第二层：驱动力（Drives）             │  0-100 的连续值，随事件涨落
│  自尊 / 责任 / 欲望 / 恐惧 / 羞耻 / 匮乏 │
├─────────────────────────────────────┤
│  第三层：行动（Actions）              │  效用打分，从中选一个执行
│  由阶段 + 驱动力 + 底线共同筛选        │
└─────────────────────────────────────┘
```

**为什么要分三层**：

- 只有阶段 → 太僵硬，同一阶段内行为千篇一律
- 只有驱动力 → 太松散，可能做出完全不符合人设的事
- 阶段管「能做什么」，驱动力管「更想做什么」，底线管「绝对不做什么」

### 2.3 驱动力设计

不是所有角色都有全部驱动力，按人设配置：

| 驱动力 | 含义 | 高值时的行为倾向 |
|---|---|---|
| `pride` | 自尊 | 拒绝屈辱、强调身份 |
| `duty` | 责任 | 忍耐、牺牲、守约 |
| `lust` | 欲望 | 主动靠近、身体先于理智 |
| `fear` | 恐惧 | 回避、顺从、不敢声张 |
| `shame` | 羞耻 | 遮掩、否认、逃避视线 |
| `need` | 匮乏（钱/资源） | 接受交易、冒险 |
| `curiosity` | 好奇 | 试探、靠近未知 |
| `loyalty` | 忠诚 | 维护某人、隐瞒、牺牲 |

### 2.4 底线（Bottom Line）

每个角色有一组底线，每条底线有**解锁阈值**：

```js
{
  id: 'aurora_no_body_contact',
  desc: '拒绝与领主的身体接触',
  holdsWhile: { corruption: '<30' },   // corruption < 30 时有效
  blocks: ['accept_lord_touch', 'serve_lord_night']
}
```

**底线存在时，被它封住的行动权重直接为 0**——不是降低，是归零。

**这是保证「不 OOC」的最后一道闸门。** 无论驱动力怎么变，只要底线还在，角色就绝对做不出越线的事。

### 2.5 惯性 + 闲置（行为要有节奏）

**只加惯性会锁死。** 做过的事越做越多，没做过的永远轮不到——v0.1 原型就陷进了「一直在祈祷 / 一直在作弄哥哥」的死循环。

所以权重必须成对给：

```
score = base × (1 + inertia × min(count, 4)) × (1 + idle × min(idleTurns, 6))
        └─ 做过的加成 ─┘                    └─ 久不做的补偿 ─┘
```

| 参数 | 默认 | 作用 |
|---|---|---|
| `inertiaPerRepeat` | 0.25 | 每做过一次 +25% |
| `inertiaCap` | 4 | 惯性计数上限（最多 +100%） |
| `idlePerTurn` | 0.15 | 每闲置一时段 +15% |
| `idleCap` | 6 | 闲置计数上限（最多 +90%） |

**两个上限都必须有。** 去掉 `inertiaCap`，一个行为做八次后权重就到 3 倍，永远压着别人；去掉 `idleCap`，一个行为三十时段没做过就涨到 5.5 倍，随机性被吃掉。

> 这一对机制合起来实现的是「**人有习惯，但不会只做一件事**」。
> 奥萝拉会反复接活（惯性），但也会抽空去看孤儿（闲置补偿），两条线交替——这才是活人。

### 2.6 观测（伯里视角）

伯里有预知天赋，所以他能"看到"一些东西：

| 观测方式 | 条件 | 信息精度 |
|---|---|---|
| **在场目击** | 同地点 | 完整 |
| **预知闪现** | 随机触发（概率随剧情推进上升） | 片段、模糊、无前因后果 |
| **传闻** | 他人转述 | 可能失真 |
| **一无所知** | 默认 | 无 |

**关键设计**：预知只给"画面"，不给"结论"。他可能看到奥萝拉在一个房间里，脸色不对，但不知道为什么。

> 这正好对应设定里「通过预知天赋看到画面 → 自欺'不可能'」——系统只负责给他看，怎么解释是他自己的事。

## 三、数据模型

### 3.1 角色状态

```js
{
  id: 'aurora',
  name: '奥萝拉',
  stage: 'normal',              // normal | anomaly | sinking | subjugated
  drives: {                     // 0-100
    duty: 70, shame: 65, fear: 50, need: 75, loyalty: 60
  },
  corruption: 0,                // 0-100 堕落度，只增不减
  sanity: 80,                   // 0-100 理智，可涨可落
  exposure: 0,                  // 0-100 曝光风险
  location: 'church',
  flags: {},                    // 剧情标记，如 { confessed_to_cecilia: true }
  history: [],                  // 最近 N 次行动 id
  lastActionAt: null
}
```

### 3.2 行动定义

```js
{
  id: 'aurora_extra_shift',
  label: '接领主府的额外班',
  stage: ['normal', 'anomaly'],
  requires: {
    location: ['town', 'manor'],
    drives: { need: '>60' },
    flags: { lord_offered_job: true }
  },
  effects: {
    drives: { need: -15, shame: +5, fear: +3 },
    corruption: +2,
    exposure: +1,
    setFlags: { took_extra_shift: true }
  },
  baseWeight: 30,
  narration: '奥萝拉接下了领主府的额外工作，回来时已经很晚。'
}
```

### 3.3 事件

```js
{
  id: 'evt_0001',
  day: 3, phase: 'night',
  actor: 'aurora',
  action: 'aurora_extra_shift',
  witnesses: ['nise'],          // 同场角色
  visibility: 'partial',        // full | partial | rumor | hidden
  text: '奥萝拉很晚才回到旅店，裙摆上有一点酒渍。'
}
```

## 四、决策算法

### 4.1 主流程

```
for 每个角色:
    1. 筛可用行动
       - 阶段匹配
       - 条件满足（地点/驱动力/标记）
       - 未被底线封锁
    2. 如果没有可用行动 → 默认行为（待在自己位置，什么也不做）
    3. 对每个可用行动算分
    4. 加权随机选一个（不是取最高分）
    5. 交给 effect 执行
```

**为什么加权随机而不是取最高分**：取最高分会让角色变成完全可预测的机器，同样的状态永远做同样的事。加权随机保留了「人」的不确定性，同时又让高权重的行为更常发生。

### 4.2 打分公式

```
score(a) = base(a)
         × Π modifier(a, state)
         × (1 + inertia × count(a))
         × personalityBias(char, a)
         + noise
```

**modifier 示例**：

| 修正器 | 规则 |
|---|---|
| `needMod` | `need` 越高，涉及赚钱的行动权重越高 |
| `shameMod` | `shame` 越高，涉及暴露的行动权重越低 |
| `fearMod` | `fear` 越高，涉及风险的行动权重越低 |
| `corruptionMod` | `corruption` 越高，越界的行动权重越高 |
| `companyMod` | 同场有谁，会影响（如伯里在场 → 隐瞒类行动权重上升） |

**noise**：`±20%` 的随机扰动，用可复现种子。

### 4.3 阶段推进

`corruption` 达到阈值时自动升阶：

| 阶段 | 进入条件 | 行为特征 |
|---|---|---|
| `normal` | 初始 | 只在安全范围内活动 |
| `anomaly` | `corruption >= 30` | 开始接受"不太对"的事，但会自我解释 |
| `sinking` | `corruption >= 55` | 主动性上升，开始隐瞒 |
| `subjugated` | `corruption >= 80` | 底线大面积消失，行为以"维持现状"为主 |

**升阶不可逆**（`corruption` 不下降），但 `sanity` 可以回升——这表示"她还能装回正常人"。

### 4.4 一个完整例子（奥萝拉 · 第 3 天午后）

```
状态：stage=anomaly, corruption=34, need=72, shame=58, duty=65
      location=town, flags={ lord_offered_job: true }
      历史：extra_shift × 3

候选行动：
  A. aurora_extra_shift     base 30 × needMod(1.4) × 惯性(1+0.25×3=1.75) = 73.5
  B. aurora_pray            base 25 × dutyMod(1.2) × 惯性(1.0)          = 30.0
  C. aurora_visit_beri      base 20 × loyaltyMod(1.1)                   = 22.0
  D. aurora_accept_gift     base 15 × corruptionMod(1.3) × 底线...       = 19.5

加权随机：A 有 50.6% 概率被选中
→ 选中 A：再次接下领主府的班
→ 结算：need -15, shame +5, corruption +2 → 36
```

**可解释性**：日志里会记下这次打分明细，出问题时能追到是哪一项权重导致的结果。

## 四·补 原型验证：跑出来的三个缺陷

`scripts/agency_demo.js` 是设计验证用的单文件原型（不入 `src/`）。v0.1 跑 12 个时段，暴露出三个会让系统原地卡死的设计错误：

| # | 现象 | 根因 | 修正 |
|---|---|---|---|
| 1 | 奥萝拉 12 个时段后 `corruption` 仍是 0 | **死锁**：`no_body_contact`（corruption<30 有效）封住了唯一能涨 corruption 的行动，而解锁它又必须 corruption≥30 | **底线只封「越界」行动，不封「渐进」行动**。接工作、侍奉晚宴、收礼都不封锁 |
| 2 | 妮丝 `corruption` 卡在 12 不动 | `sneak_casino` 消耗 curiosity（-10），几次后低于门槛，条件不满足，之后只剩不涨 corruption 的行动 | **驱动力向基线回归**：每时段 `drive += (baseline - drive) × 0.1` |
| 3 | 两人都陷进单一行为循环 | 惯性只增不减 | **惯性 + 闲置双修正**，各设上限（见 2.5） |

### 修正后的验证结果（20 时段）

```
奥萝拉  corruption=19  stage=normal
  extra_shift×6  help_orphans×7  pray×3  visit_beri×3  serve_dinner×1
  duty=93 shame=54 need=59 loyalty=67

妮丝    corruption=36  stage=anomaly
  sneak_casino×9  show_off×6  tease_beri×5
  pride=93 curiosity=45 lust=62 fear=56
```

三条判据全部通过：

1. **行为有多样性**：没有人卡在单一循环
2. **轨迹符合人设**：奥萝拉在「赚钱 / 照顾孤儿 / 祈祷」之间摆荡；妮丝在「炫耀 / 溜去赌场 / 作弄哥哥」之间摆荡
3. **阶段会推进**：妮丝在时段 19 从 `normal` 升到 `anomaly`

### 修正带来的三条通用原则

| 原则 | 说明 |
|---|---|
| **底线封越界，不封渐进** | 防死锁。任何"解锁条件 × 被封锁行动"的组合都要检查是否有渐进路径 |
| **驱动力要回归基线** | 否则一次性资源（curiosity）用完，角色就失去行为动机 |
| **加权重必须配上限** | 惯性、闲置、修正器，任何一个无上限的乘数最终都会吃掉其他所有选项 |

### 已知的调参空间

修正后 20 时段奥萝拉只到 corruption=19，还没跨过第一道门槛（30）。这是参数问题不是逻辑问题——想更快可以：调高 `extra_shift` 的 corruption 收益、或把阶段阈值降到 25、或提高 `needPressure`。

> 这三个旋钮留给主人定：**世界该多快变坏**，是审美问题不是技术问题。

## 五、模块划分

### 5.1 模块清单

| 模块 | 职责 | 依赖 | 是否需要 |
|---|---|---|---|
| `sm_core` | 状态容器：读写、订阅、快照 | 无 | 必需 |
| `sm_schema` | 数据结构定义、校验、默认值 | core | 必需 |
| `sm_rules` | 纯函数判定：可用行动、底线、阶段 | core, schema | 必需 |
| `sm_agency` | 决策：效用打分选行动 | core, schema, rules | 必需 |
| `sm_effect` | 结算：应用效果、生成事件 | core, schema, rules | 必需 |
| `sm_observe` | 观测：可见性过滤、预知抽取 | core, schema, rules | 必需 |
| `sm_turn` | 回合编排：推进时段、串联各模块 | 全部 | 必需 |
| `sm_persist` | 存档与版本迁移 | core, schema | 有持久化则必需 |
| `sm_ui` | 状态栏渲染 | core, schema | 有界面则必需 |
| `sm_log` | 分级日志、决策快照 | 无 | 有调试需求则必需 |

> **`sm_turn` 说明**：规范里没列这个职责，这里新增的理由是——「一次时段推进 = 解析 → 判定 → 决策 → 结算 → 观测 → 输出」这整条链路需要一个编排者。放进 `state_index` 会让装配入口带上业务逻辑，违反 2.4 节；放进 `effect` 又会让结算器管调度。所以单独一个。

### 5.2 依赖层级

```
L0   sm_core   sm_log                 ← 零依赖
      ↓
L1   sm_schema   sm_persist
      ↓
L2   sm_rules
      ↓
L3   sm_agency   sm_observe
      ↓
L4   sm_effect
      ↓
L5   sm_turn
      ↓
L6   sm_ui
```

`state_index` 在体系外，只负责装配。

### 5.3 数据流

```
① 时间推进
   sm_turn.tick()
     └→ 世界时间 +1 时段

② 逐个角色决策
   for char of 在场角色:
     sm_rules.availableActions(char)   → 候选列表（已过滤底线）
     sm_agency.decide(char, candidates) → 选中的行动 + 打分明细
     sm_effect.apply(char, action)      → 写状态 + 生成事件

③ 生成观测
   sm_observe.collect(events, viewer)
     └→ 按可见性过滤，产出「伯里知道什么」

④ 输出
   sm_turn.emit()
     └→ 世界快照（供提示词注入）
```

## 七、角色配置示例

### 7.1 奥萝拉（柔顺型）

```js
drives: { duty: 70, shame: 65, fear: 50, need: 75, loyalty: 60 }
lines: [
  { id: 'no_body_contact', holdsWhile: { corruption: '<30' } },
  { id: 'no_admit_to_beri', holdsWhile: { corruption: '<70' } },
  { id: 'must_help_orphans', holdsWhile: { corruption: '<95' } }  // 永不消失
]
```

> 第三条永不消失——**这是她的人设锚点**。无论堕落到什么程度，她都会去照顾孩子。留着这条，角色才不会变成空壳。

### 7.2 妮丝（雌小鬼型）

```js
drives: { pride: 80, curiosity: 75, lust: 40, fear: 30 }
lines: [
  { id: 'no_admit_weakness', holdsWhile: { corruption: '<60' } },
  { id: 'must_tease_beri', holdsWhile: { corruption: '<99' } }   // 永不消失
]
```

> `pride: 80` 高自尊 + `curiosity: 75` 高好奇 = 会主动去危险的地方，但嘴上绝不认。
> `must_tease_beri` 永不消失——她堕落成什么样都会继续欺负哥哥。

### 7.3 艾琳（骄傲型）

```js
drives: { pride: 95, duty: 70, fear: 45, shame: 55 }
lines: [
  { id: 'no_bow_to_locals', holdsWhile: { corruption: '<50' } },
  { id: 'resist_physically', holdsWhile: { corruption: '<75' } }  // 对应「挣扎更厉害」
]
```

> `resist_physically` 这条直接对应主人之前的要求——她会还手，而且一直还手到 corruption 75 才停。

### 7.4 塞西莉亚（道德型）

```js
drives: { duty: 85, loyalty: 80, shame: 70, need: 60 }
lines: [
```

## 十、设计取舍记录

| 决定 | 理由 | 放弃的方案 |
|---|---|---|
| 加权随机而非取最高分 | 保留人的不确定性 | 最高分选择（过于可预测） |
| 三层模型（阶段/驱动/行动） | 宏观可控 + 微观自由 | 纯状态机（僵硬） |
| 底线归零而非降权 | 保证绝不 OOC | 降权（可能仍然越线） |
| 时段而非回合 | 与叙事节奏对齐 | 每回合（变化过快） |
| 预知只给画面不给结论 | 符合"自欺"设定 | 直接告知真相（破坏张力） |
| `corruption` 不可逆 | 堕落没有回头路 | 可涨可落（削弱主题） |
| `sanity` 可回升 | 她能装回正常人 | 双不可逆（过于线性） |
