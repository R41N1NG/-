## 三、修复内容

### 3.1 A1 · 依赖获取时机

**修前**（危险）：

```js
const { core, schema, agency, presence, translate } = REG.modules
// ↑ 加载时就解构，此时后面的模块可能还没注册
```

**修后**（安全）：

```js
function dep(name) {
  const m = REG.modules[name]
  if (!m) throw new Error(`[OKH] 依赖未加载：${name}（检查脚本顺序）`)
  return m
}

function runTurn() {
  const core = dep('core')
  const agency = dep('agency')
  // ...
}
```

**差别**：顺序错了会**抛错并说出缺哪个**，而不是悄悄跑出空结果。

> 同一条原则在别处早就在用（`okh_rules` 里是 `const schema = () => REG.modules.schema`），只有 `turn` 和 `data` 两个文件漏了。现在统一。

### 3.2 A2 · 地点表

**修前**：`location: 'church'` 这样裸写，没人校验。

**修后**：`schema` 里新增唯一真源：

```js
const LOCATIONS = {
  town:   { name: '镇上',   outdoor: true  },
  inn:    { name: '旅店',   outdoor: false },
  church: { name: '教堂',   outdoor: false },
  manor:  { name: '领主府', outdoor: false },
  casino: { name: '赌场',   outdoor: false }
}
```

配套 `isLocation(key)` 校验函数。加地点只改这一处。

### 3.3 B1 · 时段表

**修前**：`turn` 里定义一份，`presence` 里靠字符串匹配，`data` 里写 `['morning','afternoon']`。

**修后**：`schema` 里唯一一份：

```js
const PHASES = [
  { key: 'deep_night', name: '深夜', from: 0,    to: 360  },
  { key: 'morning',    name: '上午', from: 360,  to: 600  },
  { key: 'afternoon',  name: '午后', from: 600,  to: 1020 },
  { key: 'night',      name: '夜晚', from: 1020, to: 1380 },
  { key: 'deep_night', name: '深夜', from: 1380, to: 1440 }
]
```

`turn.derivePhase()` 改成直接委托 `schema.phaseOf()`，不再自己实现一遍。

### 3.4 B2 · 标签规则表

**修前**（逻辑里写死）：

```js
if ((d.need ?? 0) > 60 && tags.includes('money')) push(1.4, 'need1.4')
if ((d.shame ?? 0) > 60 && tags.includes('expose')) push(0.75, 'shame0.75')
// ... 八条 if
```

**修后**（数据驱动）：

```js
const TAG_RULES = [
  { tag: 'money',     drive: 'need',      op: '>', val: 60, mult: 1.40 },
  { tag: 'expose',    drive: 'shame',     op: '>', val: 60, mult: 0.75 },
  { tag: 'risk',      drive: 'curiosity', op: '>', val: 60, mult: 1.35 },
  { tag: 'risk',      drive: 'fear',      op: '>', val: 65, mult: 0.70 },
  { tag: 'duty',      drive: 'duty',      op: '>', val: 65, mult: 1.25 },
  { tag: 'bond',      drive: 'loyalty',   op: '>', val: 65, mult: 1.25 },
  { tag: 'humiliate', drive: 'pride',     op: '>', val: 70, mult: 0.60 },
  { tag: 'risk',      drive: null,        op: 'sanity<', val: 40, mult: 1.20 }

```

加规则 = 加一行数据。**不动代码。**

## 四、依赖矩阵

`→` 表示"依赖"。**所有箭头都指向下方，没有一个反向。**

```
                  boot
                    ↓
                  core
                    ↓
                 schema ──────┐
                 ↓   ↓   ↓    │
              rules  │   │    │
                 ↓   │   │    │
             agency  │   │    │
                 ↓   ↓   ↓    │
                presence ─────┤
                    ↓         │
                translate ────┤
                    ↓         │
                  turn        │
                 ↓    ↓       │
               hud  debug ────┘
                    ↑
                  data（只被 debug.seed 调用）
```

**检查项**：

| 检查 | 结果 |
|---|---|
| 有无反向依赖 | 无 |
| 有无循环依赖 | 无 |
| `core` 是否零依赖 | 是 |
| `schema` 是否只依赖 core | 是 |
| 逻辑模块是否互相引用 | `agency→rules`、`presence→rules`、`turn→全部`，均为单向 |

## 七、以后加东西，改哪一处

这张表是判断"解耦好不好"的最终标准——**加功能要动几个文件**。

| 想加什么 | 只改这一个文件 | 会不会碰逻辑代码 |
|---|---|---|
| 一个新角色 | `10_okh_data.js` 的 `ROSTER` | ❌ 不用 |
| 一种新行为 | `10_okh_data.js` 的 `ACTION_LIBRARY` | ❌ 不用 |
| 一个新地点 | `2_okh_schema.js` 的 `LOCATIONS` | ❌ 不用 |
| 一个新时段 | `2_okh_schema.js` 的 `PHASES` | ❌ 不用 |
| 一条新的权重规则 | `4_okh_agency.js` 的 `TAG_RULES` | ⚠️ 只加数据行 |
| 一个新驱动力 | `2_okh_schema.js` 的 `DRIVES` | ⚠️ `translate` 会走 default |
| 一种新底线类型 | `2_okh_schema.js` 的 `LINE_TYPES` | ❌ 不用 |
| 改某个角色的人设 | `10_okh_data.js` 对应那一条 | ❌ 不用 |
| 改界面上显示什么 | `8_okh_hud.js` | ❌ 不用 |

**九种常见改动，七种完全不用碰逻辑代码。**
