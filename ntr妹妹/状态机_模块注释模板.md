# 状态机 · 模块注释模板

> 配套文件：`角色卡制作规范.md` v2.0
> 用法：新建模块时整段复制，按注释里的说明填空。
> **四必填字段（`@module` `@updated` `@status` `@reason`）缺一不可**，其余按需。

---

## 一、模块头注释（复制这段）

```js
/**
 * @module      sm_<职责>
 * @updated     YYYY-MM-DD HH:mm
 * @status      active
 * @reason      （一句话：为什么写这个模块 / 本次为什么改）
 * @deps        []
 * @provides    { }
 * @version     1.0.0
 * @history     见 状态机_变更记录.md#sm_<职责>
 */
```

### 字段分级

| 级别 | 字段 |
|---|---|
| 🔴 必填 | `@module` `@updated` `@status` `@reason` |
| 🟡 按需 | `@deps`（有依赖时） `@provides`（有对外接口时） |
| 🟡 可选 | `@version`（有版本管理需求时） `@history`（有变更记录时） |

### 填写说明

| 字段 | 怎么填 | 常见错误 |
|---|---|---|
| `@module` | 与文件名去掉 `.js` 一致 | 写成中文或缩写 |
| `@updated` | **真实修改时间**，精确到分钟 | 复制粘贴忘了改 |
| `@status` | `active` / `deprecated` / `legacy` / `archived` | 全部写 active |
| `@reason` | **说「为什么」，不说「做了什么」** | 「优化了一下」「改了点东西」 |
| `@deps` | 数组，无依赖可省略 | 漏写实际依赖 |
| `@provides` | 列出 `api` 里所有方法名 | 写了内部函数 |
| `@version` | 可选，仅在需要版本管理时填 | 写着 `1.0.0` 三年不改 |
| `@history` | 指向变更记录锚点，可选 | 留空占位 |

### `@reason` 正反例

| ❌ 错误（说做了什么） | ✅ 正确（说为什么） |
|---|---|
| 「加了治疗分支」 | 「用户反馈治疗量不随等级成长，改为走 ATK 系数」 |
| 「修了 bug」 | 「旧存档缺字段导致读档崩溃，补默认值兜底」 |
| 「重构」 | 「rules 里混了写状态的逻辑，拆出来后规则才能单测」 |

## 二、空模块骨架（复制这段）

```js
/**
 * @module      sm_example
 * @version     1.0.0
 * @updated     2026-11-08 06:00
 * @status      active
 * @deps        ['core', 'schema']
 * @provides    { doSomething, checkSomething }
 * @reason      （填写）
 * @history     见 状态机_变更记录.md#sm_example
 */

// ============================================================
// 私有区：模块内部实现，外部一律不准访问
// ============================================================

/**
 * 内部计算，不对外暴露
 * @param {number} raw 原始值
 * @returns {number} 修正后的值
 */
function _normalize(raw) {
  if (!Number.isFinite(raw)) return 0   // 非数字一律归零，防止 NaN 扩散
  return Math.max(0, Math.min(raw, 9999))  // 9999 = 上限常量，超出视为异常数据
}

// ============================================================
// 对外接口区：只放 api 里声明过的方法
// ============================================================

/**
 * 执行某件事
 * @param {string} id    目标标识
 * @param {Object} opts  可选项，缺省为空对象
 * @returns {{ok:boolean, value?:any, reason?:string}}
 *          失败不抛异常，统一返回 ok:false
 */
function doSomething(id, opts = {}) {
  if (!id) return { ok: false, reason: 'missing id' }
  const value = _normalize(opts.raw)
  return { ok: true, value }
}

/**
 * 只读检查，不产生任何副作用
 * @param {string} id
 * @returns {boolean}
 */
function checkSomething(id) {
  return Boolean(id)
}

// ============================================================
// 模块导出：形状固定，不多不少
// ============================================================

export default {
  id: 'sm_example',
  version: '1.0.0',
  deps: ['core', 'schema'],
  init(ctx) {
    // ctx 是依赖注入容器，这里只做绑定，不做业务初始化
  },
  api: {
    doSomething,
    checkSomething
  }
}
```

## 三、函数注释模板

```js
/**
 * （一句话说明做什么，不解释怎么做）
 * @param {类型} 参数名  （用途说明）
 * @param {类型} [可选参数=默认值]  （用途说明）
 * @returns {类型}  （返回值含义）
 * @throws （若会抛异常，写清什么情况下抛；不抛就写「不抛异常，失败走返回值」）
 */
```

### 必须写注释的四种函数

| 类型 | 为什么 |
|---|---|
| 导出函数 | 外部调用者需要知道契约 |
| 有副作用 | 调用者需要知道会改什么 |
| 参数超过两个 | 顺序容易记错 |
| 返回结构复杂 | 不写清没人会用 |

### 内部一行的辅助函数可以不写

```js
const _clamp = v => Math.max(0, Math.min(v, 1))   // 语义自明，不必注释
```

## 四、关键逻辑行内注释模板

以下四类**强制**加注释，不加视为不合格：

### 4.1 魔法数字

```js
const heal = atk * 1.5
// 1.5 = 治疗系数。与伤害系数刻意分开：伤害是 1.0，
// 治疗给 1.5 是为了让辅助位不至于太弱。改动需同步世界观文档。
```

### 4.2 边界判断

```js
if (hp <= 0 && !inRescueWindow) {
  // HP 归零不立即判死，留一回合救援窗口，
  // 否则玩家没有反应时间，体验极差。
  markDead()
}
```

### 4.3 兼容分支

```js
const level = data.level ?? 1
// 老存档没有 level 字段（1.2.0 之后才加），按 1 兜底，
// 不能写 0——0 会导致升级曲线除零。
```

### 4.4 反向 / 特殊逻辑

```js
for (let i = list.length - 1; i >= 0; i--) {
  // 必须倒序遍历：内部会 splice 当前项，正序会跳过下一个元素。
  if (list[i].dead) list.splice(i, 1)
}
```

## 五、废案标记模板

### 5.1 原地标记（尚未迁移时）

```js
/**
 * @module      sm_effect
 * @version     1.2.0
 * @updated     2026-10-20 14:30
 * @status      deprecated
 * @deps        ['core', 'schema', 'rules']
 * @provides    { apply }
 * @reason      结算逻辑耦合了界面刷新，无法单测
 * @history     见 状态机_变更记录.md#sm_effect
 * @deprecated_since  2026-11-08 06:12
 * @deprecated_why    结算与渲染混在一起，rules 无法独立测试
 * @replaced_by       sm_effect_v2
 * @archive_path      src/_archive/sm_effect_v1.2.0_20261108.js
 */
```

### 5.2 三个"废案必填字段"

| 字段 | 必须回答的问题 |
|---|---|
| `@deprecated_since` | 什么时候废的 |
| `@deprecated_why` | **为什么**废（不是"换成新的了"，是"旧的哪里不行"） |
| `@replaced_by` | 谁接手的 |

## 六、装配入口模板

```js
/**
 * @module      state_index
 * @version     1.0.0
 * @updated     2026-11-08 06:00
 * @status      active
 * @deps        ['全部模块']
 * @provides    { boot }
 * @reason      唯一允许认识所有模块的地方，负责装配与依赖校验
 * @history     见 状态机_变更记录.md#state_index
 */

import core    from './state/sm_core.js'
import schema  from './state/sm_schema.js'
import parse   from './state/sm_parse.js'
import rules   from './state/sm_rules.js'
import effect  from './state/sm_effect.js'
import persist from './state/sm_persist.js'
import ui      from './state/sm_ui.js'
import log     from './state/sm_log.js'

const MODULES = { core, schema, parse, rules, effect, persist, ui, log }

/**
 * 装配所有模块并校验依赖
 * @returns {{ok:boolean, missing?:string[], cycle?:string[]}}
 *          依赖缺失或成环时返回 ok:false，不启动
 */
function boot() {
  const names = Object.keys(MODULES)

  // 1. 校验声明的依赖都真实存在
  const missing = []
  for (const n of names) {
    for (const d of MODULES[n].deps) {
      if (!MODULES[d]) missing.push(`${n} → ${d}`)
    }
  }
  if (missing.length) return { ok: false, missing }

  // 2. 校验没有循环依赖（拓扑排序，顺带得到初始化顺序）
  const order = []
  const mark = {}
  const visit = (n, path) => {
    if (mark[n] === 2) return null
    if (mark[n] === 1) return [...path, n]   // 找到环
    mark[n] = 1
    for (const d of MODULES[n].deps) {
      const cyc = visit(d, [...path, n])
      if (cyc) return cyc
    }
    mark[n] = 2
    order.push(n)
    return null
  }
  for (const n of names) {
    const cyc = visit(n, [])
    if (cyc) return { ok: false, cycle: cyc }
  }

  // 3. 按拓扑序初始化，保证被依赖者先就绪
  for (const n of order) MODULES[n].init(MODULES)

  return { ok: true }
}

export { boot, MODULES }
```

## 七、快捷自检（每次保存前扫一眼）

```
□ 四个必填字段全在？（module / updated / status / reason）
□ @updated 是刚才的时间？
□ @reason 说的是「为什么」？
□ 新函数有 @param / @returns？
□ 魔法数字加了解释？
□ 有注释掉的死代码吗？（有就删或归档）
□ 依赖方向跑过 check-deps.js 了吗？
□ 该记的变更写进 状态机_变更记录.md 了？
```
