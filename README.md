# 分支剧本与事件引擎

供 **SillyTavern（酒馆）+ 酒馆助手（Tavern Helper / JS-Slash-Runner）** 使用的独立脚本插件。剧本、条件和奖励由脚本管理；主聊天模型只收到当前节点的指引。可选的辅助 API 负责判断自然语言事件和整理长文本。

## 安装与第一次运行

1. 下载仓库根目录的 [branch_story_tavern_helper_import.json](branch_story_tavern_helper_import.json)，或下载 [v1.2.0 ZIP 压缩包](branch_story_plugin_v1.2.0.zip) 并解压，取出同名 JSON。这是酒馆助手脚本导入文件，不是世界书文件。更新时先停用旧脚本，备份剧本和聊天进度，再导入新版，避免同时启用两份。
2. 在酒馆助手的脚本管理中导入，作为全局脚本启用。需要支持新版世界书 API、聊天变量和 `injectPrompts` 的酒馆助手。
3. 打开聊天，点击 **铅笔** 悬浮按钮。按钮可用鼠标或触摸拖动，位置保存在脚本设置中；拖动不会打开面板。运行页的当前节点与操作，以及“API”“事件”等页面可直接使用。切换到“剧本”页时，仅节点列表与编辑区默认模糊隐藏；点击 **🔒** 阅读剧透提醒，确认才解锁，取消保持隐藏。桌面也可用 `Alt+B`；宿主提供斜杠命令注册接口时可用 `/bse`。
4. 默认载入“停电酒店”示例，剧情注入关闭；行动选择与阶段核验默认开启，启用剧本且配置辅助 API 后才运行。独立事件的自动检查仍默认关闭。在“运行”页点击 **启用剧本**，会同时开启输入栏行动选项；关闭管理面板后，输入框上方显示当前可用的分支。
5. 在“数据”页填写世界书名称并点击 **写入世界书**，即可把当前剧本保存为条目库。保存前的草稿也会存在酒馆脚本变量中。

用户安装无需 Node、npm 或独立本地模型。停用脚本或卸载时，面板、监听和本插件的注入会随脚本退出清理。

v1.1.3 在运行页的“接下来的分支、已收集、关系与状态”区也加入 **🔒 + 模糊 + 确认解锁**。它与剧本页的节点区分别解锁；点击锁图标显示剧透提醒，取消或按 Escape 继续隐藏，确认才显示。解锁后可点击“🔒 隐藏分支与状态”重新锁定。当前节点、完成/暂停等操作与输入栏选项开关仍可直接使用。

两个区域的解锁仅在当前脚本运行期间有效；重新加载或打开另一剧本会重新隐藏。节点页工具栏可随时点击“🔒 隐藏节点”。锁定时节点区不可点击、不可通过键盘聚焦，并对屏幕阅读器隐藏。顶部导航、剧本导入导出和其他页面照常使用；解锁节点后才可删除选中的节点。

## 快捷选项与剧本内容导入导出

点击 **启用剧本** 会同时开启输入栏行动选项。运行页提供 **显示输入栏选项 / 关闭输入栏选项**，也可在“数据 → 选项与界面”修改并保存。升级时保留已保存的设置；若剧本原本已启用且选项关闭，直接点击 **显示输入栏选项**，或关闭注入后再次启用剧本。刷新不会自动覆盖你保存的关闭设置。关闭面板后，输入框上方直接列出“查看走廊”“寻找前台”等选项按钮，包括无条件可用和满足条件已解锁的分支；未解锁的分支不显示。点击选项会保留原草稿并加入行动文字，支持修改或撤销；发送后才记录选择、校验本地条件并切换节点，不自动发送。暂停、未启用剧本或当前没有可选分支时，整行隐藏。输入栏暂时隐藏后恢复、或由宿主重新创建时，选项也会重新定位和显示。输入栏只展示可选的行动标签，运行页的防剧透锁不会阻止选择。

v1.1.1 不再注册“分支剧本面板”这个酒馆助手快捷按钮，启动时也会清理当前脚本中同名的旧按钮，保留其他按钮。面板通过铅笔、`Alt+B` 或宿主支持的 `/bse` 打开。

“剧本”页顶部和“数据”页均提供剧本 JSON 导入、导出。导出的内容包括节点、分支、事件、变量定义、原文和分析报告，不含 API 设置、密钥或聊天进度。进度使用“备份当前进度”单独导出。剧本内容文件与插件安装 JSON 用途不同。

## 私有仓库下载与启动排查

当前插件属于酒馆助手脚本，不能把仓库 `.git` 地址填到酒馆扩展安装框。仓库为私有时，先登录有访问权限的 GitHub 账号，打开完整 JSON 或 ZIP 的文件页面，点击文件页的 **Download / 下载** 按钮保存。下载 ZIP 后需先解压，再导入其中的 `branch_story_tavern_helper_import.json`。

完整 JSON 包含全部插件代码，运行时无需联网读取仓库；辅助 API 功能仍按用户配置访问服务。私有仓库的匿名 Raw 请求会返回 404，CDN 也不能读取私有仓库。因此已移除旧版压缩包和根目录的在线加载文件；如酒馆中已启用旧链接加载脚本，请先停用，再导入完整 JSON 版。无需把整个仓库改为公开。

插件适配 `TavernHelper._bind` 并绑定当前脚本窗口，兼容浏览器中的 CommonJS 同名全局。铅笔入口在初始化开始时创建，初始化错误会显示，不因缺少变量接口静默退出。

如果导入完整 JSON 并启用后没有“剧本”按钮，优先确认酒馆助手的脚本功能总开关、当前脚本的启用状态及运行范围。脚本日志和面板中的初始化错误可用于继续定位。`window.__branch_story_startup__` 记录启动阶段，`window.__branch_story_ready__` 可用于等待启动结果。

## 使用剧本与分支

“剧本”页可编辑短指引、详细原文、完成标准、排除情况、完成效果和出口。出口支持“填入输入框的行动文字”与“自主输入识别标准”。输入栏按钮只是快捷输入：点击后保留原草稿并加入行动，支持“撤销待发送选择”；尚未发送时不会改变剧情或奖励。

v1.2.0 的实际流程：

1. 点击快捷选项或自主输入，然后由玩家发送。原样单一选项可直接匹配；自由输入、带原草稿或改写后的选择由辅助 API 从当前可选出口识别。歧义、假设或普通聊天留在当前阶段。
2. 酒馆等待选择识别后，记录玩家消息与分支，注入目标节点的文本用于**同一轮**主聊天生成。不可选的目标仍由本地条件拦截；一条输入只选择一个当前行动。
3. AI 回复生成结束后，辅助 API 读取本轮玩家输入和当前选中的 AI 正文，加上本阶段上一份短摘要、最多 8 条已核验事实、相关结果定义与状态，更新摘要并核验实际完成。
4. 完成证据通过且没有缺失标准时，脚本执行节点的预设效果、保存结果 ID、刷新可选出口。只有意图、看到物品或进入地点都不等于完成；模型不能自行发奖励。节点可关闭自动结算，改由人工确认。

阶段工作摘要最多 400 字符，事实最多 8 条且每条文字最多 160 字符；阶段结束后清掉工作摘要，长期结果保留去重 ID。`a`、`a1`、`ab` 是三个独立 ID；`a+b` 不会自动成为 `ab`，也不能按前缀匹配。原文中的结果含义保存在剧本定义内，本地判断条件只查已确认 ID。

“运行”页的“进入分支”和“确认完成本节点”仍是人工管理操作；进入分支不会自动完成旧节点。核验失败不会发奖励，可用“重新核验阶段进展”重试；自由行动识别失败时尚未推进，可重新生成以重试识别。模型判定仍须人工检查，引用校验不能保证语义理解无误。

停电酒店示例的走廊节点配置了“实际拾取并持有房卡”标准，前台节点配置了“查阅登记册并确认身份不符”标准。完成分别获得 `A`、`B`；返回大厅后，仅 A 解锁 D，仅 B 解锁 E，同时拥有 A+B 解锁 C。返回大厅不会隐含领取物品或完成调查。

**升级与测试：**先停用旧实例，再导入 v1.2.0 完整 JSON。旧剧本若没有完成标准，仍需手动确认，不能只靠升级自动结算。在“分析”页以“忠于原文”重新分析测试故事，核对草稿中的完成标准、效果 `collect` 和出口条件，应用为新剧本并启用后再实验。`雨夜的第七号库房` 应区分取得卡 `a`、取得码 `b`、验证成功 `a1` 和实际复位 `ab`。旧默认分析提示词会自动更新；用户自定义提示词保留，须自行加入新版 JSON 字段或恢复默认并保存。

同一节点的完成效果只执行一次。节点名称和正文可以很长，存档通过稳定 ID 引用。修改内容时保留已有 ID；删除已经访问的节点会被拒绝，以便先处理现有进度。节点编辑、批量 JSON 编辑和模型整理后都会校验引用和类型。

条件支持以下形式，可通过“必须拥有 / 必须没有”表单生成收集条件，再在 JSON 中扩展：

```json
{"all":[{"collected":"A"},{"collected":"B"}]}
```

```json
{"all":[{"collected":"A"},{"not":{"collected":"B"}}]}
```

```json
{"any":[{"completed":"N002"},{"variable":{"id":"trust","op":"gte","value":20}}]}
```

此外支持 `visited`、`event_completed`、`not` 和布尔条件。变量比较支持 `eq/ne/gt/gte/lt/lte`，大小比较只用于数值。

## 自定义事件与好感度

“事件”配置**聊天行为 → 已确认变化**。剧本节点负责剧情走向，事件规则识别正文中实际发生的行为，并更新好感度、收集记录等。分支可引用这些状态作为解锁条件；不需要行为记录的剧本可以不配置事件。

点击“用送花示例创建规则”会自动添加好感度数值变量、送花收集项，以及“实际送花并被接受 → 好感度 +1、记录收集项”的可编辑规则。“发生后的变化”用易读文字显示配置；效果 JSON、适用节点和身份 ID 收入高级设置。

基本操作：填写发生标准 → 添加发生后的变化 → 保存规则 → 在“运行”页识别当前回复 → 到“记录”页确认。勾选自动应用变化后，证据通过的完成结果会直接结算。“手动确认发生并应用变化”直接执行本条规则，不调用模型；一次性规则确认后按钮禁用，避免重复点击。

“事件”页提供名称、事件描述、完成标准、排除情况、主体/对象 ID、适用节点、前置条件、奖励、重复策略和自动结算开关。可设为辅助 API 判断或手动确认。整个项目仅一次和每条确认回复一次两种策略都有去重。

例如“送花”可以写成：

- 描述：玩家把花交给目标人物或为其佩戴，且对方接受。
- 完成标准：实际动作已完成。只有请求、打算送花或被拒绝不算。
- 排除情况：假设、回忆、转述、仅提议、拒绝。
- 效果：好感度增加 1。

在“数据 → 变量与收集项”中定义变量，例如：

```json
[{"id":"affection","title":"好感度","type":"number","default":0,"min":0,"max":100}]
```

然后为事件填写效果：

```json
[{"add":{"variable":"affection","value":1}},{"collect":"FLOWER_ACCEPTED"}]
```

效果还支持 `set`。数值增加会受上下限约束。关系变量和收集记录显示在运行页，完整预设不必进入主模型上下文。只有节点“相关变量 ID”中列出的状态会被注入。

辅助模型返回 `completed / proposed / rejected / not_occurred / uncertain`，并附上对话原文引用。脚本检查引用是否真的存在、主体是否匹配，再按本地配置结算。**原文校验能拦住虚构引用，不能证明语义判断绝对准确**；首次使用建议关闭自动结算，在记录页核对结果。未返回的候选会保留为“不确定”。

## 辅助 API 与开销

“API”页填写独立的 OpenAI 兼容地址、模型和密钥。只填域名（如 `https://你的服务`）会自动使用 `/v1/chat/completions`；带 `/v1`、其他自定义路径或完整 `/chat/completions` 地址也可使用。显式填写 `https://你的服务/chat/completions` 可调用不带 `/v1` 的聊天接口。v1.1.2 修正旧版只填域名时错误拼出双斜杠的问题。

填写地址与密钥后，点击“获取模型列表”即可从同一基础地址的 `/models` 接口读取完整模型 ID，并分别选择事件识别模型和剧本整理模型；仍可手动输入。获取列表使用 GET，不调用生成接口或计入生成 Token 用量。地址或密钥改变后隐藏旧列表，晚到的旧列表不会覆盖新配置；列表仅保存在当前插件运行内存中。模型列表能读取不代表聊天生成接口一定可用，选定模型后仍需“测试连接”，测试会发送一次很短的生成请求。

API 页会展示实际请求路径。失败时显示 HTTP 状态、请求地址、模型及服务返回的 JSON 错误说明（如 `model_not_found`），隐藏已填写的密钥与 URL 查询参数；不展示完整错误响应，也不自动重试生成请求。404 可能来自路径或模型，不宜仅凭状态码判断。原生 Gemini 等其他协议需使用服务提供的 OpenAI 兼容入口。不要发送密钥来排查错误。

服务需要允许酒馆所在浏览器的跨域调用（CORS）。插件直接从脚本发起请求，不自动借用主聊天 API 的密钥或绕过浏览器限制。请求失败会保留检查状态，可在记录页重试。服务不支持 `response_format` 时关闭 JSON 模式；“非思考”选项仅在服务支持 `chat_template_kwargs.enable_thinking` 时启用。

API 页直接显示六类**实际发送的 system 提示词**：事件核验、行动选择、阶段进展、基础拆分、剧本分析、跨段合并。可分别修改并点击“保存 API 设置”；“恢复默认提示词”先填回默认文本，保存后生效。每次自动填写的对话或剧本数据作为另一条 user 消息发送，字段说明可在同页展开查看。修改提示词仍需保留 JSON 返回协议，脚本继续检查证据、引用和结构。

- 默认每批 4 个候选，每次最多 3 批。达到上限会显示尚未检查的候选数量，由用户点击继续。
- 候选先按启用状态、节点范围、前置条件和一次性完成记录筛选。大量事件应设置适用节点，避免都作为全局事件。
- 识别默认发送上一条用户输入、当前选中的 AI 回复和相关变量，不发送完整剧本库和聊天历史。缺少上下文的事件可在记录页人工确认。
- 自由行动可能需要一次选择识别，阶段回复还需一次核验；按钮原样的单一行动可省去选择识别。阶段核验不发送多楼正文或整个剧本，长正文仍受输入预算约束。
- 输入限制以**字符数**计算，输出限制以 Token 计算；事件核验和基础拆分超限会拒绝请求，“分析”页则自动分块并逐次检查预算。
- 用量取自服务返回的 `usage`。没有 `usage` 的调用会标为未计数；错误请求仍可能被服务收费。

Token 消耗取决于回复长度、候选数量、描述长度和模型。插件能限制范围与每轮请求量，不能保证每次只有极少 Token。

密钥默认只保留在当前脚本运行的内存中，刷新后需重填。勾选“记住密钥”才会保存到酒馆脚本变量。**剧本导出、进度备份和本仓库的导入包不包含连接密钥**；自行使用酒馆助手导出脚本时，也应关闭变量数据导出或先清除密钥。

## 何时确认回复

独立“事件”规则的新 AI 回复先作为候选，不立即发奖励。启用“用户接话后自动检查”后，用户发送下一条消息才触发上一条选中回复的识别；也可以在运行页点击“确认此回复并识别事件”。结果默认由记录页人工接受。

请求绑定聊天、剧本版本和对话指纹。切换聊天、改变进度或在结果返回前修改来源，会阻止旧结果结算。对已经结算的旧回复做编辑、删除或 Swipe 会暂停剧本；先回退相关近期操作或恢复备份，核对进度后继续。

独立事件默认异步识别，当前这次主聊天生成可能使用之前已确认的事件状态；行动选择则必须完成后才合并当前生成的提示词，阶段核验在整条回复结束后进行。需要等待时，可在 API 页设置生成前最多等待的毫秒数。超过等待期限会继续生成，不无限阻塞。

## 整理长篇剧本

在“数据”页粘贴原文，可直接保存并手动创建节点，也可点击“调用辅助 API 整理为草稿”。整理模型可与事件模型不同。

模型输出经过校验后成为**可编辑草稿**，不会直接替换正在使用的剧本。原文完整保留，节点详细正文必须是原文连续摘录，节点 ID 由脚本生成；任意数值奖励或代码会被丢弃；原文有依据的结果定义、完成标准和收集条件可保留在草稿。界面会提示摘录覆盖不足，核对并编辑草稿后再显式应用为新剧本。

基础拆分一次整理预算以内的原文。需要自动分块、不同走向、结局与伏笔报告时，使用新增“分析”页。

## 分析长文本为新剧本

在“分析”页输入长文本和要求，选择“忠于原文”或“允许补充分支和结局”。默认只整理原文明确内容；允许补充时，新节点须标为建议，并与原文摘录区分。使用 API 页的剧本整理模型、分析提示词和独立输出预算。

分析结果包括阶段节点及连接、不同走向、结局、伏笔埋设与回收、待核对事项。超过单次输入字符预算时自动切割，依次分析各块，再用一次请求整合跨段连接，界面显示进度并可取消。最多 20 万字符、32 块、256 个节点；提示词或整合摘要超限时明确报错，需提高预算或分篇处理。分块分析会产生额外 API 用量，不能保证模型一定正确还原跨段关系。

结果保存为可编辑草稿，可单独导出，点击“应用分析草稿为新剧本”并确认后才切换。完整原文保留，原文节点的详细正文必须是连续摘录。脚本重映射所有节点引用，拒绝虚构摘录、无效连接或整合时遗漏节点；原文有依据的结果标记、完成标准和解锁条件会保留在草稿，确认应用后成为本地规则；缺少条件依据的出口会被阻止并提示核对，未定义结果或虚构摘录会拒绝分析。任意数值奖励和代码不应用。走向、结局和伏笔答案留在报告内，主模型继续只接收当前节点的指引。

## 存储、备份与状态栏接口

| 内容 | 位置 |
| --- | --- |
| 世界书剧本 | 清单、节点、事件分别保存为 JSON 条目；本插件条目关闭原生自动激活 |
| 未写入世界书的草稿、整理与分析草稿、API 设置、铅笔位置 | 酒馆助手脚本变量 |
| 当前节点、选择来源、短阶段进度、收集、变量、事件计数和去重记录 | 当前聊天的 `branch_story_engine.projects[剧本ID]` 变量 |
| 近期回退记录 | 最多 25 次操作的逆向变化，保存在聊天进度内 |

世界书读入内存后使用；生成时只注入当前节点，关闭世界书扫描。保存世界书保留其他条目和其他项目，更新当前项目时保留条目 UID。无需把世界书绑定到聊天来激活这些素材。

聊天进度只记录 ID、数值、短证据和操作变化，长期去重标记仍会随确认次数增长。剧本库很大时主要影响首次读取和编辑加载；待人工处理的识别结果应定期处理，减少记录页和存档负担。编辑剧本后保留条件进度，但会清除旧版本的待确认判断和回退历史。重要编辑前建议导出剧本并备份进度。

其他酒馆助手脚本可通过事件接口接入按钮、任务系统或状态栏：

```javascript
// 主动提交预设事件，由引擎验证本地前置条件并执行奖励。
// 可重复事件必须为同一实际操作重用同一个 operation_id。
await eventEmit('BSE_SUBMIT_EVENT', {
  event_id: '你的事件ID',
  operation_id: '唯一操作ID'
});

// 显示已确认状态；此事件是通知，不会修改正文。
eventOn('BSE_STATE_CHANGED', snapshot => {
  console.log(snapshot.variables, snapshot.collected_ids);
});

// 主动读取当前聊天的存档。
const progress = getVariables({type: 'chat'})
  .branch_story_engine?.projects?.hotel_demo;
```

宿主页面同时会收到 `bse:state-changed` 的 DOM CustomEvent，内容在 `event.detail`。脚本 iframe 内的 `window.__branch_story_plugin__` 提供 `getState()`、`submitEvent()` 和面板入口。这些接口提交的是已知事件 ID，不执行用户导入的任意脚本。

## 手机界面

700px 以下使用全屏单栏，导航横向滚动，正文独立滚动。按钮和输入框至少 44px，手机输入字号为 16px，兼顾触控及 iOS 自动缩放。面板监听 `visualViewport` 大小与偏移，并保留尚未保存的表单内容。支持安全区域、关闭后恢复焦点和对话框内键盘焦点循环。

已通过 Chromium 中 390px、320px 七个页面布局、缩小可视高度、触控拖动与位置恢复、剧透确认和取消、快捷选项、分析草稿及内容导入导出的浏览器检查。原有回归还覆盖运行页独立防剧透、启用时自动显示输入栏选项、暂停/继续、输入栏隐藏恢复与替换，以及刷新保留关闭设置。v1.2.0 在桌面和手机另覆盖原文分析到 a/b/a1/ab 解锁和终点完成的全流程，包括自由输入、同轮注入、跨轮摘要和失败重试。实际 iOS/Android 软键盘、不同主题和扩展组合仍以安装后的设备体验为准。

## 源码与验证

代码独立实现，参考酒馆助手公开接口和 TSE 的运行结构，没有复制原脚本源码。

| 文件 | 职责 |
| --- | --- |
| `src/core.js` | 数据校验、条件、奖励、去重、逆向回退、当前节点提示词 |

| `src/loader.js` | 在线加载器源码，供开发参考；不生成在线安装文件 |
