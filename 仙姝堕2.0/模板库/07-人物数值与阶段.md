# 人物数值与阶段模板

真源：[character_stages.json](../src/config/character_stages.json)。当前characters为空，表示没有擅自启用未定稿的正式人物阈值。下面为可复制的测试配置，角色与数值都是格式样例，不是原著设定：

```json
{"characters":{"测试角色":{"allowRegression":true,
 "metrics":{"好感":{"min":0,"max":100,"default":0}},
 "stages":[
  {"id":"stage01","priority":0,"conditions":[],"story":"阶段一故事约束","portrait":null,"nodes":[]},
  {"id":"stage02","priority":1,"conditions":[{"kind":"metric","character":"测试角色","key":"好感","op":"gte","value":60}],"story":"阶段二故事约束","portrait":{"small":"user/images/xsd_gallery/已有资源.jpg","large":"user/images/xsd_gallery/已有资源.png"},"nodes":[]}
 ]}}}
```

增加至五阶段：按同样结构添加03/04/05，ID和priority各不重复；默认阶段空条件、最低优先级。条件全部满足，优先级最高者唯一生效；allowRegression=false保留已经达到的更高阶段，true允许回退。配置改名/删阶段需另做存档迁移，不能盲改ID。

所有人物统一计算到stat_data.character_stages；数值在character_metrics。立绘优先使用该阶段portrait；未配置时沿用已有名器立绘逻辑。阶段故事由构建生成【人物阶段】条目，仅当前在场人物/当前身份启用；其他人物阶段后台可计算，但其故事不整批注入。

节点实际解锁要在conditions引用stage或metric；阶段nodes字段目前只是可配置元数据，不自动开放地图节点。不得以填写nodes代替节点自己的场景、日期与条件门禁。

数值写入口：SET_CHARACTER_METRIC（已注册白名单及范围检查）、GM字段metric.人物.数值；节点metricChanges支持确定delta并随点选事务回退，不靠自由正文决定数值。GM人工覆盖须释放后自动修改。未注册/非法数值拒绝。

阶段story是正文内容，不是另一份条目名称；构建会生成对应条目。填完正式人物配置后重新构建导入才能生效。没有接入自动由LLM评分好感/堕落、跨人物阶段依赖或首次升阶额外奖励。

源码：[统一阶段](../src/runtime/character_stages.js)、[条件](../src/runtime/conditions.js)。
