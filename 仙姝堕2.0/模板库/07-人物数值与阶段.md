# 人物数值与阶段模板

更新：2026-10-12。**设计已按晋升剧情门槛修正；v15运行代码仍是旧的阈值选阶段逻辑，尚未改卡。** [character_stages.json](../src/config/character_stages.json)的正式characters仍为空，因此尚无正式角色被此旧逻辑自动升阶。

## 已定规则

1. 数值达标只解锁晋升剧情资格，不直接切阶段。
2. 玩家点击晋升节点后，按该节点配置演绎；未完成时仍使用原阶段。
3. 玩家点击完成节点后，模型对配置的“是否xxx”给出简短回报；是则本地保存晋升成功和新阶段，否则晋升失败、不升阶段。
4. EJS/阶段世界书、节点和立绘读取同一个已完成阶段。不能由各处再次比较数值自行升级。
5. 未选、取消、中断、退出不直接晋升。完成事实、阶段、原探索状态跟随聊天快照回退。

数字例子只用于解释格式，不是正式阈值或数值种类定稿。

| 对象 | 条件/内容 | 结果 |
|---|---|---|
| 阶段一 | 初始或尚未完成晋升剧情 | 使用阶段一故事和立绘 |
| 晋升资格 | 填写指标与必要的事件前置 | 满足后开放相应晋升节点 |
| 晋升过程 | 入口注入邀请/过渡与专属故事，玩家自由参与 | 保持原阶段，模型自然演绎，不堆大量流程子节点 |
| 完成提交 | 玩家点完成，模型简短是/否回报 | 是→本地保存成功并切阶段；否→失败、保持阶段 |
| 阶段二 | 晋升完成事实已有效保存 | 后续使用阶段二内容 |

晋升节点两类及引导约定见[12](12-晋升节点与引导流程.md)。不再采用“只要好感达到60，就将stage02作为当前阶段”的测试样例作为填写模板；旧样例允许自动升级，与新规则冲突。

## 已有基础设施

数值在stat_data.character_metrics；计算结果在character_stages。已有SET_CHARACTER_METRIC、GM白名单/人工覆盖、节点metricChanges和数值范围检查。阶段结果已供故事及立绘读取，仅注入当前在场人物的阶段故事。阶段nodes字段仍只是元数据，不自动开启节点。

## 尚需改造的运行行为

[character_stages.js](../src/runtime/character_stages.js)目前按conditions满足程度选最高priority，不能把它说成晋升剧情完成制。其allowRegression例子也不能作为人物阶段随数值下降自动退阶的已批准规则；降阶机制没有定稿。

需要为晋升资格、晋升进度、已完成阶段建立明确接口，并在完成节点的是/否回报落地时提交阶段；入口点击不自动晋升。普通节点仍按本地点选结果，不统一加模型完成审批。具体新字段名尚未定，不提供一份假装已能直接加载的JSON。

正式人物指标、初始值、阈值和五阶段正文尚未配置。好感/信任/堕落/欲望/羁绊等数值清单仍是助手建议，未获得主人逐项确认；自动由模型评分、首次升阶奖励、降阶规则也不是定稿要求。
