# 人物数值与阶段模板

更新：2026-10-13，当前v39。**v16已将阶段改为读取完成记录，并接入叶红缨独立专属试点。** [character_stages.json](../src/config/character_stages.json)已注册叶红缨试点：好感整数范围−100—100、初始0、资格≥20。叶红缨双身份路线已配置20/40/60/80四道晋升及五阶段正文，其他人物按需填充。

## 已定规则

1. 数值达标只解锁晋升剧情资格，不直接切阶段。
2. 玩家点击晋升节点后，按该节点配置演绎；未完成时仍使用原阶段。
3. 玩家点击完成节点后，模型对配置的“是否xxx”给出简短回报；是则本地保存晋升成功和新阶段，否则晋升失败、不升阶段。
4. EJS/阶段世界书、节点和立绘读取同一个已完成阶段。不能由各处再次比较数值自行升级。
5. 未选、取消、中断、退出不直接晋升。完成事实、阶段、原探索状态跟随聊天快照回退。

数字例子只用于解释格式，不是正式阈值或数值种类定稿。

| 对象 | 条件/内容 | 结果 |
|---|---|---|
| 阶段一 | 初始或尚未完成晋升剧情 | 使用阶段一故事和立绘 |
| 晋升资格 | 填写指标与必要的事件前置 | 满足后开放相应晋升节点 |
| 晋升过程 | 入口注入邀请/过渡与专属故事，玩家自由参与 | 保持原阶段，模型自然演绎，不堆大量流程子节点 |
| 完成提交 | 玩家点完成，模型简短是/否回报 | 是→本地保存成功并切阶段；否→失败、保持阶段 |
| 阶段二 | 晋升完成事实已有效保存 | 后续使用阶段二内容 |

晋升节点两类及引导约定见[12](12-晋升节点与引导流程.md)。不再采用“只要好感达到60，就将stage02作为当前阶段”的测试样例作为填写模板；旧样例允许自动升级，与新规则冲突。

## 已有基础设施

数值在stat_data.character_metrics；计算结果在character_stages。已有SET_CHARACTER_METRIC、GM白名单/人工覆盖、节点metricChanges和数值范围检查。阶段结果已供故事及立绘读取，仅注入当前在场人物的阶段故事。阶段nodes字段仍只是元数据，不自动开启节点。

## v16运行阶段提交

[character_stages.js](../src/runtime/character_stages.js)按completed_character_stages读取已完成阶段，未完成者取initialStage。不再按数值conditions选择最高priority。非负数值升降不自动晋升；负值由中控按四档覆盖，保留正向完成记录；真实回退随分支快照恢复，不额外定义关系降阶机制。

中控验证晋升完成节点的stageGrant白名单，并在本轮有效“是”回报后写完成阶段；“否”不升。入口点击只开启故事。EJS不是必需，现有世界书门禁读取同一阶段结果。

当前只有独立专属试点；通用嵌入/回原事件机制尚未接入。所有回报须匹配本次完成行动ID，缺失/冲突可再次点击完成，历史回报不沿用。

叶红缨已配置好感事件表，模型按协议申报、中控校验依据并执行分值、冷却与上限。其他正式人物的指标、阈值及阶段正文仍需配置；信任/堕落/欲望/羁绊等未获逐项确认，不自行扩展。首次升阶奖励和关系降阶规则仍非定稿。

首份填写稿：[叶红缨阶段一至二](../内容样板/叶红缨-阶段一至二-专属晋升.md)。主人数值门槛20与剧情已接入，当前完整双轨稿见[叶红缨全阶段与晋升定稿样板](../内容样板/叶红缨-全阶段与晋升定稿样板.md)。
