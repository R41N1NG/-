# 中控与条件模板

所有状态通过 dispatcher 的意图/事务入口处理。UI不直接写日期、背包或数值；模型状态标签不直接写人物数值。故事条目负责描写，后台负责确定结果。

## 已支持的条件

```js
conditions: [
  {kind:"identity",op:"eq",value:"赵无忧"},
  {kind:"known",key:"map_youjigu",value:true},
  {kind:"item",key:"幽寂谷地图",op:"gte",value:1},
  {kind:"metric",character:"已注册人物",key:"好感",op:"gte",value:60},
  {kind:"stage",character:"已注册人物",value:"stage02"}
]
```

这是格式样例，不是正式人物阈值。数组内为AND；空数组无附加限制。运算支持eq/gte/lte。缺失值不满足条件；未知类型或运算报错。人物阶段选取优先使用数值、known、身份/物品条件；不要定义阶段互相依赖形成循环。

地图显隐、后台点击合法性、正文中的可见路线共同检查同一条件。条件不满足时不能靠手动发送代码绕过：没有本轮授权pending，故事条目保持关闭。

日期使用整数日运算（30日/月、360日/年），显示为1578年3月3日；这是现有游戏历法，不是公历。历时、发送次数、原生消息楼数、成功故事轮数不能互相替代。
