# 数值事件申报机制 · 机制规格（草稿 v1，待主人审定）

> 状态：讨论稿，未实现、未提交仓库。审定后落入 `仙姝堕2.0/模板库/` 并排期实现。
> 目标：让好感等人物数值随玩家真实言行流动——大事件走判例，日常走「投其所好」三档判定；模型只有举证权，定价权与节拍权在后台上控。

## 一、原则

1. **模型不是权威**：模型每轮至多申报一次「她会对 {{user}} 这轮言行产生印象」，申报内容是档位或锚点事件 ID＋原文依据；分值、上限、范围全部由后台配置与校验决定。
2. **多数回合 0 分**：关系在节拍上移动，不在每句寒暄上移动。无申报＝无变动，这是设计而非缺陷。
3. **复用既有纪律**：正文实证（同纳戒）、统一写入口（dispatcher.writeMetric）、同楼快照撤回（同节点 metricChanges）、GM 人工优先（同物品覆盖）。
4. **宪章红线不碰**：19 个 XML 字段原样保留（新标签独立于 Status_block，渲染前剥离）；库存/known/日期/阶段不开放模型申报。
5. **感知门槛（主人定）**：数值反映「她对 {{user}} 的态度」，只有她**察觉到**的言行才能改变数值。她不省人事时的冒犯不落账；事后察觉的当轮再申报。口头提及 < 轻慢 < 毁物 < 窥视秘密 < 身体侵犯 < 强迫破身，幅度按剧情情感重量成阶梯，大恩大恨用几十分级，日常才是个位数。
6. **不重复计分**：已由晋升等专属剧情定案的桥段（如夜访撞见沐浴）不再被通用锚点重复结算；锚点只接新发生的事。

### 叶红缨好恶依据（人设逻辑，供基米填其他人物时参照）

她的一切好恶都从「自己是烈火、怕自己是灾星」这一个对立长出来：师尊的谎让她确信亲近她等于被她烧死，人前拿大大咧咧当铠甲，人后连心动都当病发作。因此她欣赏**「不怕她的火」的人**（接得住烈性、直肠子、讲义气、不慕名头、接得住她醉后试探、她着火时站着不动）；记恨**「证实她最怕的事」或冒犯她骄傲的人**（当众撩拨取乐、人前揭短、当瓷器管束、背信弃义、浮浪恭维）。

注意两条边界：①**诛心话锚点不成立**——体质之秘外人不知，普通人眼里她是名动百花榜的炎姬，「骂她灾星」无从戳中心结；心结类伤害只能来自已知秘者（泄秘、窥视、触碰等行为锚点已覆盖）。②**行为者信息前提要校验**——设计任何锚点先问「做这件事的人可能知道什么」；她人不知情的行为构不成心结伤害。

### 陆烬颜好恶依据（人设逻辑，供基米参照）

第十三位，荒原野猫：她的怕有两条 canon 直写——①**「最怕自己成为兄长道途上的包袱累赘」**：证明自我的倔劲使她低估险恶而行险；②**「对交付了信任的朋友毫无保留防备，易被阴险魔道利用此点设伏围剿」**：盲目信任是她的命门（骗她设伏 -30 即此）。暗面「屈服软化」（双腿要害被制时的羞愤瓦解）属晋升线材料。配表要点：①门禁 `known['已抵达陨仙原']`，与花芷凝同款；②师徒/姐妹互挂：花芷凝表已有护陆烬颜 +2、救陆烬颜 +20、危害 -30、杀害 -50——镜像闭合；③兄长陆十三是 NPC 不配好感表，但他是她的天（救兄 +25 倒挂高于救己 +20，危害兄长 -40 高于一般 -30）；④撮合打趣是她的心头好：拿兄长与花姐姐情事打趣的分寸是「助撮合不揭破」，揭破则恼。

- `tiers`：三档中的两档可申报分值（「无感」不申报、默认 0）。分值按人物可覆盖，默认 +1/-2（按其人设：好感难升易降）。
- `anchors`：锚点事件表。`repeat:false` 的一次性事件落账后记入 `stat_data`，同轮查重；`conditions` 复用现有 conditions（当前支持 eq/gte/lte，identity 用 eq，暂不支持 in——多殿主身份要分别配置条目）。
- `cooldownTurns`：同一人物同一档位的冷却有效轮数，冷却内重复申报不落账。
- 指标本身仍须先在 `character_stages.json` 注册（范围/初始值），两表联查，未注册数值拒写。

## 三、世界书注入

- 每人物生成一条 **【好感事件表】人物名** 常驻条目（`constant:true`、默认 `disable:true`、防递归双开、order 202），内容由两部分组成：申报格式规则（全卡统一模板）＋该人物的 rubric 清单。
- 开关逻辑在 `story_entries.js` 的 `managedEnabled` 里加一段：**该人物在场**（身份/stage_focus/在场角色）且其指标已注册 → 开启。与【人物阶段】同款机制，不在场不注入（主人已确认：提及时有人物条目就够）。
- 条目同时给出**当轮仍处冷却/已消耗一次性事件**的简报，让模型不浪费标签次数（一行以内）。

## 四、模型申报协议

模型在正文之外的任意位置输出至多一个标签（一轮至多一个人物）：

```
<好感事件>叶红缨｜记心上｜依据：她接过酒坛仰头饮尽，笑骂了句勉强入耳</好感事件>
<好感事件>叶红缨｜锚点 yh_anchor_sujiu｜依据：同上格式</好感事件>
```

- 三段式：**人物名｜档位或「锚点 ID」｜依据**。分隔符全角竖线，格式解析失败整笔丢弃并记 GM 诊断计数，不锁流程、不重试。
- **依据必须是可见正文的逐字子串**：校验前先剥离 think/analysis、details、Status_block 与本标签自身；只在叙事正文里找。
- 该标签在输出给玩家的可见正文里被剥离（同 `<Promotion_result>` 的处理），不产原生消息楼。
- 申报「无感」、报未注册人物、报配置外锚点 ID：一律静默丢弃＋诊断，不影响正常叙事。

## 五、校验与落账（新模块 src/runtime/metric_events.js，挂进 applyStory 结算）

1. 人物已注册、指标已注册、数值范围校验（writeMetric 现有逻辑）。
2. 证据校验：依据 ∈ 可见正文。
3. 限次：每轮每人物 ≤ `maxPerTurn`；同一档位距上次落账 ≥ `cooldownTurns` 个有效故事轮；锚点按 `repeat`/`perTurn`/一次性查重（一次性事件查 `stat_data.metric_anchor_done`）。
4. 分值取配置，不由模型定；正负照实，负分触底止于指标下限。
5. 经 dispatcher 统一事务写入 `character_metrics`，与该楼其他结算同笔提交。
6. **GM 人工覆盖该指标期间，自动申报整笔拒绝**（同人工库存覆盖语义），面板给一行提示。

## 六、撤回与恢复

- 本楼落账的档位/锚点与增减值记入该楼回执（pluginState），停止生成、删楼、swipe、分支切换时按快照同笔回退，不累计、不残留。
- 冷却窗口与一次性记录随同一快照恢复，删楼重演可重新申报。

## 七、与晋升体系的咬合

- 本机制只管**数值流动**（资格线以下的积累，以及超过资格线后的继续浮动）。
- 升阶仍只走「晋升入口→完成→是/否回报」；数值到线不发生任何阶段变化。
- 殿主玩家作恶 → 命中记恨档/负分锚点 → 好感下行、入口不亮；正向转圜靠他改行，数值如实反映。

## 八、分工

- 机制与校验：小狐狸实现（含测试）。
- rubric 清单与锚点事件内容：人设创作，交基米按各人物设定填写；分值与冷却数值由主人定调。
- 已确认移交基米的事项一并记录：叶红缨阶段二正式行为正文。

## 九、待主人定夺

1. 首批注册指标：好感度先上；信任/堕落/欲望/羁绊是否留配置位（机制通用，加指标只是填表）。
2. 默认分值：记心上 +1 / 记恨 -2、冷却 3 轮，是否认可为初始值。
3. 好感是否在 HUD 可见（关系刻度类），还是仅后台门槛、靠态度侧面体现。
4. 锚点表首版人物范围：只配叶红缨试点，还是连同幽寂谷相关人物一起配。

## 十、实施范围预估

新 runtime 模块＋config＋managedEnabled 一段＋dispatcher 挂钩＋测试（申报解析/证据/冷却/一次性/撤回/GM 拒绝）。引擎无结构性改动；与「移除结束拜访按钮」同批出版。

## 十一、规模化（几十人物）——负担评估与对策

**结论：运行与卡体负担很小，真正的成本在内容创作，不在引擎。**

| 维度 | 负担 | 对策 |
|---|---|---|
| 计算开销 | 每轮只扫描在场人物的注册表，几十人物×两三次比较，可忽略 | 无需处理 |
| 卡体积 | 每人物事件表条目约 0.5–0.8KB，50 人合计约 30KB；卡内脚本已 1.6MB | 无需处理 |
| 注入 token | 默认 `disable:true`，条目不启用电量为零；仅在场人物条目开启 | 在场门控（已有）＋rubric 控制在五至八行 |
| 配置出错 | 字段写错、锚点重名、引用未注册指标才是真风险 | 构建期校验进 ship.js：ID 唯一、指标已注册、conditions 引用的身份在 IDENTITY_NAMES、范围合法，不过即构建失败 |

**内容侧减负：通用默认层＋人物差异层。** 不要求每人物从零写一份：设一份「世俗通例」默认 rubric（寻常客套无感、行侠仗义记心上、趁人之危记恨之类），未配置的人物走默认层或干脆不启用好感系统；只有可攻略的重点仙姝写定制 rubric 和锚点。预计定制量：重点人物十份上下，其余后续按需追加，无迁移压力。

**分批上线**：机制随叶红缨试点先落地，其余人物配一个亮一个，`ship.js` 校验保证配错出不了卡。
