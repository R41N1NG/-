# v74：一键修复

基于 v73 增补，保留 v72 的轻量存储。更新当前角色卡并重新进入聊天，诊断版本应为 `2.0-framework.74`。

最新卷中录顶部和节点错误提示旁改为“一键修复”。点击即自动检查并选择处理方式，无需再选择检查、刷新或撤回。高级检查和撤销按钮仍保留在面板内。

处理顺序：

1. 上次修复中途失败且备份仍可恢复时，先恢复备份，再重新检查。
2. 原操作和原回复仍可验证时，按原顺序补结算。
3. 原回复已缺失、空白或不再符合关联关系，且当前已是可信的回滚状态时，只清理失效任务标记，保留当前数值、物品和剧情位置，供玩家重新选择未完成节点。不会把这类情况标成节点完成。
4. 尚未收到完整回复的中断操作，自动撤回。
5. 删楼恢复已完成的旧提醒收起，但作废回复名单继续保留，不重新结算这些旧回复。
6. 没有需修补的问题时，只刷新显示，不重复创建备份或覆盖上一次撤销点。

修复前备份、跨重载撤销、消息和候选变化校验仍保留。清理旧错误也可撤销；诊断保留原故障记录，并用 `repairAcknowledged` 和 `recoveryStatus` 区分历史故障与当前提示。修复摘要显示于面板，界面重建导致面板关闭时也会显示于最新卷中录；后续状态变化后不继续显示旧摘要。

另外修正原回复回调遗漏的处理：例如第11楼的操作对应第12楼回复，而处理拖到第16楼时，先核验第12楼，再依次处理后续普通回复。不会拿第16楼冒充原操作回复；存在其他操作、人工调整或删楼作废记录时，不自动跨越这些边界。

原回复无法验证或当前分支没有可信进度时，不强行补认完成、发奖励或重置开局。修复不重新生成，也不改写已有正文。

验证包含运行时、打包模拟宿主、实际 DOM 按钮，以及构建成品回读。尚未在玩家的真实酒馆实例验收。

验证结果：288 项源码/模拟宿主测试与 13 项成品集成检查，共 301 项通过。v74 PNG 为 7,934,525 字节。
