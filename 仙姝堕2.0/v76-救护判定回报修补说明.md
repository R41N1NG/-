# v76：救护判定回报修补

基于 v75 修改，保留独立归属显示、一键修复及备份功能。更新当前角色卡并重进聊天，诊断版本应为 `2.0-framework.76`。

本次完整存档确认玩家已完成救助回应并请求判定，最终记录为回报解析失败，而非救助被判为“否”。旧版会用通用失败说明改写模型回复，因此这份旧存档无法再确定原回报究竟缺标签、编号不匹配还是格式有差异；不能从现存文本断言模型当时具体输出了什么。

修补内容：

- 判定请求的用户消息自身带有核验条件、当前编号与结果格式，不再只发送一个裸操作码。扩展提示仍保留，用户消息中的历史入场编号替换为本次入场指代，保证授权解析只识别当前判定编号。
- 结果解析兼容单引号、标签大小写和正常排版空白，仍只接受唯一结果、当前编号和“是/否”。多标签、旧编号、额外属性、未闭合标签、隐藏思考或历史示例内的标签不授权路线。
- 西北救护失败记录包含具体解析状态、标签数量、编号、回报长度及有界的标签片段。失败时不覆盖原助手回复，且不把无效回复当作正式路线判定。
- 主卷提供“重新请求救护判定”按钮；旧存档的失败节点同样可用。玩家无需重新输入前面的救助行动，也不必折返重开。
- 自检明确报告判定未完成，不再将这种状态描述为没有错误。

适用已有失败存档：更新后打开原聊天，点击“重新请求救护判定”。此操作会发送一次新的判定请求；只有新回报通过校验才切换路线，不从自然语言片段、隐藏思考或已丢失的旧回报中补认成功。

验证使用 Node、模拟酒馆和 DOM；未连接玩家正在使用的模型服务，真实模型是否遵守格式仍需重试确认。若再次失败，保留原文和新诊断中的 `resultProtocol` 可直接定位下一步。

验证结果：源代码、模拟酒馆与 DOM 共 295 项测试通过；导出卡集成测试 13 项通过，合计 308 项。PNG 回读版本为 `2.0-framework.76`，大小 7,940,241 字节；v74/v75 历史卡逐字节保持不变。
