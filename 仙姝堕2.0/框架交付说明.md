# 2.0框架首轮交付

源码仅取仙姝堕2.0迁入材料；正式世界书和旧卡保持隔离。GPT负责的框架、HUD、GM、宿主与流水线已完成；基米979044e的地图插件已接入，并补过真实插件与调度器之间的离线联调。

运行：Node >=22.7，在本目录先 `npm ci`，再 `node ship.js`。Windows依宪章使用node.exe绝对路径。默认运行离线检查、生成独立JSON/PNG及世界书，再按可选环境变量部署；没有配置部署目录会明确跳过，不会猜本机酒馆路径。

最新角色卡目录仅两个同名成品：仙姝堕2.0·框架测试.json / .png。用户只需导入PNG；开发世界书和运行脚本在dist。卡内包括229条世界书和酒馆助手脚本，导入时绑定独立同名世界书。需要启用酒馆助手脚本运行，并部署原有本地图包到当前用户的images/xsd_gallery。

部署：设置 `XSD2_TAVERN_USER_DIR` 指向现有酒馆用户目录（其中已有characters和worlds）；只写独立2.0测试卡和世界书，覆盖同名测试产物前备份到用户目录backups/xsd2。未覆盖正式仙姝堕。

源码分层：runtime是唯一权威写入口；host封装酒馆API及当前主世界书；ui负责HUD/GM；tools/data将迁入注册表和名器规则包入显式依赖作用域，不拷贝旧版脚本；bootstrap装配原生生命周期。内置幽寂谷地图按分工与接口草案注册。

实证边界：默认ship检查包括核心状态规则、DOM按钮回调、候选变量宿主适配、基米原有7组纯函数测试和新增6组真实地图插件/调度器联调，共41项。插件与核心的离线接入已验证；通过不等于真实酒馆视觉和模型验收。127.0.0.1指访问端自己的机器，本次没有把云端模拟说成本机实测。

迁入材料事实：注册表实际96个known字段，名器配置13个；世界书模板还写122个锚点，需基米统一文档/模型申报白名单。图包清单85项中84项为图片，另1项为README；Git仅存清单，原图在基米本机。六套开场纳戒均“无”，本轮遵循源材料空库存，没有编造未迁入的旧版起手物品。若旧实机另有身份起手物品，请基米迁入对应配置后接入defaults，不能以空库存冒充已复刻旧版物品表。

主人实测清单（框架及已接入的地图）：

1. 新建独立聊天，0楼选赵无忧应为三月初三，殿主八月初一；自设填写自己的日期/修为/地点，检查六个身份世界书只开当前一个。
2. 状态栏三组面板初始收起；在场角色关系、心境、神态显示正确；本地图包小图、大图及缺图提示正常。
3. 点击纳戒物品和观察/交谈应直接发送自然语言；正常正文取得/消耗与背包一致，否定句不加物品。
4. GM改身份、日期、库存、段位和名器阶段立即生效；人工回锁不能被自动规则冲掉，释放后允许后续自动更新。
5. 生成时停止，删助手楼、再删用户楼；换候选、重生成、切分支、刷新，检查日期/物品/人工标记恢复到对应历史。
6. 当前独立卡已内置南疆地图及幽寂谷圆点：三月身份测地图只显示图和圆点、点击只派发一个行动、完整回复后才出后续点、互斥、密室前置、离开即深入、退出确认、正常2日/提前1日。

当前地图联调补正：证据使用完整事件定义，而非经核心裁剪的选择回执；仅正文真实到达/取得才结算，铁匣、普通古卷、状态栏宣称及门外计划不放行。奖励去重、GM日期/known投影、完成进入后的TTL起点、入口过期后的可选择路径及等待时所有圆点禁用均有离线覆盖。地理显示为圆点加短标签，开局时点不在窗口内则无圆点。节点/奖励/互斥/出口耗时沿用基米当前配置，没有扩写正式剧情。
