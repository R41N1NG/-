## 二、目的需求

把 0 楼自设开局的「当前时点」从**8 个按钮**改成**一根滑块（时间轴）**，并让它显示**所有时间点（＝卡内【中立】一~七 的日期 ＋ 正章之前）**：

| # | 滑块停靠点（值＝标签，含年月日） | 来源 |
| :-: | :--- | :--- |
| 0 | 正章之前 · 仙盟历 1577 年 · 七月初一 | 主人给的（正章＝第一章，故在其前一年） |
| 1 | 暗流微澜 · 仙盟历 1577 年 · 十二月初一 | 【中立】一 自带日期 |
| 2 | 第一章（墨山探幽）· 仙盟历 1578 年 · 三月初三 | 【中立】二／正篇起点 |
| 3 | 南域大劫 · 仙盟历 1578 年 · 八月初一 | 【中立】三 |
| 4 | 天溪兽潮 · 仙盟历 1579 年 · 一月初一 | 【中立】四 |
| 5 | 天溪城破 · 仙盟历 1579 年 · 三月初一 | 【中立】五 |
| 6 | 乱世割据 · 仙盟历 1579 年 · 六月初一 | 【中立】六 |
| 7 | 极乐定局 · 仙盟历 1580 年 · 一月初一 | 【中立】七 |

**交互需求**
1. 拖动时**实时显示**当前停靠点（年月日）；
2. 松手／每次 `input` 就把该停靠点的字符串**写进 `custom_timepoint` 输入框**（保持与既有解析链兼容）；
3. 拖动时顺带显示该时点的**一句中立大势**（例：3 ⇒「南域大劫 · 天地神诅与四殿分疆」）；
4. 键盘可达（←/→ 换点）、移动端可拖且**触控命中 ≥36px**、PC 端零破坏（纯 CSS `@media` 隔离）；
5. 无 JS／老存档时**退化为现有按钮或手填**，不能把输入框变空。

### 3.2 两种挂载方式（请你选一种并写代码）

| 方案 | 做法 | 我的判断 |
| :--- | :--- | :--- |
| **A（推荐）** | **不内联脚本**：在面板侧新增一小段——监听 `input[data-xds-range]` 的 `input` 事件（事件委托挂 `window.parent.document`，遵守铁律 32），读 `value` 索引 → 从 `data-xds-labels` 取出字符串 → 写进对应 `custom_timepoint` 输入框 ＋ 更新 `<output>`；初始化用一次性委托即可（菜单是渲染后注入 DOM 的，必要时配 `MutationObserver`） | 与既有 `data-xds-fill` 的"外部 JS ＋ data 属性"路线一致；风险最低 |
| **B** | 菜单 HTML 里**内联 `<script>`** 自包含 | 更自包含，但**酒馆消息渲染是否会执行内联脚本我没核到**，风险高；若你知道可行也可选 |

**你要写出来的具体东西（按 A）**：
1. 面板侧事件委托与同步函数（含初始化时机、重复渲染时的幂等）；
2. 轨道／把手 CSS（含移动端命中区、`touch-action` 防与聊天滚动打架、`@media` 隔离）；
3. 无障碍细节（`aria-valuetext`、键盘、`output` 同步）；
4. 回填逻辑：**输入框里已有自定义日期时滑块怎么显示**（吸附最近点，还是显示"自定义"）——这条需要你给一个明确规则。

- 8 个中立停靠点与卡内【中立】一~七 的**日期必须逐字一致**（那 7 条现在是按日历区间开的闸门：`[本条日期, 下一条日期)`）。

## 四、风险

| # | 风险 | 说明与缓解 |
| :-: | :--- | :--- |
| 1 | **跨文档绑定** | 菜单在聊天正文、面板在 iframe ⇒ 事件必须挂 `window.parent.document`；**面板未挂载时滑块会失效** ⇒ 保留手填输入框兜底（现状即有） |
| 2 | **内联脚本可能不执行** | 酒馆对消息 HTML 的脚本处理我**未核到** ⇒ 选 A 方案回避 |
| 3 | **回填规则缺失** | 玩家手填了「仙盟历 1579 年 · 六月初七」后再打开菜单，8 个停靠点对不上 ⇒ 需你给规则（建议：吸附到"不晚于该日期的最近停靠点"，并在 `output` 里标注"自定义日期"） |
| 4 | **双处维护** | 若把 8 句中立大势写进面板脚本，就与【中立】条正文重复 ⇒ 建议只写**短标题**（如「南域大劫 · 天地神诅与四殿分疆」），并在注释里标明来源是【中立】三 |
| 5 | **面板产物编译** | 动面板必须改 `_src` 源再 `build.js` 编译，`_verify_panel_pack`／`_chk_panel_artifact` 两道门禁要过；**改错文件**是这项目踩过的坑（我曾把改动的底稿当生效源） |
| 6 | **移动端手势冲突** | range 拖动与聊天区滚动冲突 ⇒ 需 `touch-action: pan-y` 之类的取舍，命中区 ≥36px（铁律 29） |
| 7 | **主题/皮肤差异** | 我的取值盘属性（`aria-pressed` 等）被其它主题 CSS 影响 ⇒ 建议样式自带命名空间前缀（现有 `data-xds-*` 风格） |
| 8 | **回归面** | 菜单是 0 楼唯一入口，改坏 ⇒ 新玩家无法开局 ⇒ 必须保留：纯文本手填路径、老卡快照、以及"无 JS 时按钮仍在" |
