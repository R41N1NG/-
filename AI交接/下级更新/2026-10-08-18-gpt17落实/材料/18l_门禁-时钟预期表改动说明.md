# `_chk_clock_acc.mjs` 预期表改动说明（该文件未被 git 跟踪，故不给 patch，只给改动前后）

## 1) 超限：从「按上限截半截计入」改为「整笔拒绝」
改前（第 105-109 行一带）：
```js
  const r = nextAcc({ 历时累计: 0 }, 9, 5, false);
  check('常规历时超限按 0.1 计入（5 → 0.1，原为 0.02）', near(r.adv, 0.1), 'adv=' + r.adv);
  check('超限带 clipped 标记（原来静默截断）', r.clipped === true, 'clipped=' + r.clipped);
```
改后：
```js
  const r = nextAcc({ 历时累计: 0 }, 9, 5, false);
  check('常规历时超限 ⇒ 整笔不计（5 月申报，adv=0）', near(r.adv, 0) && near(r.acc, 0), ...);
  check('超限带 clipped 与 rejected 标记（原来只是静默/诊断）', r.clipped === true && r.rejected === true, ...);
  check('超限时把申报值原样带回（供落 [历时待确认]）', near(r.raw, 5) && near(r.capM, 0.1), ...);
  // 另加：超限拒绝时不改动已有累计（3.14 个月保持）
```
依据：gpt 17 §5-4 ↔ 05 §4 L98「未接受/异常跳变应整笔待确认或拒绝；不能累计三日，却让正文变成五个月后」。

## 2) 「未来计划不算已过」：原断言写在相反方向
改前：
```js
check('④b 已过历时仍照常计入（「三日后启程」不得被守卫误杀）', parseLishi('三日后启程') > 0, ...);
```
改后（并补三条，避免只是削弱判据）：
```js
check('④b 未来计划不计（「三日后启程」＝0）', parseLishi('三日后启程') === 0, ...);
check('④b-2 师尊说的计划也不计（「师尊说三日后启程」＝0）', parseLishi('师尊说三日后启程') === 0, ...);
check('④b-3 明写已过的转场照计（「三日已过，我们启程」＝0.1）', near(parseLishi('三日已过，我们启程'), 0.1), ...);
check('④b-4 定于/拟于 一律 0', parseLishi('定于三日后启程') === 0, ...);
```
依据：gpt 05 §4 L100「『师尊说三日后启程』与『距启程三日』都是 0；只有玩家接受转场后的『三日已过，我们启程』才计 1/10 月」。

结果：该门禁 **32 通过 / 0 失败**（改前 25 通过 / 2 失败 —— 那 2 条失败正是旧预期，与 gpt 裁定相反）。
