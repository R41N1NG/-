# 协作流程

## 接手

检查当前用户指令、仓库工作区状态和适用的AGENTS.md。根目录已有其他项目及独立的“AI交接”，不属于本项目，勿混改。先阅读本交接、项目制作规范、最新样张未完成记录，再挑选对应区域与方向参考。

提交前同步远端，保留其他人的修改，不强推：

```bash
git status --short
git fetch origin main
git merge --ff-only FETCH_HEAD
```

旧会话的`/tmp`脚本、生成缓存和内存任务队列不属于可复用环境。当前脚本从自身位置定位项目，不依赖固定克隆目录。

## 路径与清单

`图片/生成清单.json`的`output`相对于仓库根；`relative_path`相对于`尾行/图片/正式素材/`。样张清单的`path`相对于样张清单所在目录。旧`source_path`和原始摄影提示词保留来源含义，实际制作以用户最终要求和`制作规范.md`为准。

`generated_source`或历史`source`可能指向已不存在的旧临时文件，不是当前图片入口。当前图片路径及SHA-256才是交付事实。迁移时全部217张PNG内容保持不变。

## 继续生图时

1. 读取用户新要求，确认本次是正式素材还是独立样张；不自动扩大范围。
2. 先查看同套同区域的已交付图片及该方向参考，再调用当时可用的图像生成／编辑工具。不要臆造工具、凭据或API调用方式。
3. 核对人物、版型、穿搭、方向、动态、手掌、裁切和尺寸。失败结果不能计入完成；采用过渡参考时明确写明局限。
4. 新文件写入对应中文目录。替换时保留Git修订记录，使用清单的`revisions`记录用户要求、旧SHA、来源和实际提示词。
5. 更新`actual_dimensions`、`sha256`、`review`等字段。正式素材运行索引脚本；样张更新其独立README、清单与未完成记录。
6. 每张生成图完成后提交推送；不要只放在临时工作区。遵从当前会话已有授权与平台访问控制。

```bash
python 尾行/AI交接/脚本/更新索引.py
python 尾行/AI交接/脚本/校验图包.py
git add -- 尾行
git commit -m '说明本次图片或交接修改'
git push origin HEAD:main
```

索引脚本只重建正式素材分类和图片总目录，不改样张状态。新增规则和交接链接请放在图片总目录的“正式素材进度”之前，避免被自动生成区覆盖。

## 打包与收尾

运行`打包图包.py`，会先校验当前文件，再重建仓库根`图包下载/服装插画图包-20261020.zip`及SHA-256文件，包内根目录为“尾行”，含图片与AI交接。保持当前下载路径可继续使用。正式素材和历史参考已经接近GitHub单文件100MiB限制，脚本超过该上限会停止，不应不加检查地继续扩大单包。

```bash
python 尾行/AI交接/脚本/打包图包.py
git add -- 尾行 图包下载 wardrobe-samples-illustrated/README.md
git commit -m '更新图包与交接'
git push origin HEAD:main
```

只在本次涉及迁移兼容入口时暂存旧目录README。完成后确认工作区状态、远端main、下载链接，并用GitHub链接向用户交付；对未完成项保持如实说明。
