# 第一步：人物什么时候可以交流

这是可单独打开的原型，尚未接入正式卡。验证一条规则：**忙碌 → 可交流 → 结束**。

## 看什么

| 时刻或条件 | 状态 | 交流入口 |
| --- | --- | --- |
| 当前节拍早于忙完时刻 | 忙碌 | 关闭 |
| 已忙完，且尚未到离开时刻 | 可交流 | 开放 |
| 到离开时刻、人物不在场或场景已关闭 | 结束 | 关闭 |

示例配置在 `index.html` 的 `initial` 中：第 0 步忙碌；第 1～3 步可交流；第 4 步结束。这些是明确标注的演示参数，尚未作为正式时间规则使用。

## 怎么试

下载 [demo.html](demo.html)，用浏览器打开即可，不需要其他文件。开发源码为 `index.html` 与 `availability.js`；`node prototypes/local-scene/build-demo.cjs` 会重新生成单文件演示。

1. 初始“测试交流入口”不可点击。
2. 点击“模拟一次有效行动”，入口开放。
3. 点击“只查看状态”或测试交流入口，节拍不会推进。
4. 推进到第 4 步，入口关闭。提前结束也会关闭。
5. 可以重置，重复比较。

GitHub 文件页只显示源码，请使用页面右上角的下载按钮保存 `demo.html`，再用浏览器打开。

## 已做与未做

- 已做：无依赖的纯状态计算、条件门槛、明确错误、网页演示和边界验证。
- 尚未做：正式技能结算、信息和交流成果、世界时间、人物性格决策、聊天与存档接线、模型叙述。
- 演示不调用模型、不读写聊天、不调用正式存档 API、不改变 v0.8.2 角色卡。
- `availability()` 的输入可 JSON 序列化，JSON 往返只验证数据可恢复，不代表已经实现持久化或聊天回退。

人物状态每次根据进度推导，不重复存一个可能与时刻表冲突的状态值。关闭标记优先，避免结束后因条件重新满足又打开入口。
