# 重点维护模块：聊天与存档同步

玩家反馈“对话与存档不匹配、串档、重复扣账、删楼后进度错误”时先查本目录。

| 文件 | 职责 |
| --- | --- |
| `controller.js` | 串行操作、完整状态恢复、提交、备份恢复、诊断入口 |
| `session.js` | 聊天身份和任务代际校验，切聊天后取消旧任务 |
| `timeline.js` | 消息指纹、回合分支、最后共同检查点、保留窗口 |
| `repository.js` | 宿主聊天变量读写出口 |
| `keys.js` | 聊天变量名契约 |
| `diagnostics.js` | 只含阶段、楼号和错误码的有界诊断 |

`glue.js` 负责事件接线。完整引擎档格式与迁移位于 `src/runtime/game/save.js` 和 `src/runtime/persistence/migrations.js`。

专项文档：[聊天与存档同步专项](../../../docs/聊天与存档同步专项.md)。运行 `npm run test:sync`，代码检索标记为 `CHAT_SYNC:`。

新档版本为 v2，时间线协议为 schema 1。旧 v1 档迁移时保留原随机流。聊天身份或完整历史缺失时，诊断会注明能力降级，不能保证删楼、分支和消息去重。实际宿主事件与异步变量 API 行为仍需 TT 实机验收。

v0.8.3 新增 `src/contracts/chat-sync-report.js`（无正文的错误/楼层契约）和 `src/ui/sync-notice.js`（定位、重新校验和复制诊断）。请勿将引擎回合 `floor` 当成聊天楼号。诊断提供 `lastFailure` 与不确定提交标志 `needsReload`；恢复原聊天后可重新校验解除阻塞。普通操作失败与时间线损坏分开处理。


## v0.8.6 无新增聊天楼的本地操作

时间线 schema 1 增加可选 `locals`：以当前完整聊天路径为锚保存本地活动／物品操作的完整档，同路径更新最新检查点，最多 64 个路径。`locate` 选择最新匹配的输入／回复或本地检查点；切换回复分支不会把另一分支的活动带入。修改回复前发生的物品操作必须带入随后回复，不能回退到旧 `afterInput` 而覆盖掉。

日程命令另含操作编号、日期／时段／递增序号及聊天 scope／epoch。重复请求复用已保存回执，保存应答不确定则先重读；不以新编号盲目重试。普通费用／条件错误仅在活动区提示，不锁住全局同步。检查点损坏可确定路径时报告对应聊天楼层；超窗仍保留原档并提供原恢复入口。

日程框架测试已加入 `npm run test:sync`。详细业务边界见日程行动框架文档。TT 实机与无原子 CAS 的宿主限制仍保留。
