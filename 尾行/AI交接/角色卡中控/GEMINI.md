## 一、设计宪法（核心定稿，不得重议）

1. **效果只认标签**：凡加减益走后台标签栈，叙事口说无效（防 LLM 口胡）。
2. **故事描写后台定果**：LLM 只申报事实，骰子、修正、结算全在中控单一真源（借仙姝堕 dispatcher 架构）。
3. **她的状态是天气不是仪表**：玩家侧数值全亮，她侧只给行为信号（DC 变化不解释原因，信号歧义是设计特性）。
4. **一切结算汇于状态栏**：插件是器官，状态栏是壳，中控单一真源。状态栏统筹常驻条、抽屉、深页、手机设备与结算台。
5. **LLM 出场判据是「有戏没戏」**：例行走插件（打工、购物、例行结算）零楼数零 token；只有出现实质剧情、对话交互、节点事件才请 LLM 进场。
6. **终局行动常开**：扳机永远在玩家手里；条件不成熟的失败是机制必然（六道墙拦截：知识/距离/身心/转移/结算/教育）。
7. **追缉系统已砍**：玩家全程处于灰色地带，警党不会登场；真正压力来自她的警觉、长线防备以及身边人。追缉仅作结局层文案用途。
8. **系统做减法**：保留核心四感载体（心跳甜区、警觉、面容记忆、接近度、谎账、标签栈、种子骰、养与杀）；冻结车厢章、后三模板生活包（**原「天赋系统」已于 v0.8 转正为开局身份制并落码**——七身份池＋20 点自设基底，数值真源 `rules.json identity`，设计见数值策划第一节）；疑虑与戒心合并为「她的防备」；**放弃自然语言穷举**：动作判定只认前端胶囊/抽屉传递的结构化代码对象（Action ID 直通中控单一真源），输入框文本纯作玩家给大模型的伴随扮演叙事，两者在架构上完全解耦。
9. **美术走素材线**：基米保功能与逻辑严密；插件只认 PNG 图片（3D 文件不进卡）；音效合成优先 + 微采样混合。
10. **Token 与性能纪律**：白天经济与准备期全在插件完成（零楼数）；开发 token 同样是成本，必须纸面先行、公式推演到位、一次做对。玩家可见层严禁开发黑话，使用通俗人话。
11. **行为必须单独成册**：每个判定行为必须以「行为定义｜适用场景｜判定标准｜判定公式 + 联动」四栏规格收入《行为册.md》，有判定就有页。
12. **动作与标签全量注册**：讨论与设计中提到的每一个动作（如偷袭、强攻、追逐、按制等）与标签（如胆小、胆大、压制等），必须在后台词表（`lexicon.json`）与规则/标签栈中全量注册，严禁口头存在黑户。
13. **严禁口头设定，凡讨论必对后台**：策划、交流与机制推演中，严禁使用模糊的自然语言主观臆断效果（如“体力恢复略快”、“防备不易消退”、“易分心”等浮夸口说）；所有性格、爱好、特征与交互，必须能直接映射为后台真实字段与代码管道（Tag ID、Category 分类、数值修正 Value、检定 DC 钩子、物证道具与 HUD 展现契约）。杜绝模型口胡乱编，凡无法落入规则、词表与引擎真源的概念，一律不得作为机制依据。
14. **宿主环境与角色卡真源铁律**：主人使用的真机环境为 **TT 酒馆**，角色卡与世界书改动的**唯一交付真源路径**为 `E:\角色卡制作\尾行\最新成品\尾行.json`！世界书采用标准 Spec V2 格式内嵌于该卡片的 `character_book` 字段，严禁将外部其他酒馆目录当作真源。世界书条目严格做减法，仅收录明确讨论定稿的目标群体生态画像条目（开局选定目标后动态常驻与互斥），所有系统规则、回执演绎与文风骨架统一收拢于卡片 `system_prompt`（方案三），杜绝在世界书中塞入未经讨论的冗余陈旧条目。

## 三、工程复盘与错误归因戒律（真机交互血泪经验）

1. **数据结构重构全量检索防悬空**：
   - **典型教训**：操作线重构为数组 `LINES = [70, 90]` 后，绘图逻辑残留 `LINES.normal[0]`，在脚本顶层抛出未捕获 `TypeError`，直接阻断后续全部事件监听器注册，导致仪表盘与终端在真机中完全点不动。
   - **执行防线**：修改任何配置、状态字段或全局常量规格后，必须在全局（含 `src/` 与 `状态栏.html`）全量检索旧字段名；修改前端脚本后必须运行 DOM 执行测试，验证零报错方可交付。
2. **热更新清理机制禁设拦截死锁**：
   - **典型教训**：打包脚本中写死 `if (topDoc.getElementById("wx-statusbar-root")) return;`，导致真机测试中覆盖新代码时，检测到旧 DOM 存在直接退出，既有僵死节点无法被替换，新修复代码无法生效。
   - **执行防线**：嵌入式状态栏挂载逻辑必须采用「先清理旧节点（`oldRoot`、`oldModals`），再挂载新闭包」的热插拔模式，严禁使用直接 return 的拦截逻辑阻断更新。
3. **原生嵌入非核心 DOM 判空防护**：
   - **典型教训**：状态栏提取进入酒馆时仅打包主 section，若脚本直接访问仅在预览外部存在的元素（如 `previewStatus`、测试调试控件），未判空即抛空指针异常，造成快照渲染中断。
   - **执行防线**：状态栏脚本内所有 DOM 获取与属性赋值，一律采用判空守卫（`const el = document.getElementById(...); if (el) ...`）或安全可选链，非核心辅助展示绝不可阻断核心数据流与交互闭环。
4. **动作与输入解耦铁律（胶囊代码单一真源）**：
   - **典型教训**：前端胶囊传下结构化动作对象后，中控曾退化地将其拼装成 XML 文本字符串并调用正则解析器重新猜测，一旦按钮展示名称不匹配即丢弃动作，导致“选了动作却结算 0 个”并试图靠穷举别名库补救的严重偏差。
   - **执行防线**：前端传递的结构化动作对象必须直通中控执行引擎（`opts.actions -> _actionQueue -> settleAction`），严禁将结构化数据降级拼装为文本再走反向猜词；输入框自然语言纯作伴随文学描写，绝不参与动作判定。
5. **静态文本越权侵入动态中控管辖区（静态与动态状态机边界铁律）**：
   - **错误类型本质**：静态开场白或常驻系统提示词越俎代庖，去硬编码本应由中控引擎（Target State）负责动态抽样与管辖的数据槽位参数（如具体服饰细节、鞋具声响、双手行为、身心理由与即时心智状态），导致静态文本抢跑中控职权，与后续动态回执产生数据竞争、语义冲突与状态穿帮。
   - **执行防线**：静态文本只负责客观宏观环境底色、时空物理定位与远景留白剪影；所有涉及目标个体的微观具象表征（着装、鞋具、双手、身心），必须且只能由后台规则与生活包真源通过回执流动态驱动，严禁静态层抢跑越权。
