# 重点维护：聊天与存档同步

玩家在仙姝堕项目中多次反馈对话与存档不匹配；尾行将同步作为独立模块维护。入口是 `src/host/chat-sync/`，事件接线是 `src/host/glue.js`。

## 已实现的处理

| 操作 | 当前处理 |
| --- | --- |
| 切换聊天 | 按角色/聊天身份识别会话；旧任务在读取、提交、通知等步骤校验代际并取消 |
| 重复消息或重复事件 | 指纹匹配已记录回合，复用原结算；并发请求串行处理 |
| 重生成回复 | 恢复动作结算后的状态，只重做回复声明，不重掷、不重复记账 |
| 删除/编辑消息 | 匹配最后共同检查点，恢复账目、路线、日期、标签、装备、随机状态等完整数据 |
| 复制/切换分支 | 按完整消息前缀匹配保留的分支，不能只靠楼号判断 |
| 保存失败 | 不发布未保存快照；模块内动作使用独立草稿，失败恢复原内存实例 |
| 两个脚本实例冲突 | 比较时间线 revision 和已读存档正文指纹，冲突时拒绝覆盖 |
| 损坏/未知版本存档 | 保留原档并阻止后续普通保存；不静默初始化新局 |
| 重开 | 清理存档、快照、时间线、回执和待处理标志，同时保留重开前备份 |
| 版本升级 | v1→v2 显式迁移，旧档随机版本保留为 1；新局使用修复后的版本 2 |

这些行为有自动测试；它们依赖宿主提供真实聊天身份和完整消息历史。当前适配从 `SillyTavern.getContext()` 读取 `characterId/chatId/chat`，聊天 ID 也可经助手的 `getCurrentChatId()` 获得。

如果宿主只有变量 API，没有身份或完整历史，保留基础读写并在 `wx_diag.sync` 和诊断接口中显示降级状态。此时不能提供完整的去重/历史恢复保证。不能用临时虚构的聊天 ID 掩盖能力缺失。

## 边界与保留窗口

时间线最多保留 64 个回合/分支节点，达到窗口后推进基础检查点并清理更早的分支。修改早于基础检查点的消息会返回 `HISTORY_OUTSIDE_WINDOW` 并停止覆盖，须恢复相应聊天历史或选择有效备份。

升级前的旧档没有逐楼时间线，只能从首次接入时的完整档作为基础检查点；不能凭空恢复升级前删掉的回合。

变量 API 仍由宿主指定活动聊天。代码在调用前后核验身份，并将档、显示快照、时间线和备份同次提交；这不是宿主数据库事务。宿主必须在写入调用时确定写入对象。如果某个 TT 分支延迟到 Promise 完成时才选择目标聊天，必须为该分支增加明确的定向写入适配后再承诺跨聊天写入隔离。跨实例 revision 校验也不等同于底层原子 CAS。

## 数据契约

| 变量/接口 | 用途 |
| --- | --- |
| `wx_save` | v2 完整引擎档；v1 可迁移；恢复不使用 HUD 快照 |
| `wx_snap` | 脱离引擎引用的显示快照 |
| `wx_timeline` | schema 1 时间线，含检查点、完整状态和消息指纹，不存消息正文副本 |
| `wx_sync_backup` | 覆盖前最后一份完整档及时间线；单份备份，不无限增长 |
| `wx_init` / `wx_conf` | 开局参数 / 管线设置 |
| `wx_diag` | 最近提交的楼号、注入通道、身份验证与时间线版本信息 |
| `WxGlue.getSyncDiagnostics()` | 当前实例最多 24 条诊断事件，以及能力/阻塞状态；不含正文、盐或完整档 |
| `WxGlue.reconcile()` | 按当前历史重新匹配检查点；失败保留原持久档 |
| `WxGlue.restoreBackup()` | 显式恢复备份；校验其与当前历史兼容，恢复前仍备份当前档 |
| `WxGlue.command(method, ...args)` | 序列化执行装备、消耗品、过夜等命令；UI 不再先改引擎再单独保存 |

以上调试接口通常位于助手隐藏 iframe 上下文，父页面控制台未必直接可见。不要向玩家索取完整聊天或包含未公开资料的全量变量作为第一步排查材料；优先收集错误码、操作顺序、版本和能力状态。

## 症状与首查位置

| 症状 | 首查 | 关键错误/信息 |
| --- | --- | --- |
| 切聊天后进度错误 | `session.js`、`environment.js` | `STALE_SESSION`、身份/历史能力 |
| 同一动作扣账两次 | `timeline.js`、`glue.js` | 输入指纹、重复事件、是否处于降级模式 |
| 删除/编辑后不能恢复 | `timeline.js` | `HISTORY_OUTSIDE_WINDOW`、基础检查点 |
| 进度保存失败 | `repository.js`、controller 提交步骤 | `WRITE_FAILED`、`WRITE_CONFLICT` |
| 已保存但界面没更新 | UI 快照接收与轮询 | `PUBLISH_FAILED`、过期 scope、组件是否卸载 |
| 旧档无法读取 | `migrations.js` | `SAVE_VERSION_UNSUPPORTED`、`SAVE_INVALID` |
| 时间线损坏 | `timeline.js` | `TIMELINE_INVALID`；不要清档重建掩盖错误 |
| 重开或设置失败 | controller | `RESET_FAILED`、`CONFIG_INVALID`、`CONFIG_WRITE_FAILED` |

其他错误包括 `READ_FAILED`、`RESTORE_FAILED`、`SERIALIZE_FAILED`、`MESSAGE_NOT_FOUND` 和 `BACKUP_MISSING`。`persist.done` 代表宿主成功应答，不代表底层提供数据库事务。

## v0.8.3 楼层诊断与恢复修复（2026-10-22）

本次修复聚焦真实同步故障，不接入白天玩法。

- `timeline.js` 比较消息指纹，报告**首次差异的聊天索引**（从 0 楼起算）、当前消息 ID、是否已缺失、最早保留检查点位置。首次差异不等于能证明玩家具体做了哪次编辑；插入、删除和修改都可能改变后续前缀。旧档没有历史检查点的部分不能凭空重建。
- `src/contracts/chat-sync-report.js` 将错误转换为白名单诊断契约。存档损坏、版本不支持或宿主读取失败无法归因到某楼时，明确显示“无法确定具体聊天楼层”。游戏 `floor` 是结算回合，不当成聊天楼号。
- `src/ui/sync-notice.js` 独立负责显示、定位、高亮、重新校验与复制诊断。被删楼无法定位；历史楼未加载时提示先加载历史。复制内容不包含聊天正文、堆栈、种子盐或完整存档。备用快照刷新不再掩盖故障。
- 玩家恢复对应聊天后，“重新校验进度”会重新读档并解除已解决的阻塞，不再陷入旧阻塞标志无法自愈的循环。校验只恢复已有检查点，不重掷，也不自动补结算未成功提交的操作；失败操作须重新选择动作后重试。
- 修复刷新/强制重读后只恢复内存而不写回持久档的问题；修复删楼后执行物品/过夜命令使用旧回合状态的问题；恢复备份也按当前聊天检查点定位。
- 结算提交前后核对当前聊天历史；期间改楼则停止发布草稿快照，要求重新校验。存储调用已经发出时不能假设一定没落盘，因此标记 `needsReload`，下一次操作先读取实际结果。宿主写入成功但应答失败的重试，会复用已提交回合，避免重复扣除。
- 进一步校验基础路径、节点路径、回复路径与父子前缀关系；损坏时保留原档。普通命令错误不会作为时间线损坏锁住整局。

维护入口：宿主 `controller.js`（恢复和提交）、`timeline.js`（匹配和楼层）、`src/contracts/chat-sync-report.js`（诊断契约）、UI `sync-notice.js`（玩家提示）。诊断接口新增 `lastFailure` 和 `needsReload`，失败事件保留楼层元数据，返回深拷贝。

### 玩家处理顺序

1. 保留聊天，查看错误码和首次差异楼层；使用“定位该楼”查看，未加载则先加载历史。
2. 若是较早聊天被改动，恢复对应内容/分支后点“重新校验进度”；若是重复脚本冲突，关闭重复实例后重新校验。
3. 若是存储失败，先校验实际保存结果，再决定是否重试动作，避免重复点击。
4. 真正损坏、未知版本或超出保留窗口时保留原档及备份，提供“复制诊断信息”的内容排查。不要为了消除提示而直接清档。

### 自动验收与实机边界

新增回归覆盖：第 0 楼差异、缺失楼层、恢复原聊天解除阻塞、刷新后删楼写回、删楼后命令、保存中改楼、备份按历史恢复、并发冲突恢复、损坏回复路径、诊断隔离、宿主已落盘但应答失败，以及定位/重试/异步旧请求不清除新错误的 DOM 交互。

64 节点保留窗口、旧档没有历史快照、宿主缺失完整历史和底层缺少事务/CAS 的边界仍然存在。以上不是所有 TT 分支已完成实机验收的声明。发布前后的真机检查应包含删楼、改楼、swipe、聊天切换、刷新、重复脚本和存储应答失败；未验证项仍按待验收处理。

本轮本地验收：完整自动测试 348 项通过；专项测试、类型检查通过；Chromium 桌面与手机宽度共 55 项检查通过，包含错误楼层显示、楼层高亮和诊断复制。TT 实机验证仍为待办，不以浏览器模拟替代。


### 超出窗口但希望继续的玩家入口

仅 `HISTORY_OUTSIDE_WINDOW` 提供“保留现存进度继续”。第一次点击展示说明，第二次明确确认后调用 `WxGlue.acceptCurrentSave({confirm:true, expectedEpoch})`：校验完整现存档和聊天身份，备份修复前存档及时间线，以当前聊天建立新检查点，保留现存数值和回合，不初始化新局。早先聊天改动不补算，旧回合动作不能借此重放。切换聊天后旧确认失效；损坏或未知版本的存档拒绝此恢复操作。它是玩家主动选择的对齐方式，不代表已经重建丢失的历史。


## v0.8.6 无新增聊天楼的本地操作

时间线 schema 1 增加可选 `locals`：以当前完整聊天路径为锚保存本地活动／物品操作的完整档，同路径更新最新检查点，最多 64 个路径。`locate` 选择最新匹配的输入／回复或本地检查点；切换回复分支不会把另一分支的活动带入。修改回复前发生的物品操作必须带入随后回复，不能回退到旧 `afterInput` 而覆盖掉。

日程命令另含操作编号、日期／时段／递增序号及聊天 scope／epoch。重复请求复用已保存回执，保存应答不确定则先重读；不以新编号盲目重试。普通费用／条件错误仅在活动区提示，不锁住全局同步。检查点损坏可确定路径时报告对应聊天楼层；超窗仍保留原档并提供原恢复入口。

日程框架测试已加入 `npm run test:sync`。详细业务边界见日程行动框架文档。TT 实机与无原子 CAS 的宿主限制仍保留。

## v0.8.20 心跳衍生状态回归

甜区标签sweet_focus由已存心跳推导，不写入save.tags，避免旧档、回退与保存失败重试时因临时标签顺序产生差异。snapshot只读，不在读取快照时增删心跳标签；恢复仅重建甜区标签，保留旧档高心跳标签原状，实际检定时再正常刷新。resource-sweet.test.js纳入test:sync，覆盖边界、恢复及旧档。

独立日程预览的补救状态与工资回执只随同一试玩保存，尚未接TT聊天时间线，不能据此宣称真实聊天删楼／swipe已验收。
