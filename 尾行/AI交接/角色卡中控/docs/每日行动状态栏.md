# 每日行动状态栏 v0.8.4

本轮范围：将每日行动点、五时段、当前活动与结束状态接到正式状态栏和共用完整存档。尚未启用全天活动调度、目标全天日程、身份排班、尾行入口条件、活动入场扣费和完成后推进。没有增加能绕过条件的“开始尾行”按钮。

## 已确定的规则

- 每天 4 点行动点。
- 每个时段只能进行一次活动；活动完成后推进一个时段。
- 尾行消耗 2 点，但只占一次活动机会；内部回合不额外扣每日点数或推进五时段。
- 五段顺序显示为早间、午间、午后、晚间、子夜，对应原讨论的“早、中、午、晚、子”。本轮仅确定顺序，不新增分钟边界。
- 共用存档保存日程，与聊天分支和恢复检查点一起恢复，不在状态栏 localStorage 单独存储。

## 数据与入口

| 文件 | 职责 |
| --- | --- |
| `src/config/day-plan.json` | 4 点、尾行 2 点、五时段标签的唯一配置 |
| `src/contracts/day-plan.js` | 日程校验、兼容初始化和派生显示数据 |
| `src/runtime/game.js` | 实例初始化、恢复、原过夜后的预算初始化 |
| `src/runtime/game/save.js` | 完整档中的 `dayPlan` |
| `src/runtime/game/snapshot.js` | `dayPlan` 只读显示快照 |
| `src/ui/renderers/day-plan.js` | 日程条显示、空态和清理；不扣点或推进时间 |
| `src/ui/template.html`、`styles/statusbar.css` | 正式结构和桌面/手机样式 |
| `tools/build/day-preview.js` | 生成独立预览，使用正式 UI 与引擎存档往返快照 |
| `previews/day-plan/` | 可切换状态的 HTML 及浏览器实际截图 |

存档字段：`schema`、`period`（0～4）、`spent`（0～4）、`activity`、`ended`、`source`。日期来自同一账本，不重复维护；预算、剩余点数、时段名称从配置及存档派生。尾行活动记录须标明已经支付 2 点；字段非法则报告 `SAVE_INVALID`，不能为了显示而静默补满。

## 与原流程的兼容

- 存档版本仍为 v2，日程字段为可选扩展；新日程自身协议为 schema 1。
- 没有日程字段的旧档按原时段补显示状态，标记 `source: legacy`。不猜测历史消耗，不补扣此前尾行费用，不改变原路线、账本和随机流。
- 当前正式卡继续原夜间开局，日程条显示“原有夜间流程 / 日程活动尚未启用”。显示的 4 点是新增日程的预备预算；原动作目前不消耗它，不能作为全日日程已启用的证明。
- 原来的显式过夜成功后初始化下一日显示预算；过夜被原规则阻止时保留日程。刷新、普通消息和重生成不会重置或推进日程。
- 完整活动逻辑接入时，应在同一次保存事务内更新活动效果、点数、当前活动、时段与去重记录。不能让 UI 自行先扣点再保存。
- 当前没有活动完成按钮，避免把“结束”点击误当成完整业务结算。

## 预览与验收

`npm run preview:daily` 生成 `previews/day-plan/index.html`，下载后可用浏览器直接打开。含早间 4 点、午后 3 点、尾行中 2 点、本日结束 0 点，以及“当前正式流程”五个显示状态。切换只查看显示，不执行活动；演示状态经过实际引擎保存、恢复后生成，不混入正式模板。

`npm run test:browser` 同时生成桌面 1100px 与手机 390px 截图，并检查 320px 无横向溢出。`npm test` 覆盖日程往返、旧档兼容、非法数据拒绝、普通回合不推进、日期预算初始化、渲染清理与跨聊天隔离。TT 酒馆实机显示仍需验收。

本轮本地结果：完整测试 355 项、同步专项 63 项、浏览器检查 76 项通过，类型检查通过。浏览器检查含 1100/390/320px 日程状态和原有零楼、弹窗、音频异步检查；不代表已完成 TT 实机验收。

## v0.8.5 纠正旧显示

- 移除“探头锁定·禁动手 / 深水盲区·终局开”常驻标签。其来源只是地点 `strike_sealed`，并非实时探头检测。底层地点数据与现有判定不在本次修改范围。
- “离收摊剩 N 步”按 `route.nodes.length - 1 - route.here` 计算，实际是路线剩余节点。现显示“路线剩余 N 段”，提示明确排除行动点、剩余回合与一天结束倒计时；终点也不再称作安全区。终端日期统一显示“第 N 天”。
- 清除咖啡配置中的“行动点+0.5、日限两杯”承诺。它从最早导入的配置即存在，旧策划对应物品表仍标为待终审，不能据此认定用户已确认。实际使用代码原本不改变行动点或任何数值，本轮保持行为并如实标注，不另加效果。
