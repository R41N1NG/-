# 日程行动框架 v0.8.6

本轮完成统一注册、可用条件、费用预览、本地效果结算、活动结束、时段推进、换日和整卡存档接线。目标全天日程、职业排班、工作报酬表、商店货单与交流事件尚未实现，不以示例数据开放入口。

## 当前可见效果

| 活动 | 暂定费用 | 当前支持 |
| --- | --- | --- |
| 休息 | 1 点 | 本地恢复 `min(50, 体力上限 − 当前体力)`；满体力不收费用、不推进 |
| 打工／接单 | 1 点 | 预留工作处理器；暂无可接工作 |
| 购物 | 1 点 | 预留批量结账输入和物品效果接口；暂无商店 |
| 独立交流 | 1 点 | 预留持续事件；暂无交流事件 |
| 尾行 | 2 点 | 预留出行条件和持续活动；尚未连接原尾行流程 |
| 度过本时段 | 0 点 | 无收益、无恢复；推进一次时段 |

休息 50 是本轮暂定试验值，配置在 `daily-actions.json`。每天 4 点，五段为早间、午间、午后、晚间、子夜；活动结束后只推进一段。尾行或交流入场先扣一次费用，结束前保持时段；内部回合不触碰每日费用。结束／中止均不退点，只有可信本地处理器允许时才出现可用控制。零点也能度过剩余时段。本日结束后显式进入下一天，不自动跳过玩家尚可查看的状态；换日复用原日期、天气等轮转。

正式卡继续默认原流程，保留原胶囊和目标选择功能。新界面有“试用日程安排”：只在原流程尚未推进或已到路线终点时可用，从当前时段启用，不补扣历史费用。按钮提前说明尾行入场条件待接通。完整的全天玩法尚不可替代原流程，不能把试用入口描述为已接完整日程。独立预览默认启用日程，可操作休息、度过时段、换日。

UI 不维护点数副本；按钮文字不是判断依据。日程 ID 已注册到词表，`dailyOnly` 会拒绝从旧动作管线绕过费用。正式新增活动也应在词表注册 ID，但日程处理仍统一走日程命令。

## 新增活动的方法

1. 在 `daily-actions.json` 增加定义；新的内容业务独立成模块，由 `registry.js` 装配。`instant` 为一次完成，`scene` 为持续活动。只有已完成本地结束条件的场景才能接通入场，避免出现无法结束的活动。
2. 处理器仅接收脱离引擎引用的 `ctx`，包括账本、玩家、日程、世界和目标 ID。`available(ctx)` 返回不可用原因或 `null`，`prepare(ctx,args,definition)` 返回本地算出的结果。
3. 结果为 `{summary, ledger?, inventory?, payload?}`。`ledger` 是增量；`inventory` 当前仅支持已有物品 ID 的正整数添加。资金不足、未知字段、物品无效等整笔拒绝。装备、消耗、移除、地图改变等没有通用结果接口，接入时须补专用校验，不能默默忽略。
4. 持续活动把业务状态存于 `activity.payload`。`finish(ctx,args,activity)`／`cancel(...)` 复核实际条件后返回效果；不能相信玩家参数或模型声称“已完成”。处理器为同步、可信本地代码，不接受模型提供的函数或公式。
5. 如需商品／工作等选项，定义 `inputRequired: true`，通过 `WxStatusbar.dailyActions.registerInput(id, async snapshot => args)` 注册 UI 输入提供器；取消返回 `null`。输入回到引擎后仍需检查价格、货品、资格等，UI 不能直接声明收益。
6. 测试可通过 `createGame(init, {dailyActions:[{definition,handler}]})` 注入适配器。宿主若使用该装配方式，必须让 `createGame` 工厂在恢复／草稿克隆时持续提供相同处理器；处理器不写入 JSON 存档。

停用时保留活动 ID 的旧档读取与结束处理，先隐藏新入场入口；不能直接删除仍被进行中活动引用的处理器。

尾行接入的下一步：提供经过本地目标日程检查的出行机会，入场时初始化原路线／模式，场景内部使用原回合引擎，退出时由可信适配器调用统一结束接口。当前只验证了此接口的扣费和时段语义，尚未实现目标全天出行模块。

## 保存与文字边界

命令带 `operationId`、当前日期／时段／递增序号，以及聊天 scope／epoch。宿主先匹配历史，再从完整档建立草稿，执行效果并保存；成功后发布快照。相同请求复用最近 32 条回执；回执过期后旧状态序号仍能拒绝重复执行。不同请求冒用同一编号会被拒绝。聊天生成期间不允许安排新活动。

无聊天楼层的本地操作记录在时间线 `locals` 检查点中，以完整聊天路径为锚；同锚保存最新完整状态，不修改不相关回复节点。编辑／删楼后取匹配分支的检查点；恢复原回复可找回原本地活动状态。与输入回合一样保留最多 64 个路径，超窗明确报告首次差异聊天楼层，原档保留，不能承诺无限回溯。本地操作不会凭空增加聊天楼。

保存拒绝时不发布未保存进度；应答丢失时重新读取确认是否落盘，重试使用原请求避免重复扣点。宿主变量接口没有原子 CAS，跨窗口同时写入的宿主限制仍存在。

日程待机／普通交流文字不执行旧夜间结算，也不解析模型宣称的奖励或情报。发送文字时注入当前日程、最近已结算活动和叙事边界；这能约束提示，但不能保证模型从不写错文字。机械状态仍由本地代码保护。当前未接自动交流生成，休息／度过时段不请求模型。
