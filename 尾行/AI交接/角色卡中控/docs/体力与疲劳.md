# 体力与疲劳（暂定实装，v0.8.24）

本轮先调整玩法，不新增体力教程。正式引擎与女大独立预览共用规则；全天日程、首败补救和打工DC15仍只有独立预览接入。

## 费用与难度

- 六种跟随动作（follow、ride_along、transfer、follow_work、ride_follow、car_follow）每次4点，打量2点，拍照3点。成功、失败、大成功均付动作费用。
- 原心跳段税保留：每回合按峰值收1/2/4/6点，同回合多个动作各付费用、段税只收一次。既有追逐／冲突规则不改。
- 判定前读取当前体力／实际上限：大于50%不加DC；25%至50%（含两端）跟随DC＋1；大于0但低于25%跟随DC＋3，替代＋1。远端＋2可叠加。不直接修改敏捷，不给打量／拍照套疲劳DC。
- 体力0不能继续付费跟随；1至3点也不足支付4点跟随费用。可补给或结束本次尾行，保留已获信息。补给原效果与休息恢复50不变。
- 一轮动作的费用合计不足时，结构化输入在结算之前拒绝，不扣资源、不推楼层／钟点／路线，不送免费骰。玩家可删减动作或补给后重试。每个动作的疲劳DC按其执行前体力决定，因此前一动作花费可能使后一动作跨档。
- 每次尾行的首败补救仍只在独立预览；追找需付跟随4点及一轮段税。体力不足不会吃掉追找机会或改变距离。

## 源码与存档边界

- 数值：rules.json stamina.fatigue；费用：lexicon.json entries[].cost.stamina。
- 比例与可支付性：src/contracts/stamina.js；仅纯函数派生，没有新疲劳标签或持久字段。
- 检定：game/checks.js fatigueDC；动作记账：game/actions.js；输入费用预检及回执：game/turn.js。
- UI费用／锁定：action-options.js、statusbar.js；体力提示：renderers/snapshot.js；判定账目：settlement/controller.js。
- 新局无显式体力时，在身份修正上限后补至上限；旧档与显式初始体力保持原值。原save v2和聊天时间线版本不变。snapshot不修改状态。
- STAMINA_INSUFFICIENT属于游玩条件不足，不标记聊天同步故障，不显示“进度不匹配”或要求重新校验；真实存储错误仍走同步专项。

## 预算参考

原同街六轮样本心跳段税合计11点。若心跳／判定过程保持相同：仅跟随35点；每轮另打量47点；每轮另打量和拍照65点。这是预算计算，不是保证每次实战恰好如此。新角色满体力、距离变化、失败与补救会改变实测结果。

先验证疲劳是否形成补给与休息选择，再考虑调数值或制作教程。验证记录见本轮GEMINI.md。

本轮实测：独立女大预览种子college-preview-2、晚间入场、同街连续六轮，新局115体力；只跟随最终80，每轮跟随＋打量最终68，每轮跟随＋打量＋拍照最终50，均六轮成功。该样本最后一次跟随判定发生在跨疲劳线之前，因此其疲劳DC仍0；不能宣称满状态短路线一定触发疲劳。需要继续试玩先打工再出发与较长取证流程。
