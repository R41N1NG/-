# 街区地图与采购分区 v0.8.9

本轮按用户要求把城市地图做成固定空间布局，显示玩家及已知目标位置；专用器材迁至固定区域黑市，线上入口仅保留食品补给。沿用既有四区与 39 个节点，增加玩家据点、临江黑市，共 41 个地点，不改原目标路线与检定公式。

## 实际游玩

地图常驻于状态栏，可收起，提供全城与四区切换。v0.8.8 的节点连线图已被俯视街区地图替换：道路划分街块，建筑屋面、公园林地、院落和江面构成底图；地点固定在对应地块或街口。主路、支路、小巷和步道按宽度与颜色区分。老城在西北，郊野在东北，临江在西南，CBD 在东南；各视图北向一致。

默认完整适合屏幕，可“放大查看”后横向滑动；全城保留主要地标，街区展示全部地点。点击建筑或地点只查看；确认“前往这里”才修改位置。缩放、切区、点选不消耗 AP，不写存档。底图道路用于表达地理空间；实际可通行出口仍由 `places.json` 与本地条件决定，不能因画面上有街道就绕过私人区域或交通门槛。地理底图不声称真实测距或新增目标全天日程。

玩家位置是独立字段，不再用目标路线 cursor 作为日程玩家位置。尾行中仍由原回合决定移动，不能在地图上免费跳到别处。目标只在本地目视成立时画实心标记；跟丢后画带虚线边框的“忆”标记，并显示记录日期。没有目击记录时显示未知。日程移动、模型文字不会直接更新目标位置；没有新增定位器实时追踪能力。

陌生私人区域标作“未探明区域”。地图可展示公共空间结构，但不等于已获得某人的门牌或进入权。地图不提供进入住宅的捷径；需要进入条件的节点仍走原机制。已有目标全天日程尚未接入，因此日程待机不会按旧夜间路线伪造目标实时位置。

## 移动规则与保存

数值策划第二十六节已有“核心三区日常穿梭不额外消耗行动点”规则。本版日程待机允许 A/B/C 市内移动：不扣 AP、不推进时段，也不作为一次已完成活动。活动进行中、日终和原尾行流程禁止该入口移动。到店采购确认后仍消耗 1 点并推进一次时段。D 区交通代价尚未接通，不提供免费北郊直达；不会新造车费／概率。

每次移动仍有操作编号、日期／时段／递增序号与会话校验，和工资、订单一起走整卡草稿保存。保存失败不更新位置；应答丢失先重读并复用同一回执。聊天回退、恢复原分支或切换聊天，同步恢复位置与对应采购资格，不单设地图 localStorage。

旧档缺少 `spatial` 时保留原账本、路线、随机流，补一个标明“旧档起始位置”的地图起点；日程旧档补为玩家据点，原流程沿既有场景补起点。没有历史目击证据时不补实时目标位置；后续本地目击或玩家确认移动后更新。损坏位置数据拒绝读取并保留原档，不靠重置 AP 修补。

## 采购分区

- **线上补给**：仅售已注册的便当、饭团、能量饮料。在线操作不移动玩家，浏览／取消不收费；确认一批消耗 1 点，按已有体力效果入库和使用。咖啡无已确认恢复效果，故不在该渠道销售。
- **临江黑市**：新增 `black_market_c`，固定在 C 区城中村主弄旁。玩家先在地图前往该处，才能通过地图按钮或日程“黑市采购”打开器材目录；伪造入口／渠道、远程请求同样会被本地拒绝。所有身份可到店，原身份的九折是价格优势，继续读取旧配置。
- **物流**：继续原规则，日常物品即时入库，专用器材隔日到货，购买不等于设备功能已安装。旧 `retail` 订单保留原单价与到货进度，只禁用旧混合销售入口，不删除已有物品。
- **行动点食品**：预留 `actionPointFoodIds` 名单，但恢复量、价格与限购尚未确定，因此未上架，也没有把旧咖啡半点草案恢复为规则。新增前应明确补充 AP 的结算与每日上限，再接入消费端。

## 维护入口

| 文件 | 职责 |
| --- | --- |
| `src/config/places.json` | 既有场所、步行出口、据点和固定黑市 |
| `src/config/city-layout.json` | 固定坐标、四区范围、跨区接驳、私人区域与服务节点 ID |
| `src/contracts/spatial.js` | 可选 `spatial` schema 1 完整档验证 |
| `src/runtime/spatial/system.js` | 地图移动资格、可达性、本地目击、跟丢后的最后位置、只读地图投影 |
| `src/runtime/game/turn.js` | 原本地回合结算完成时同步目击；模型回复不调用此入口 |
| `src/runtime/game/snapshot.js` | 地图投影；日程场所名与分区使用玩家独立位置 |
| `src/config/city-cartography.json` | 各区道路、地块、绿地和地点短名；只管呈现，不定义移动出口 |
| `src/ui/styles/city-map.css` | 地图独立样式与手机适配，由 UI 构建合并 |
| `src/ui/map/cartography.js` | 俯视底图、建筑屋面、街名、地标与位置标记 |
| `src/ui/map/city-map.js` | 视图、缩放、地点查看、移动与黑市 UI 接线 |
| `src/config/economy.json`、`runtime/economy/shop.js` | 线上食品白名单、固定黑市、渠道／地点复核与原订单兼容 |

`spatial` 保存 `playerPlaceId`、`assumed`、`tracking`、`lastSeen`（目标 ID、地点、日期、时段、回合）与 `knownPlaces`。坐标仅存在配置中，地图改版不会改变存档所指地点。原 `route.here` 继续控制目标路线；不维护第二份目标实际日程。

新增地点时同时注册场所与出口、所属区坐标、底图地标短名、私人／公共性质；再绑定服务。新增道路或建筑美术只改 `city-cartography.json`；它不会新增可玩地点或改变寻路。新增店铺须在本地处理器检查位置与商品白名单，不能只在 UI 隐藏按钮。跨区接驳是交通关系，和原区内步行寻路出口分开，旧寻路规则未被暗改。

## 下一阶段的设计前提：玩家引导（2026-10-23）

用户明确要求重点考虑如何引导初来乍到的玩家。目标日程隐性，须通过行动调查逐步体现；地图不应要求玩家凭空知道去学校蹲守。先设计玩家可感知的初始线索和行动动机，再接地点行动：为何注意目标、为何选择该地点、调查发现如何反馈、下一次行动有什么可依据的信息。引导提供调查方向，不提前揭示后台日程或未知住址。具体开局事件、引导界面与重复调查阈值尚待设计和定稿，本节不表示功能已实现。
