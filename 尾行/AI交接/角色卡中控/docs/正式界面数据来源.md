# 正式界面数据来源（v0.8.2）

## 本次修复

旧版正式包排除了 `preview-data.js`，但模板里仍有 OL 档案、敏锐 7、便当情报、设备位置和在线记录。这些字段没有消费者用真实快照覆盖，因此会长期残留。模板现已统一使用空态，预览人物属性脚本已移除。

- 档案：名称取 `snapshot.target.realName/name`；属性只读 `snapshot.profile.attrs`，不从后台 `target.stats` 或完整画像猜测玩家已知信息。
- 情报：引擎投影通过已有 `facts.view()`，读取当前 PI 和当前人物的固定事实。当前没有持久化的成功观察凭据集合，因此不伪造票据，不直接输出全部人物事实。
- 日程：只显示 `snapshot.route.known` 标记的节点和已记录的时间。
- 道具：说明和数量读取当前 `snapshot.inventory`，不再使用三个范例道具的说明字典。
- 设备：实时安装、在线和取卡状态尚无完整持久化后端，显示“设备状态暂未接入”，保留相册入口。
- 谎言：原处理器仅验证当轮申报，没有长期档案，显示“暂无已保存的谎言记录”。
- 追缉：当前版本未启用，界面明确说明，不显示虚构等级。

属性揭示和外观印象尚无完整持久化实现，正式档案保持未知/无记录。本次没有新增这些玩法，不把空壳界面视为已经实现。

## 模块与防回归

`src/ui/renderers/details.js` 统一维护详情页；`empty.js` 在初次挂载、重开及聊天重置时清空实时区域、道具说明、图片和历史指示，避免保留上一局数据。`snapshot.js` 仍负责主 HUD。

`src/runtime/game/snapshot.js` 提供经过规则过滤的 `profile` 投影，包含 `targetId`。详情投影与当前目标不匹配时丢弃。旧档不需要迁移字段，读档后从已有状态重新投影；完整人物生成结果不重抽。

没有真实信号时不再合成“目标离开原位”的记录；计划出发时间保留在路线字段，不能冒充观察事实。正式环境没有引擎命令接口时，行囊操作报错，不走演示逻辑模拟增减资源。同步错误提示区域已补入模板。

生活包完成标记由构建器从实际生活包配置派生，修正原先错误宣称 OL 有完整生活包的文案。未制作的生活包、目标内容和玩法仍未补齐。

维护要求：模板不能带具体人物、已解锁数值、持有物或设备在线等示例事实；新增详情区必须说明它消费哪个快照字段，并定义无数据和重置状态。只有提供明确持久化数据来源后，才能将“未接入”换为真实运行状态。

## 验证

`tests/live-panels.test.js` 覆盖正式模板和脚本残留扫描、情报过滤、存档往返、当前人物名称、未知属性、真实道具说明、无引擎不模拟资源变化、换目标和重开清空。

浏览器检查覆盖桌面及 390px 宽度下的档案/设备空态、其他弹窗、热重挂载、零楼与 Canvas。自动化不代替 TT 真机验收。
