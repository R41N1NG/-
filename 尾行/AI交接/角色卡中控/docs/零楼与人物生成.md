# 零楼与人物生成（v0.8.1）

## 行为与边界

新局在第 0 条消息的正文内显示创角组件，先创建玩家，再选择和生成目标。确认前不写存档、不切世界书、不调用模型、不新增聊天消息。返回上一步不重抽人物；不同目标类型各自缓存当前候选，只有“重新摇号”替换当前类型的候选。

确认仍调用 `WxGlue.newGame(init)`：创建引擎、同步目标世界书、切换目标开场、保存完整首档并发布快照。成功后隐藏零楼、还原开场正文。保存失败保持界面可重试，错误继续交由 `CHAT_SYNC` 诊断处理。世界书和开场的宿主写入不具备跨接口数据库事务，不能承诺与存档原子提交。

已存档的聊天直接续局，不重建人物。第 0 条消息被宿主重绘时，挂载组件重新定位；销毁时恢复正文并清理观察器。未找到消息容器时等待，不退回弹窗或覆盖其他聊天楼层。独立预览允许在预览正文内展示。

卡内原有 `first_mes` 和备选开场保留，作为确认后的开场来源；零楼 DOM 由角色卡脚本挂到消息内，不将整套交互 HTML 写进聊天历史。

## 模块入口

| 路径 | 职责 |
| --- | --- |
| `src/persona/generator.js` | 统一完整人物生成入口，生成版本、种子、属性、外观和固定事实 |
| `src/persona/candidates.js` | 候选过滤、权重、前置和互斥条件 |
| `src/persona/facts.js` | 固定事实抽样；旧 `target_state` 导出仍兼容 |

| `src/contracts/persona.js` | 性格 ID 归一化、人物结构与新人物引用校验 |
| `src/ui/zero-floor/host.js` | 消息内挂载、正文恢复、宿主重绘、扩展插槽 |
| `src/ui/zero-floor/stages.js` | 步骤注册、进入条件、导航 |
| `src/ui/statusbar.js` | 两个默认步骤的内容和建局接口接线 |

UI 与运行时共用纯人物模块，不互相导入引擎实例或宿主模块。现有胶囊、结算台及其他弹窗保持各自入口。

## 随机与存档

`generateTargetPersona(targetId, { seed, version })` 的相同输入产生相同完整结果。省略种子时只在生成入口取得一次熵源。姓名、性格、爱好、鞋具、各属性、外观和事实使用独立随机域；新人物外观不再使用 d20 取模。每日穿搭统一使用种子采样，不再在字符串种子下回落到 Math.random。

人物保存 `generatorVersion`、`generationSeed` 以及完整生成结果。种子用于排查，读档以已保存结果为准；修改候选池不得导致旧人物重抽。新人物完整校验配置引用；旧档按结构校验并兼容旧性格格式，避免删除池中候选后仅因其不再出现在当前池中就拒绝旧档。

候选对象可选字段：

```js
{
  id: "example",
  enabled: true,
  weight: 1,
  requires: { personalityId: ["timid"] },
  excludes: { targetId: ["ol"] }
}
```

这是支持条件对象的生成池契约，不会自动改变生活包旧事实池的权重算法。条件按生成顺序读取：目标类型 → 性格 → 爱好。前置字段未生成时，依赖它的候选不成立。空池、全零权重或非法权重明确报错，不循环重抽或无声替换成其他人物。此版本不新增剧情模板、收益公式或人物数值规则。

## 零楼扩展

零楼根元素有 `data-zero-slot="before"` 和 `data-zero-slot="after"`。简单内容可直接维护模板，也可调用：

```js
const unregister = WxStatusbar.zeroFloor.registerExtension("my-panel", element, "after");
```

新增步骤先在插槽中放入独立的导航按钮、视图区，再注册：

```js
WxStatusbar.zeroFloor.registerStep("extra", {
  tabId: "myTab",
  viewId: "myView",
  canEnter: () => true,
  enter: () => { /* 刷新本步骤内容 */ }
});
WxStatusbar.zeroFloor.go("extra");
```

默认步骤 ID 为数字 1 和 2。新的强制步骤还需调整默认前后导航与 `createConfirm` 的确认条件，不能仅靠隐藏按钮保证其必经。新增持久字段必须通过 `init` → 引擎初始化 → save/restore 接入，不在扩展面板里直接改账本。UI 重挂载会清理扩展，调用方需针对新实例重新注册。

## 目标档案启闭与扩展

预览切换目标不修改世界书，最终确认和读档按实际目标同步。匹配顺序支持条目正文的 `[TARGET_GROUP: targetId]`、目标配置的 `worldbookEntry`，以及已有名称映射。使用机器标记后，调整显示名称不必同步改 JS 映射。

选中的档案设为 `enabled=true`、`constant=true`、`disable=false`；其他目标档案对应关闭，普通世界书条目不修改。没有匹配条目时关闭旧目标档案，返回 `targetMissing=true`，避免旧人物资料继续注入；这不意味着缺少的目标内容已经制作完成。没有世界书 API 时沿用原诊断降级行为。

新增目标仍需配置其生活包、世界书和开场内容。此版本没有填充原有占位目标的缺失内容。

## 验证

- `tests/persona-generator.test.js`：种子复现、结果独立、多目标/多种子、存档往返、旧性格兼容、非法数据、候选约束。
- `tests/zero-floor.test.js`：消息挂载与重绘、正文恢复、步骤扩展、真实建局管线、返回/切换/重抽、续局、热重挂载、目标档案互斥。
- `npm run test:browser`：桌面和 390px 宽度的消息内零楼、布局、步骤交互、原有弹窗、热重挂载及 Canvas 错误检查。

真实 TT 宿主仍需验证消息 DOM 选择器、消息重绘与世界书 API。自动测试覆盖标准 `.mes[mesid="0"] .mes_text` 及 `data-message-id` 适配，不能代替 TT 真机验收。
