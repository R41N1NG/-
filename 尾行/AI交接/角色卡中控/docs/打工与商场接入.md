# 打工与商场接入 v0.8.7（历史实现）

**v0.8.8 已调整销售边界**：线上只售食品，器材须前往固定黑市，详见 [具象地图与采购分区](具象地图与采购分区.md)。下文保留 v0.8.7 接入说明，原混合商场入口已停用，既有订单／物品保留。

用户指出原项目已有内容。核对结果：数值策划第九节已有七种工作和工资档，`rules.json.identity` 已有身份修正与专属工作，`rules.json.items` 已有物品、价格及装备／使用管道；物品章已有普通品当次入库、器材隔日到货规则。v0.8.6 只接通用日程框架，将工作、商场都置为不可用，未把这些内容接上，也没有准确区分“策划／数据已有”和“执行端未接”。本版补上对应执行与 UI。

## 实际行为

- 打工点击后选工种，先显示收入、体力代价、资格原因和一次活动费用。浏览、取消不扣点。确认成功后，工资、体力、每日一班标记、AP 和时段一次保存。
- 当前开放搬场零工、远程接单、保安当班、教练专属私教课、罪犯专属黑工，均按原有底薪／身份倍率结算。示例：阿宅远程 264，学生搬场 280，保安本职 384，教练私教 360，罪犯黑工 196。搬场／黑工体力 −40，私教 −20。
- 商场点击后组一批清单，数量可改、渠道可选，确认前显示总价、现金和行动费用。只在付款时消耗 1 点并推进一次时段；不按商品件数扣 AP。
- 商品／价格源为 `rules.json.items`，不单写 UI 价格表。事件／战利品不作为可购商品。黑市渠道仅对应身份可用，器材折扣读取已有 `identity.blackMarketDiscount`，补给不打折。
- 消耗品及日常用品（如雨伞、耳机）当次入库；工具、科技器材、设备与伪装品隔日到货。付款后有订单列表；进入下一天时，与日期／AP 重置在同一完整档提交到货，只入库一次。购买设备不代表已安装或已接通监控，不追加其尚未实现的功能。

## 没有自行补定的部分

已有过检／高收益工资数值，但没有找到打工 DC 定值，因此当前只结算底薪；选项保留已定加薪档及待定说明。没有拿别的动作 DC 或默认 13 冒充原定规则。

外卖只有“曝光小概率”而无概率值，暂禁；酒吧有占用夜间窗口的代价，但全天尾行适配器尚未完成，暂禁；侦探委托须具体事件。阿宅被动收入、生活费、二手回收／销赃与强制排班不是本轮新增结算，保持待接。保安本职当班的周轮换时段已复核，但没有强制替玩家占班或扣 AP。零楼相关未兑现收入说明已标为待接，避免承诺当前可获得。

## 模块与扩展

| 路径 | 职责 |
| --- | --- |
| `src/config/economy.json` | 从既有策划转录的通用工种工资、身份本职映射、物流分类和清单上限 |
| `src/config/rules.json` | 原有专属工种、倍率、物品价格和黑市折扣，继续复用 |
| `src/contracts/economy.js` | 可选 `economy` 完整档结构和损坏校验，旧档补空态 |
| `src/runtime/economy/work.js` | 工种可用性、本职／专属身份、体力和每日一班结算 |
| `src/runtime/economy/shop.js` | 可购目录、价格复核、订单、隔日到货和只读投影 |
| `src/runtime/daily/system.js` | 通用效果中增加受验证的经济状态，仍是一条保存管线 |
| `src/ui/daily/economy-inputs.js` | ID／数量选择、总价与订单；不宣布收益、不扣费 |
| `src/ui/daily/actions.js` | 输入等待、取消、重试与会话／日程校验 |

工作／商场处理器的 `view(ctx)` 提供只读输入内容，UI 不导入运行时。处理器只相信 `jobId` 或 `channel + cart[{id,quantity}]`，客户端传入工资、骰面、总价都不能改变结算。工资与物流数据改动后同步对应测试与本说明。

完整档 v2 增加可选 `economy` schema 1：`workedOn`、`lastWork`、`orders`。字段不在独立浏览器存储中维护，随整卡和聊天检查点保存。订单有固定 ID、下单日期、实际单价、总额、数量、到货日期和入库标志；最多保留 64 笔，只压缩已完成订单，待收货订单不丢弃。损坏时拒绝读取，不清空订单或补满行动点。

输入等待期间普通轮询不关闭选择；换聊天／推进时段会取消旧选择。热挂载／销毁会关闭并清理表单。复用原日程操作编号与递增序号，保存失败不发布，已落盘但应答丢失时重读并复用原结果。
