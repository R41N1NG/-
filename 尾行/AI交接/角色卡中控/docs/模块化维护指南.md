## 依赖与状态约定

```text
config + 通用算法
        ↑
runtime/game 各业务模块 ← game.js 装配
        ↑
host/glue.js → environment / receipt / initial-state / worldbook / opening
        ↓ 快照、回执、显式命令
UI 入口 → renderers / audio / settlement / action-options
```

- 运行时不导入宿主或 UI。UI 不导入引擎与宿主模块，沿用 `WxGlue`、`WxStatusbar` 和消息通道通信。
- 每次 `createGame()` 创建一组模块实例。模块只通过工厂参数获得所需依赖，不从全局寻找游戏实例，也不反向导入 `game.js`。
- `g` 是单局共享状态，`L` 是账本；数值变更仍经账本接口。跨模块操作通过传入的函数完成，例如行囊使用心跳标签同步接口、警觉模块使用路线推进接口。
- `seedAt`/`getSalt` 读取当前会话盐，不能在工厂初始化时缓存盐值，否则旧档恢复后可能继续使用错误的随机流。
- UI 的 `view` 只保存当前显示状态；音频通过 getter 读取它，快照渲染不持有完整引擎实例。
- 公开 `createGame()`、`WxEngine`、`WxGlue`、`WxStatusbar` 保持兼容，v1 档通过迁移读取。`_g` 作为旧接口保留，新代码优先使用公开方法。
- 模块共享状态尚未改成私有存储，因此新增代码仍需遵守字段所有权；这次重构没有引入另一套状态容器。

## 修改和增删步骤

### 修改一个已有功能

1. 按上表定位模块，先读该工厂参数与返回接口。
2. 在模块内修改实现；规则参数进入 `config`，不要同时写两套数值。
3. 如果改了公开字段，同步检查生产方、消费者和存档恢复位置。
4. 运行测试与构建，在生成预览中确认交互。

### 新增一个引擎功能

1. 在 `src/runtime/game/` 增加模块，导出 `createXxxSystem({ 所需依赖 })`，返回命名方法。
2. 在 `game.js` 创建实例，传入所需状态和回调；不要通过导入另一个业务模块取得它的实例。
3. 从回合管线、动作处理或公开 API 接入。新增持久字段时同时更新初始化、保存与恢复。
4. 如果需要展示，在引擎快照中增加字段，再让 UI 消费该字段。
5. 新动作还需注册词表、规则和 UI 选项，并按项目规范更新行为册。

### 删除一个功能

依次移除 UI 入口、调用方、装配和模块文件，再检查配置与测试。旧档字段应先做兼容处理。不要直接删掉仍被消费者依赖的快照字段。可选 UI 组件只改自身入口；存在业务依赖的引擎模块不能仅靠删除文件来停用。

## 构建和验证

```bash
npm ci
npm run test:sync        # 聊天存档同步专项
npm test                 # 测试进程自动禁用外部酒馆热同步
npm run build:runtime    # 只重建引擎
npm run build:ui         # 只重建可直接打开的状态栏预览
```

完整交付构建：Linux/macOS 用 `WX_SKIP_SYNC=1 npm run build`；PowerShell 用 `$env:WX_SKIP_SYNC='1'; npm run build`。省略该变量会沿用项目现有本地热同步行为。

构建使用锁定版本的跨平台 esbuild。引擎构建失败会终止完整构建，不再沿用旧引擎报告成功。直接修改生成的 `状态栏.html` 会在下次 UI 构建时被覆盖。

验证包括原有 279 项测试，以及旧 v1 存档续局、实例隔离、依赖边界/循环检查、UI DOM 集成测试。重构时另以旧实现做了 56 个检查点的逐步对照，覆盖动作、回复、行囊、过夜与读档。
