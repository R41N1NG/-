## 1. 总则

### 1.1 运行分层（四层 ＋ 演绎规则的落位 · 每张卡都长这样）

```
① 显示层  ── 一条显示层正则把模型输出的纯文本块，换成自包含的 HTML/CSS 卡面
                    ↓ 被渲染时调用（不是监听事件）
② 脚本层  ── 卡内脚本（酒馆助手 iframe 里跑）：纯入口 → 读原文 → 解析 → 写变量 → 回填 UI
                    ↓
③ 变量层  ── 酒馆变量（chat 层为主 ＋ 消息层兜底），**脚本是唯一写入者**
                    ↓
④ 世界书层 ── 常驻公开层 ＋ 按人名/关键词触发的私密层 ＋ 闸门（@@if / EJS 按阶段渲染）
                    ↓
⑤ 演绎规则的落位 ── 全局演绎引擎（FNE 式）＋ 每角色小引擎（心智姿态条）
```

> ⚠️ **别数成"五层"**：①–④ 是**跑起来的四层**，⑤ 只是**演绎规则往哪放**（原稿标题就是"四层"）。
> **范例卡实测（2026-10-01 复核，153 条）**：字面含「女性言行指导／FNE／演绎引擎」的**世界书条目 0 条**；
> 但它的**演绎指引实际落在【叙事引擎】条里**（`constant`／`at_depth`／**9,538 字**，含「双轨视点镜像律」「对手戏与留白法典」「防越权底线」）。
> ⚠️ **旧稿说的「演绎类全局规则全在 `depth_prompt`（1,823 字符／86 行）」在这份拆解里核不出来** —— 范例卡的 `depth_prompt.prompt` 实测是**空字符串**（`depth 4`），`system_prompt`／`post_history_instructions` 也都是 **0 字**。
> 我卡按**秋风口径**（「FNE 类演绎和文本导演指引规则，不要放到 D1 和 D0，放到 CHAR 级别也可以，要强调也别低于 D3 D4」）放 **CHAR 前**（`position 0`，见 v3.0 §1.3）。

### 1.2 六条设计原则（违反任何一条都算不合格；＋**第七条见 §1.5**）

| # | 原则 | 含义 |
|---|---|---|
| 1 | **模型只写人话** | 不让模型交 JSON／变量块；结构化数据由脚本从文本解析 |
| 2 | **永不碎图、永不空栏** | 任何资源或解析失败都有降级链（多源图 → SVG 占位；解析失败 → 保留旧值＋提示） |
| 3 | **判不出来就放行** | **只适用于"条目／功能闸门"类判断**（如"是否最新楼"）：取不到值**默认放行**，绝不因判不出把功能焊死。⚠️ **不适用于"阶段渲染"** —— 那里判据取不到时出**显式安全占位**（v3.0 §8.5；这一处是**刻意**与范例卡"用空 catch 静默退回旬1"相反的） |
| 4 | **一处真相** | 变量只有脚本写；世界书只有一套来源；命名靠约定（拼音 id、前缀、目录）而非名单 |
| 5 | **★ 禁令必须配替代管道（泄压口）** | 写"不要 X"时必须同时写"改写成 Y" —— 只写禁令，LLM 会换个姿势继续作恶 |
| 6 | **0 用户预设** | 引擎只写"角色如何看待玩家"，**绝不规定玩家是谁**（身份、命格、来历、修为） |

| 层 | 放什么 | 判据 |
|---|---|---|
| **CHAR 前**（`position 0`） | 死文本：卡内运行规则、旁白禁泄总注、演绎引擎、阶段驱动、文风、闸门、公开名册、名器释义 | 全部 `position 0` |
| **`@D0`** | 状态栏三件：状态栏规格 ／ 状态字段台账 ／ 收尾契约（**编号必须连续**） | `position 4 / depth 0` |

| **`@D3`** | 角色资料（人物档、公开名册） | `position 4 / depth 3` |
| **禁止** | 「演绎／文本导演指引类规则」落 `@D0`／`@D1`；要贴生成点也不低于 `@D3` | —— |

**但六条【身份】实测是 `position 4 / depth 1`（＝`@D1`）**，而上表把「闸门」列在 CHAR 前 ⇒ **「身份条算哪一档」这条口径含糊、待主人裁定**（`交接说明` §七·11 早已把它列为未决项）。

⚠️ **例外（主人 2026-10-01 令「挪」）**：**`【阶段驱动】` 落 `@D0`（`position 4 / depth 0`）**。
它是**"特殊导演要求"**（秋风 21:1x 第⑧条：「状态栏和**特殊导演要求** D0」），不是一般的"演绎指引"。

### 1.4 ★ 体例三件（硬性）
1. **包裹**：每条一个英文小写 `<TAG></TAG>`，标签名与分区一一对应（见《世界书体例》标签名表）；分区标记条不包。
2. **层级**：`# 条名`（一条只有一个）→ `## 小节` → `### 细分` → `- 条目`；键值写 `- 键: 值`（冒号后一个空格）。
3. **允许符号只有** `#` `##` `###` `-` `:`；**禁**行首 `·`／`・`／`①②`／中文序号「零、一、…」／编号「1. 2.」。

### 1.5 ★★ 承压原则（硬性设计判据）

> **主人原话**：「**我们必须设想 LLM 是会犯错的，给它留出冗余和修复自愈空间。**」
> **秋风原话**：「跟『无』其实没关系，是**这个结构本质上就是在依靠 LLM 这个不稳定的选手来承压做精细活儿**。
> 它还在纠结这种毫无关系的细节。大量『偷懒·无』**已经是注定的结果**，哪怕偶尔没有『无』，**这个结构也是不能依靠的**。」

**1.5.1 判据（设计任何机制时的一句话自检）**
> **模型填错／不填之后，还有什么能顶上来？答"没有" ⇒ 这个设计不成立，退回改结构。**

**1.5.2 三条硬要求（缺一不可）**
1. **关键状态不交给模型**：时间、阶段、计数、判定归属、主线开关 —— 一律**后台脚本算**。
   （**和 v2.0 §1.2① 不冲突**：那一条说的是"**不要交 JSON／变量块**"，**不等于让模型做判定** —— 判定的活一律归后台。）
   模型只做**低精度、可容错、错了不致命**的活（例：只报「本回合相对过了多久」这种量级；绝对时刻由后台承接）。
2. **冗余**：每个关键状态至少**两条独立通道**，取并集或取最大。**任一条断了，另一条照走。**
3. **自愈**：漏判**不许成为终局**（下一次必须能原样重来）；误判**必须可回退**。

**1.5.3 另配两问（补进 §12 验收之前）**
- **「这个机制里，谁在承压？承压方一旦失手，后果可逆吗？」**
- **「模型写多了／写错了，会不会被当成既成事实写进状态里？」** 会 ⇒ 必须挡：**只接受"当前待判项"，其余忽略并记日志**。

**1.5.4 这一条的由来（实例，别重犯）**
〔仅本卡〕《仙姝墮》主线闸门把 **14 个锚点**列在 `<实际发生>` 里让模型挑 ⇒ 8 楼真机 **7 楼写「无」**；
四段阶段判据又全部来自模型填写的 `known` ⇒ **主线整段停摆**。
我当时的反应是去论证「无」这个答案对不对 —— **纠缠毫无关系的细节**；错的是结构本身。

## 3. 工程规范（卡内脚本）

### 3.1 必须
- 【必须】脚本**只暴露纯入口**（形如 `mount(container, rawMsg, msgId)`），**不赌宿主事件**；事件钩子只作**冗余加速**，拔掉事件后功能仍要能跑。
- 【必须】所有宿主 API 调用都 `typeof` 保护；**加载时绝不抛错**。
- 【必须】DOM 操作走 `window.parent.document`（脚本在 iframe 里）；入口同时发布到 `parent`/`top`。
- 【必须】**唯一写盘出口**：所有写变量都过一个函数，出口里统一过闸门（「只写最新楼」＋判不出来放行）。
- 【必须】加**轻量缓存 ＋ 失效指纹**（以楼层号当指纹即可）。
- 【必须】解析失败**保留旧值**，不写空、不写默认值。

### 3.2 禁止
- 【禁止】把大段 HTML/CSS 塞进正则的 `replaceString`（案例卡塞了 7,467 字，编辑即崩、报错还指向别处）。
- 【禁止】把模型产出的文本**未经转义**拼进 HTML（案例卡有 6 处未转义注入面）。
- 【禁止】内联 `onclick` 里拼未转义的字符串（名字含 `'` 即断 JS）—— 用事件委托。
- 【禁止】写盘绕过出口函数（案例卡的 `setChatVar` 有两处无条件写，绕过了自己的闸门）。
- 【禁止】监听泄漏：开/关灯箱等**必须统一移除**所有监听（案例卡只在按 ESC 时移除）。

### 3.3 铁律（沿革，全部有效 · **编号沿用历史、不是连续编号**）
1. 联网先挂代理 `127.0.0.1:7897`

3. 涉渲染/UI/事件，先读源码再动手
4. 只能 UI 操作的项：脚本启用、世界书条目启停（改盘会被内存回写）
5. 改卡 `extensions` 后要**切卡再切回或重新导入**，Ctrl+F5 不够
6. 审剧透先审「必进上下文的卡字段」
12. 推卡顺序：先复制卡 → 再重建独立世界书 → 最后拨开关（⚠️ 2026-10-01：这三步已由 `_push_card.mjs --apply` **自动执行**；照 §2 第 11 步走即可）

### 8.1 删自解释（判据）
- 逐句问「**模型读到这句会做出什么动作？**」——答不出的，删。
- 典型该删：解释脚本机制的话、强调"这句很重要"的话、"你必须／你只能"的重复强调。

### 8.2 降负担
- **不解释"某某是什么"**，只写「**哪个标签里填什么**」。
- 判据：把关键词（如"状态栏"）出现的句子逐句读一遍，解释机制／用途／重要性的，删或压成指针。

### 8.3 单一真源（防多重打包）
- 同一批纪律**只留一处**；别处一律写成指针：`每个标签里填什么，一律照「状态栏模板」条`。
- 卡字段（`description`／`depth_prompt`）**不得**再抄一遍常驻条的规则。
- ⚠️ **澄清（防误读）**：禁的是「**同一批纪律出现在两处**」，**不是"禁止写在卡字段"** —— 规矩放**卡字段**（如 `depth_prompt`）或放**世界书条**都行（**范例卡放世界书条，本卡卡字段与世界书条各有**），**只许有一处**。

### 8.4 缩水
- **这类规则不要多**；非要放就必须缩水；**没脱过水的别放进去**。
- 脱水后**必须保留重点**，并由**子代理审一次"有没有失真、要补什么"**；子代理自己判错的地方，作者回卡核对后驳回并留证。

### 8.5 注入（〔仅本卡〕口径）
- 〔仅本卡〕本卡**没有"章节"概念**：不照抄"按章节 EJS 注入"的方案。
- 〔仅本卡〕判据用我们的三样：`stat_data.身份` ／ `stat_data.known` 的锚点 ／ `stat_data.地点`。
- ⚠️ **与 §1.5 的冲突（已知、未解，别当成已定案）**：本条这三样判据**全部是模型填写的**（`known` 锚点来自 `<实际发生>`、`地点` 来自状态栏），
  而 §1.5.2 要求「**关键状态不交给模型**」。⇒ **改造前照本条执行**；改造方向是**三腿冗余**（后台时钟／锚点／人手，`阶段 = max(三腿)`），见 `交接说明.md` §十四。**卡未动，等主人点头。**
- 〔仅本卡〕写法照《阶段驱动》骨架：**静默计算层（try 包住，取不到就出安全占位）＋ 逐段互斥输出**，同一时刻只渲染一个分支；失败时只吐占位，绝不整段吐出。

## 9. 角色演绎引擎规范（FNE 吸收版 · 本规范的核心新增）

### 9.1 三层结构（写引擎按这个顺序落笔）
```
① 仲裁层：谁说了算      —— 真实态度天花板 → 角色特异性 → 通用引擎
② 驱动层：她到底要什么  —— 欲望核心（1 主 1 辅）＋ 受挫后的迂回变形
③ 泄露层：表面怎么变化  —— 三阶泄露（微表情 → 语气裂痕 → 行为失控）＋ 回落
```

### 9.2 ★ 泄压口铁律：每条禁令必须配替代管道

| # | 禁令（不要写） | 替代管道（改写成） |
|---|---|---|
| 1 | 用台词复述、确认玩家说过的话 | **物理转译**：身体微动作、空间位移、微表情、环境互动 |
| 2 | 凭空捏造共同回忆套近乎 | **纯粹当下性**：只锚定当下可感官物 ＋ 历史真实记录；未记载＝认知盲区 |
| 3 | 把算计／吃醋／利益盘问**说出口** | **动机潜沉**：只经情绪起伏、生理反应、环境意象泄露；索取包装成要具体物件或荒谬却亲昵的条件 |
| 4 | 用数字与频次统计动作 | **感官痕迹流**：肌肉痉挛、黏膜充血、润滑度、压痕、呼吸顿挫、声响共鸣 |

### 9.3 高维压缩词清单

| 用途 | 压缩词 | 写法要求 |
|---|---|---|
| 关系进度 | **五级温差** | 高戒备 → 观察松动 → 基本信任 → 亲近许可 → 无戒心；＋**升温阻尼**（严禁跳跃升温） |
| 动机 | **欲望核心（1 主 1 辅）** | 安全感索取／自我确认／权力掌控／孤独代偿／生理满足／成就满足 —— **每类必须写"受挫后的迂回变形"** |
| 性格 | **三色旋钮** | 底色性格／反向张力（越克制越剧烈）／特有要素（≥2 类，严禁单一重复小动作） |
| 人设速写 | **神韵灵魂底模 [A × B]** | 两个现成角色的组合灌入气质 |
| 说话方式 | **语言指纹（选 2–3）** | 节奏控制／比喻式情感隔离／语法跳跃／自指非人感／祈使句撒娇／否定式反向引导／小动作先行／以弱控强／迂回引诱 |
| 身体许可 | **逐级许可链** | 视线 → 无意触碰 → 有意轻触 → 拥抱抚脸 → 隔衣 → 解除 → 性器相触 → 本番（＋主动跃级特权，跃级后次轮收敛试探） |

### 9.4 状态机化
- **三阶泄露**：微表情（伪装越用力泄露越明显）→ 语气裂痕（句式碎裂、语速突变）→ 行为失控（反向张力接管）；
- **跳崖与回落**：被精准直触可**瞬间跳三阶**，释放后**回落一阶**；
- **状态 C**：三阶常态化后底色与反向张力**融成第三态**；
- **阻尼冷却**：连续受挫 → 情绪供给骤减、身体许可收紧、语言回到礼貌距离。
