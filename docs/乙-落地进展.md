## 二、为什么 ③ 不能马上 apply（顺序风险）

闸门条件写成 `@@if variables.stat_data.known['X'] === true`：

- **MVU 跑通时** → 条件为假 ⇒ ST-PT 把整条 `splice` 掉，一个字都不进上下文 ✅ 正是我们要的
- **MVU 没跑通时** → 变量不存在 ⇒ 条件**恒假** ⇒ **13 条【剧情】会全部被剔除**，比现在的「停用」还糟（现在至少玩家能手动启用）
- **ST-PT 停用时** → `@@if …` 会**作为纯文本进上下文**（等于把「这里有条隐藏线＋它的条件」告诉 AI）

⇒ 所以顺序铁定是：**先真机确认 MVU 就绪 → 再 apply 闸门**。
（ST-PT 侧已确认无恙：`EjsTemplate.enabled / preload_worldinfo_enabled = true`）

## 三、关键技术发现（本轮读源码得到的，不是推测）

### 3.1 卡内脚本的执行方式

出处：JS-Slash-Runner `src/panel/script/iframe.ts`

```js
<script type="module">
${content.match(/^\s*```[^\n]*\n(.*)\n```\s*$/is)?.[1] ?? content}
</script>
```

推论：
1. 脚本被包进 **`<script type="module">`** ⇒ **支持 `import`**
2. 但**必须用动态 `await import()` 并包 try/catch** —— 静态 `import` 一旦失败（CDN 不通），**整个模块都不执行**，连日志都没有
3. 它跑在 **iframe（about:srcdoc）** 里 ⇒ 脚本里的 `document` 是 **iframe 的 document**
   ⇒ **这彻底坐实了状态栏面板「字段全空」的根因**：面板脚本用 `document.querySelector('.mes[mesid]')` 找消息，
   而 iframe 文档里一条消息都没有 ⇒ 每次填充都静默失败（6.0b 里那句「没查清的那一步」）
4. MVU API（`@types/iframe/exported.mvu.d.ts`）：`getMvuData` / `replaceMvuData` / `parseMessage`，
   并且要 **`await waitGlobalInitialized('Mvu')`** 才算就绪
5. ⚠️ `@types` 里 `VARIABLE_INITIALIZED: 'mag_variable_initiailized'`（**多一个 i，旧拼写**），
   线上 bundle 是 `mag_variable_initialized` ⇒ 卡内脚本**两个都监听**

### 3.2 `@@if` 是「整条剔除」，所以「条内分段」不能靠它

丙 已查实：`@@if` → `<%- !!(参数) %>`，假则**整条 splice**。
⇒ 锚点表里那三条需要**条内分段**的（【人物】玄机子／叶红缨／孤月）**不能**用 `@@if` 实现，两条路：

- **(a) 拆条**：把「点名＋定性段」拆成独立条目挂 `@@if`，可见段留在原条 —— 稳妥（`@@if` 已验证），T1 的拆分法已有先例
- **(b) 正文内 EJS**（`<% if (...) { %> … <% } %>`）：更优雅，但**尚未真机验证**
  （丙 只验证过 `@@if`；`<%` 报错那次只证明它在解析正文，没证明条件可用）

⇒ 本轮 ③ 先只做「整条闸门」13 条，分段那三条**单独一步**做（优先 (a)）。

### 3.3 `[initvar]` 与终检的冲突（已解决）

`[initvar]` 必须 `enabled:false`（样板惯例：靠代码读，不进上下文），但条目名又必须保持 `[initvar]` 前缀
⇒ 它不能带「〔后期·需手动启用〕」标记，而终检脚本原本要求「停用条目必须带标记」。
已给终检加**豁免**：`!e.comment.startsWith('[initvar]')`。
