> 能自动算的部分另配了脚本 `tools/checks/_verify_acceptance.mjs`（见第 4 节），它已经在旧记录上抓出过两个真 bug，不是摆设。

> **验收结论只有两种**：某一条「通过」＝我列的现象全部出现；否则算不通过，按第 6 节报给我。

## 0.5 不想碰「控制台」的走法（**推荐先看这条**）

**先说你截图里那个面板 —— 它就是我说的「看实际发出去的内容」，而且比控制台好用得多：**

> **酒馆助手自带的「提示词查看器」**（标题栏「提示词查看器」，上面写着总 token 数）。它有两个控制台没有的好处：
> ① 直接显示**这一回合真正发给模型的全部内容**；② 顶上有搜索框，**打字就地搜**，不用按 F12、不用找 Console 标签。
> 所以：**凡是本文写「控制台搜 X」的地方，你都可以改成「打开提示词查看器，搜 X」。** 下面讲的「控制台」只是备选。

「控制台」（console）是**浏览器自带**的一个开发者小窗口，不打开它游戏照样玩；之所以提到它，只是因为程序内部的日志写在那里。**你完全可以只用提示词查看器。**

另外卡里现在有一条命令帮你做体检：**在聊天框里发两个字**

```
验收
```

（`/验收`、`体检`、`自检` 都一样。）

发完会发生两件事：

1. 右下角弹一个提示条，直接告诉你 `✅ 体检通过` 或 `❌ 体检有 N 项不过`；
2. 完整体检单（物品数量、后台时点与状态栏时间对不对得上、成形锚点有没有破身证据）**写进了变量**，跟着聊天一起存盘。

然后把**聊天记录文件路径**发我（`E:\tavern\SillyTavern\data\default-user\chats\仙姝堕\…jsonl`），我直接读出来告诉你哪一项不过。

> 所以整份方案里凡是写着「控制台搜 X」的步骤，**你都可以用「发一句 `验收` 再告诉我」代替**；那些搜词是给「能开控制台的人」用的更细的排查手段，不是必须动作。

## 1. 场景一：`@@if` 闸门是不是真在生效（GPT 第一步点名要验的那条）

> **2026-10-07 更新（主人实测「显然没挡住」之后）**：那时的答案不是「`@@if` 坏了」，而是**那 15 条剧情的老闸门只认身份** —— 你玩的就是赵无忧，所以对你的线**永远是开的**，真正决定它进不进的是触发词。
> 现在主线剧情的闸门已经改成 **「正门＝里程碑锚点，兜底＝段位」**：
> **正门**（剧情真到了 ⇒ 立刻放行）＝该段的里程碑锚点为真，锚点逐段取自卡内既有的 `STAGE_FAST_FORWARD` 表；
> **兜底**（模型一直不报里程碑 ⇒ 也不至于卡死）＝段位到点。
> 本场景的判定因此变成「**正门没开、段位也没到，就该搜不到**」。

**目的**：确认「条件为假 ⇒ 条目内容真的没进请求」。

**操作**

1. 新开局，随便走 2~3 楼（还在墨山道，**段位是 1**）。
2. 在聊天框输入并发送：

   ```
   我把师姐胸口的乳环记在了心里，念了一句「封元镇灵环」。
   ```

   （这句话故意把两个触发词塞进去：`乳环` 与 `封元镇灵环`。）
3. 打开**提示词查看器**（酒馆助手的那个面板），搜索 **`葬魔渊绝壁`**，再搜 **`朱樱逢劫`**。

**期望**

- 搜不到「葬魔渊绝壁」那一段（那是【剧情】十二 的 3612 字原文照录）—— 因为【剧情】十二 现在的闸门是「身份＝赵无忧」**且**（第 12 段里程碑锚点已真 **或** 段位 ≥ 12），而你现在两者都没到。
- 【物品】封元镇灵环 那一条**也不该**出现（它的闸门是 `赵无忧看见乳环`，这句台词不算看见）。

**判定**

| 现象 | 结论 |
| :--- | :--- |
| 两条都搜不到 | ✅ 闸门生效 |
| 搜得到剧情十二 的正文 | ❌ 报我（并附提示词查看器的截图，截到他搜出来的那一段） |

**顺带验一下「正门」是活的**：让剧情真的走到某一步并让状态栏记下对应锚点（例如 `/解锁 进入幽寂谷`），再看提示词查看器 —— 那一段应当**立刻**出现（不必等段位爬到第 3 段）。这条验的就是「段位只兜底、里程碑才是门」。

> 参考：ST-Prompt-Template 的文档提过 `window.TavernHelper.Context.getAllActivatedPrompt()` 能直接列激活条目，但那个 PR 还在审核、**暂时无效**。

## 2. 场景二：阶段驱动与「时钟照抄」（治时间线卡死）

**目的**：确认模型有一条能照抄的当前时点，且**只渲染当前那一段**。

**操作**

1. 同一局里连发 **15 次**：

   ```
   推进剧情
   ```

   （这四个字不含任何触发词，正好顺带验「主线不靠撞词也能往前走」。）
2. 控制台搜 **`后台当前时点`**；再搜 **`阶段二 ·`**、**`阶段三 ·`**、**`阶段四 ·`**。（不想开控制台：这一步跳过，改发 `验收` —— 它会告诉你「后台时点」与状态栏的 `<时间>` 对不对得上。）
3. 每 5 楼看一眼 HUD 的 `<时间>`，和后台那行对不对得上。

**期望**

- 控制台里能看到形如：

  ```
  ## 后台当前时点（`<时间>` 一栏照抄这一行，严禁自行推算年月）
  - 仙盟历：仙盟历 1578 年 · 四月
  - 段位：第 2 段（全书共 16 细分段位，本条目已按它只渲染当段）
  ```

- **同一时刻只有一个阶段标题**（搜到「阶段二 ·」就不该搜到「阶段三 ·」）。
- HUD 的 `<时间>` 那一栏，年与月跟后台那行**一致**（写三月/四月都行，但不能长期停在同一个月份不动）。

**判定**

| 现象 | 结论 |
| :--- | :--- |
| 后台时点出现、单段渲染、HUD 跟着变 | ✅ 通过 |
| 搜到两段以上阶段标题 | ❌ EJS 没渲染（模板没被处理）→ 报我 |
| 后台时点有，但 HUD 连续 10 楼都写同一个月份 | ❌ 模型没照抄 → 报我（这条正是旧版的老毛病） |
| 连发「推进剧情」15 次后段位完全没动 | ❌ 段位驱动没生效 → 报我 |

## 3. 场景三：两壶酒喝一壶（数量）＋ 命令实测

**目的**：主人最初报的那个问题，逐条落地。

**操作**

1. 新开局，发：

   ```
   /物品
   ```

   **期望**：控制台出现 `【纳戒物品清单】共 2 种：`，其中 `醉春风 ×2`。
2. 发一句自然语言，逼模型报消耗：

   ```
   我取出一坛醉春风，与师姐对饮。
   ```

   **期望（控制台）**：`[纳戒] 第 N 楼消耗「醉春风」×1（剩 1）`。
   再看 HUD 物品栏：`【醉春风】 ×1`（**还在**，不是消失）。
3. 再发一次同样的话。
   **期望**：`[纳戒] 第 N 楼消耗「醉春风」×1（已用尽，移出纳戒）`，HUD 里「醉春风」不见了。
4. 现在实测命令（GPT 点名要验「命令是否被酒馆原生截走」）：
   发 `/消耗物品 墨山道佩剑`。
   **期望**：弹出提示 `已消耗「墨山道佩剑」×1，已用尽并移出纳戒`，且这条消息**没有被模型当成剧情**（若它被当成对话发出去了，说明酒馆原生把 `/` 截走了 → 报我）。
5. 发 `/获得物品 凤血灵芝 3 幽寂谷所采`。
   **期望**：HUD 出现 `【凤血灵芝】 ×3`。

**判定**：第 1~5 步现象全部出现 = ✅；任何一步的数量不对（比如一坛就把两坛都扣光）= ❌ 报我。

## 4. 场景四：重生成／切换回复不重复累计

**目的**：GPT 那条「切换回复和回退时的正确性」。

**操作**

1. 在刚刚那层（消耗过醉春风的那一楼）触发**重生成**（点「重新生成」）。
2. 等新正文出来，再看 HUD 物品栏与控制台。
3. 再用楼层左右的 **◀ ▶** 切一次回复（swipe），切回原来那条。
4. 再看一次物品栏。

**期望**

- 控制台出现 `[纳戒] 第 N 楼内容变了 ⇒ 先回滚旧账（消耗 1 项／获得 0 项）再重算`，或者 `[纳戒] 第 N 楼这一栏与上次一致 ⇒ 不重复入账（幂等）`。
- **物品数量不会往下掉两次**：不该出现「喝一次酒，数量从 2 变 0」。
- 反复切回复，物品栏数字稳定（同内容 ⇒ 同结果）。

**判定**：数量稳定 = ✅；每切一次就再扣一次 = ❌ 报我。

## 5. 场景五：提前提到后段道具不串章 ＋ 口交不再误判成形（两条回归）

**目的**：这次改的两处老毛病，别改回去。

**5.1 提前提后段道具**

- 操作：新开局，发一句把后段专名塞进正文的话，例如：
  ```
   我听说葬魔渊底下有阵法传承，孤月师姐要去中洲取一样东西。
  ```
- 期望：模型接得上话，但**不应**把第十四章、第二十几章的原文照录演出来（不出现撕衣、探指尝露、漱玉阁这些桥段）；控制台里 `剧情十二` 那一段不该出现在实际提示词里（同场景一的搜法）。
- 判定：出现了后段桥段 = ❌ 报我（说明挡板漏了）。

**5.2 口交不再误判成形（这次修的核心）**

- 操作：正常跑到剧情二（幽寂谷解毒那一段），或在任何亲密场景里让模型自行推进；**控制台搜索 `⛔`**（不想开控制台就发 `验收`，它会逐条列出「已成形的名器有没有破身证据」）。
- 期望：
  - 若模型在没破身的情况下报了 `九幽玄阴穴成形`，控制台出现：
    ```
    ⛔ [成形闸门] 第 N 楼丢弃「九幽玄阴穴成形」：破处簿与「孤月／…处女丧失」都没记，本回合正文里也查不到落在这几人身上的破身实证。要手工补，发「/解锁 九幽玄阴穴成形」。
    ```
    并且 HUD 里那件名器**保持未亮**。
  - 若确实破了身，控制台出现 `↳ 派生：孤月处女丧失 ⇒ 「九幽玄阴穴成形」`，HUD 名器亮起。
- 判定：没破身就亮起来 = ❌ 报我。**这一条可以只做被动观察**：整局只要没出现过「没破身就亮」的现象就算通过。

## 6. 自动核对（能算的部分，别用眼睛看）

改完之后跑这一条命令，它读聊天记录逐楼对账：

```powershell
& "C:\Program Files\nodejs\node.exe" E:\角色卡制作\仙姝堕\tools\checks\_verify_acceptance.mjs
```

不给参数就自动取 `chats\仙姝堕\` 里最新的那条；也可以把路径写在后面。它核五件事：

| 标签 | 核什么 | 怎么算出来的 |
| :--- | :--- | :--- |
| A 物品账 | 数量不许 ≤1 之外的怪值、同 id 不许两条、**每楼的增减必须等于该楼账本**（抓重复入账与漏回滚） | 酒馆把每层楼的变量快照写进了聊天 jsonl（`<行>.variables["0"].stat_data`），逐楼差分即可 |
| B 时钟照抄 | 状态栏 `<时间>` 是否照抄后台 `仙盟历文`（阈值 90%） | 同上，比较两个字段里的年与月 |
| C 思维块 | 统计原文里带 `<think…>` 的楼 | ⚠️ jsonl 存的是**原文**，正则只在发送内容里生效 ⇒ 这条只能看控制台 |
| D 成形抢跑 | `X成形` 翻真的那一楼必须同时有 `破处者[X]` 或 `X处女丧失` | 同上，逐楼看 `known` 与 `破处者` |
| E 状态栏质量 | 字段齐缺、关系刻度假数值、在场子块是否用了旧字段 `<阶段>` | 直接扫正文 |

**它已经在旧记录上验过自己**（`仙姝堕 - 2026-10-06@16h16m49s.jsonl`，84 楼）：

- ✔ A 物品账无异常（只有《极乐引》残篇那次正当入账）
- ✘ B 照抄率 **7%**（后台「1578 年 · 四月」，状态栏写「三月」，共 38 处不一致）← 正是这次要治的病
- ✘ D 第 5 楼「九幽玄阴穴成形」翻真却**没有任何破身证据** ← 正是「口交就成形」那个 bug
- ✔ E 状态栏字段齐全、无假数值、无旧字段

**新卡跑出来的结果应当是 A/B/D/E 全绿**；B 若仍低，说明模型没照抄，把不一致的前几条贴给我。

## 8. 不通过时怎么报我（最小信息量）

1. **聊天记录文件的完整路径**（`E:\tavern\SillyTavern\data\default-user\chats\仙姝堕\…jsonl`）；
2. **出问题那一楼是第几楼**（HUD 上能看到楼层号）；
3. **控制台里那几行原样复制**（带 `[纳戒]`／`⛔`／`🧹`／`✅ [实际发生]` 这些前缀的）；
   **懒得开控制台就免了** —— 只要在问题出现后发一句 `验收`，把聊天文件路径给我，我自己读体检单；
4. 若是数量问题，附 **HUD 物品栏截图**；
5. 若是照抄问题，附 **后台那行「仙盟历…」＋ HUD 的 `<时间>`** 两行文字。

有这几样，我基本不用再问就能定位。
**最省事的组合是：跑完 → 发一句 `验收` → 把聊天文件路径丢给我。**

## 9. 已知边界（验收时别当成 bug）

1. **账本按楼层号记账**：删掉**中间**某楼会让后面的楼层号前移，那一笔归属可能错位；当前只覆盖「该楼变空」与「同楼内容变化」两种情形，兜底是 `/获得物品`、`/消耗物品` 手动纠正。
2. **数量是整数、不做单位换算**：「一坛」和「一壶」都算 1 件。
3. **`count` 为 1 时 HUD 不显示 `×N`**，与旧界面一致。
4. **思维块在 jsonl 里永远能看到**（存的是原文），只有「发送内容」被正则清掉 —— 别拿 jsonl 判断正则有没有生效。
5. 旧存档会被一次性迁移（物品补 `id` 与数量，「醉春风」按设计的「两坛」记 2），控制台会打 `[初始化·…] 纳戒老数据迁移：…`。

| 名词 | 人话 |
| :--- | :--- |
| **控制台 / console** | 浏览器自带的开发者窗口，给程序员看程序内部消息用的。**不打开，游戏照玩**。 |
| 怎么打开它 | 在酒馆那个浏览器标签页上按 **F12**（或右键页面 → 检查），再点上方标签里的 **Console**。关掉它不影响酒馆。刷新页面后里面的旧日志会清空。 |
| 在里面怎么搜 | 控制台里按 **Ctrl + F** 会出来一个搜索框，把要搜的字打进去就行。 |
| **toast / 弹窗** | 屏幕右下角那个会自动消失的小提示条。发 `验收` 之后弹的就是它。 |
| **变量 / 变量层** | 卡在后台记东西的地方（段位、物品、谁破了谁的身）。它跟着聊天一起存盘，所以我能从聊天文件里读出来。 |
| **世界书条目** | 卡里一段段会按条件塞给模型的资料；**闸门**就是它的开关条件。 |
| **触发词** | 唤醒某个条目的词。玩家或 AI 的话里出现它，那一段资料就会被塞给模型。 |
| **`验收报告`** | 发 `验收` 之后写进变量的那份体检单，我需要它来定位问题。 |
