## 1. 机制总览与数据流

一句话：**模型写状态栏 → 脚本记账进变量 → 下一回合的闸门读这些变量决定「哪些条目进提示词」**。

```
第 N 楼（模型输出）
  └─ <Status_block> 19 个展示字段 ＋ 隐藏栏 <实际发生>/<进度>/<破处>/<纳戒>
        │
        │ 状态机（酒馆助手 script iframe）
        ├─ applyStatusToVars()   ← 解析状态栏
        │    ├─ ① 展示字段直接覆盖写      → stat_data.{时间,地点,在场,…}
        │    ├─ ①c 段位／仙盟历（见 §2）  → stat_data.{段位,仙盟历,仙盟历文,窗口起点,时点加速}
        │    ├─ ③ 进度一致性校验（只告警）
        │    ├─ ④ applyMilestones()：<实际发生> → 过滤（必须在 109 项台账内）→ known[X]=true
        │    │     ＋ <破处> → 破处簿/名器归属；＋ <纳戒> → inventory ＋ 纳戒账本
        │    └─ ⑤ 通知 HUD 面板刷新
        │
第 N+1 楼（组装提示词）
  ├─ ST 世界书扫描：keys 命中 ＋ scanDepth=6 ＋ constant ⇒ 「选中」条目集合
  ├─ ST-Prompt-Template：对每个被选中条目的@@if求值 ⇒ false 的整条排除
  ├─ ST-Prompt-Template：对留下的条目跑 EJS ⇒ 【阶段驱动】只吐当前段
  └─ 最终 payload → 模型
```

**三道门（按发生顺序）**：

| # | 门 | 谁在管 | 决定什么 |
| :--- | :--- | :--- | :--- |
| ① | 触发词（`keys`） | 酒馆世界书引擎 | 这条「要不要读」 |
| ② | `@@if` 闸门 | ST-Prompt-Template | 读到了「给不给」 |
| ③ | EJS 分段 | ST-Prompt-Template | 给了之后「给哪一段」 |

## 2. 段位是怎么算的（**这是保底量，不是门**）

### 2.1 两张表（原样，来源：`卡片脚本/状态机.js`）

```js
const STAGE_STEPS = [30, 20, 25, 20, 15, 20, 30, 20, 25, 20, 20, 20, 30, 30, 35, 999];
const STAGE_BASE  = [1, 31, 51, 76, 96, 111, 131, 161, 181, 206, 226, 246, 266, 296, 326, 361];
const SEG_TIME    = [1578.03, 1578.04, 1578.06, 1578.08, 1578.11, 1578.11, 1578.12, 1579.01,
                     1579.01, 1579.02, 1579.03, 1579.04, 1579.04, 1579.05, 1579.06, 1580.01];
```

⇒ 段 N 覆盖楼层 `[STAGE_BASE[N-1], STAGE_BASE[N-1] + STAGE_STEPS[N-1])`：
段 1＝1–30、段 2＝31–50、段 3＝51–75、段 4＝76–95、段 5＝96–110、段 6＝111–130、段 7＝131–160、
段 8＝161–180、段 9＝181–205、段 10＝206–225、段 11＝226–245、段 12＝246–265、段 13＝266–295、
段 14＝296–325、段 15＝326–360、段 16＝361 起（`999` 是尾巴）。`SEG_TIME` 是每段的仙盟历时点。

### 2.2 楼层 → 段位（源码，逐行）

```js
function stageOfFloor(floor, shift) {
  const f = Number(floor) + (Number(shift) || 0);
  if (!isFinite(f) || f < 1) return 0;                 // 取不到 ⇒ 0（渲染侧按第 1 段兜底）
  for (let i = 0; i < STAGE_STEPS.length; i++)
    if (f < STAGE_BASE[i] + STAGE_STEPS[i]) return i + 1;
  return STAGE_STEPS.length;
}
```

要点（**我的判断**，请复核）：
1. `段位` 与 `want` 分离 ⇒ 实际写入的 `段位` 是**带节流的**（一次只前进一段、每段至少 3 楼、亲密场景暂缓）。
2. `stageOfFloor` 单调（同 `shift` 下楼层越大段位不降）；`段位` 也**只增不减**（`cur = max(1, 旧段位)` 起步）。
3. 取不到时 `stageOfFloor` 返回 0、`XSD` 渲染侧另有兜底（见 §6.1），不会因此把书锁死。
