# 奥克赫斯 0.2.0 · R4 配套整合包

## 安装

1. 在酒馆导入 `奥克赫斯_R4配套.json`，首次安装建议为这张卡新开一个聊天。
2. 在酒馆助手的脚本环境中载入 `okh_complete_R4_card_autostart.js`，并启用。它包含完整后台和自动启动代码，不需要再粘贴第二份启动脚本。
3. 不要同时启用旧核心、旧应用合订本、上一份完整脚本或本包的普通运行版；只保留一份完整后台。
4. 启动成功后，控制台会显示 `[奥克赫斯] 监听已启动`。可在同一个脚本上下文执行 `await OKH_CARD_READY` 检查启动结果，执行 `OKH_APP.info()` 查看存储和聊天信息。

角色卡 JSON 本身不执行 JavaScript。这里明确采用“角色卡 + 一份后台脚本”的加载方式，没有在 JSON 中伪造未验证的插件脚本字段。

若已使用自己的启动配置，可继续载入 `runtime/tavern_scripts/okh_complete.js`，在同一上下文执行 `await OKH_APP.start()`；此时不要再启用自动启动版。

## 开局与存档

- 新聊天从第 1 天 18:00 的荒原途中开始，随队角色为古兰、伊丝娜、妮丝、奥萝拉。
- 爱德尚未获救入队；艾琳在山庄，塞西莉亚在教堂。
- 已救助并接纳爱德后申报 `ed_joined`；实际抵镇后申报 `arrived_oakhaven`。不会按天数自动完成里程碑。
- 自动启动不会强制重置旧存档。第一次加载且聊天只有首条消息时会登记该消息；重复加载不会重复推进首条消息。
- 新卡的初始资料不应覆盖正在继续的旧聊天状态。不要通过强制初始化来迁移旧剧情。

## 世界书

卡内已嵌入 11 条基础世界书，导入卡时一并带入，无需重复导入另一份基础书。包含世界背景、前传连续性、玩家、七名角色和地点语义。

原始的完整外部世界书未随文件提供，已检查的工作区与仓库中也未找到该项目的正式条目。因此本包没有补造专属剧情、艾琳完整身份等未知内容。之后可合并原始正式档案；不要把基础条目当作完整剧情库。

运行时台账与待决事件由后台直接注入。若原来启用了读取 `pendingText/ledger` 的旧世界书条目，请关闭那些重复注入条目，普通人物和世界设定条目可以保留。

## 本轮修改

- 统一前传开局与 R4 的初始坐标、时间、入队状态。
- 补齐七名角色 ID、八个地点、活动取消、解除规则、前传里程碑、互动事实、待决事件应答与时间语义。
- 移除“位置立即更新”的旧说明；默认在本轮终点生效。
- 补充示例回复，玩家的重大选择不由叙事代替。
- 更新脚本加载说明，提供包含自动启动代码的完整脚本。
- 在应用适配器的台账中列出待决事件真实 ID、目标和登记选项，避免让模型猜 `event_resolve` 属性；结案后该条从待决清单消失。
- 沿用已修复的 R4 核心，事件条件和数值规则没有改变。

## 本地源码合并

`runtime/奥森德/src/` 提供需要合并的四个源码文件：R4 的三个核心模块，以及本轮补充事件清单的 `app/okh_app_adapter.js`。

如果已合并上轮 R4，只需合并应用适配器后，用原工程的构建命令重建。其余应用源码没有改动。

## 验证

解压后，在当前目录运行：

```sh
node --test test_card.cjs
node runtime/奥森德/scripts/test_foundation.cjs
node --test runtime/review-regressions.cjs
```

结果分别为 6/6、10/10、8/8。覆盖卡格式与世界书、角色地点清单、真实首条消息、示例回复、待决事件清单和旧记录、自动启动与重复启动，以及既有核心回归。

测试在 Node VM 沙盒完成，真实酒馆的脚本接口和世界书导入效果仍需安装后检查。自动启动失败会在控制台明确报错，不会静默切换为测试内存存档。
