# 整套脚本自检 · 2026-11-20

本轮覆盖 `奥森德/src` 的 22 个模块（9 个核心、13 个应用），检查存档、解析、计时、事件、阶段节点、互动与经济、生成监听、历史回滚、迁移及 HUD 接入。登记数据包含 7 名角色、15 个日常行动、18 个阶段节点与 98 个事件；角色、地点、静态数值效果和物品引用契约检查通过。

## 已修复的问题

| 类别 | 复现与影响 | 当前处理 |
| --- | --- | --- |
| 排队操作跨聊天 | `step`、回复回调、生成前回调等进入串行队列后切换聊天，原实现会在执行时重新取聊天 ID，把旧操作应用于新聊天；异步提示注入期间切换也会留下失效请求 | 在调用入口捕获会话，执行前和异步注入后校验归属，失效操作终止 |
| 生成准备与取消 | 注入失败后残留 prepared 记录；切换聊天后清理旧准备会报错；冷重载残留准备累积；空聊天首轮目标错误；重生成可能提前撤销原有效进度，相同回复又可能无法释放准备 | 失败时释放准备，切走时保留旧聊天存档、回到该聊天后清理遗留请求；修正空首轮匹配。正常最新楼重生成基于原检查点生成提示，原有效进度保留到新回复成功提交；取消保持原回复状态与历史 |
| 存档版本倒退 | 取消生成曾直接写回旧快照，版本号回退，破坏乐观并发校验 | 取消仅删除准备记录，提交版本递增；持久化边界拒绝非递增版本 |
| 回复替换与历史重放 | 替换旧回复先持久化回滚，再解析或保存新回复；后一步失败会丢失原成功状态。多楼重放也可能只提交前半段 | 单楼替换和状态、历史检查点同步提交；多楼重放先在内存中完整校验再一次提交。内存检查点也按配置窗口裁剪。解析、业务校验或拒绝写入时保留原存档 |
| 超出回滚窗口的修改 | 修改被裁掉检查点的旧楼后，原实现可能从剩余窗口开头局部重放，保留被修改旧楼的过时效果 | 校验最早可用检查点之前的聊天锚点；超出窗口时明确报错，保留当前存档 |
| 迁移登记错误 | 重复事件实例 ID 被当成事件定义键，迁移后出现两个待决记录；补齐缺失的爱德条目时可能提前把未加入者设为登场 | 按稳定事件定义键恢复实例，并保留 occurrence / instanceId；补齐角色时服从既有加入标记 |
| 角色资格与旧选项 | 已死亡或未登场角色仍能结算赠礼、佣金协助；继承的 Object 方法会被误作互动种类；角色不可交互后旧待决选项仍残留 | 检查存活、登场与显式登记的互动种类；失去交互资格时撤下待决选项，保留 `allowInactive` 显式例外 |
| 满仓补给收费 | 补给接近或达到 999 上限时仍按完整申请数量扣钱，超出部分被截掉；同一回执连续购买进一步放大问题 | 按剩余容量计算实际入库数量和金额，同批购买共享剩余容量 |
