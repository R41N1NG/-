# v1.4.0：玩家小面板、完成记录与数值行为

【身份：gpt｜日期：2026-10-08｜类型：使用与字段说明】

## 输入栏小面板

启用剧本会开启输入栏小面板，顶部显示当前阶段、状态、🎒、⚙️与收起/展开按钮。展开区域主要展示当前可选行动；点击仍只填入草稿，玩家发送后才记录选择并更新同轮注入。折叠状态会保存，折叠不会撤销待发送选择或修改输入文字。

⚙️收纳“确认阶段完成”“核验本轮”“暂停/继续”与后台入口。没有出口的阶段仍显示小面板，玩家可以确认终点完成；暂停后保留继续入口。完成判定待确认、语义不确定的行为结果会给⚙️加提示点；行为待确认项可直接在此接受或忽略，不必打开管理面板。核验本轮检查当前选中回复的阶段与本轮行为；已结算来源不会重复奖励。

小面板进入输入区布局，为输入区保留高度。普通纵向布局由布局自动缩小聊天区；固定定位宿主若与聊天区重叠，会临时限制聊天区高度，并计入内边距和边框。关闭面板、隐藏输入区或卸载时恢复原样。铅笔入口避开小面板按钮。输入区重建时清理复制出来的插件容器，保持一个实例。云环境覆盖普通布局及固定输入区；真实主题、扩展组合与手机软键盘仍需设备验收。

## 🎒与完成关系

🎒直接读取当前聊天的 `collected_ids` 和项目结果定义，不建立另一份游戏进度。只显示实际获得的物品、线索、资格等结果；进入阶段或仅满足解锁条件不会自动取得结果。

```json
{"id":"b1","title":"房卡","description":"在储物间找到的房卡，上面写着301。"}
```

例如完成N2的 `effects:[{"collect":"b1"}]` 后，🎒出现“房卡（b1）”；点击展开说明和取得来源。新来源从已有结算账本读取，旧进度缺少来源时如实显示“旧进度或导入记录”。结果说明可在“数据 → 结果与🎒说明”编辑，或从关系图结果详情跳转。新建结果可填写短代码，留空自动分配b1/b2；仍需配置获取来源。模型分析只接受原文连续摘录作为公开说明，不自动推断未写明的房号或隐藏用途。

“记录 → 完成与解锁关系”增加“完成记录”，并列显示已完成阶段、完成时间/标准/可用证据，以及已获得内容、说明和来源。保留完成阶段→获得结果→解锁阶段的箭头，整个关系页仍有独立🔒、模糊与确认。进度刷新、普通撤销与依赖回退同步更新🎒和后台记录；旧已获得结果未填写说明时不编造说明。

## 数值载体

“数据 → 数值载体”可创建、编辑数值名称、归属/对象、初始值、总上下限；显示当前聊天值及最近12条实际变化和来源。归属为通用文本，可用于玩家、角色、组织或全局。它不自动绑定其他角色卡状态栏。更改初始值不会覆盖已存在的当前值，旧当前值不符合新范围时拒绝保存。

```json
{"id":"V1","title":"关系值","owner":"同行者","type":"number","default":0,"min":0,"max":100}
```

数值存在聊天进度的 `variables.V1`，事件和阶段效果直接更新它。事件包条件仍使用 `{"variable":{"id":"V1","op":"gte","value":40}}`。其他数值例如警戒、经验、资源使用同一机制；好感度仅是例子。已有外部聊天变量映射仍是只读同步，不写回角色卡或MVU。

## 可重复行为与奖励限制

独立行为事件与一次性阶段事件分开。独立行为可选择“每轮实际发生可重复，同一回复一次”，勾选证据通过后自动应用变化。API页的“生成结束后自动核验独立行为事件”默认开启；没有符合条件的候选或未配置API时不发请求。保留原“用户接话后自动检查”选项。旧事件的奖励、重复策略与自动结算开关不被升级强改。

辅助模型只判断实际发生并引用本轮玩家输入与选中AI正文，本地脚本决定奖励。completed必须有本轮AI的原文证据，只有玩家意图不能自动奖励。缺少证据/主体不符等降为不确定，玩家可在⚙️确认或忽略。用户接话、手动核验、重试和刷新共用来源回执；对同一AI消息换指纹或手动确认不会再次加分。编辑已结算来源仍按原规则暂停，正常回退可撤销后重新核验。

```json
{
  "id":"E1","title":"赠礼被接受","description":"实际交付并被接受",
  "repeat_policy":"once_per_accepted_turn","auto_settle":true,
  "effects":[{"add":{"variable":"V1","value":4,"max":70}}]
}
```

变量的 `min/max` 是载体总范围；效果中 `add/set` 的 `min/max` 是该行为的奖励边界，向上最多加到max，向下最低减到min。例如总上限100、赠礼奖励+4且max70：当前69实际+1到70；当前70或80此行为不增加，也不会把80降低到70。其他行为仍可增加到总上限100。支持负数和set，奖励限制可在事件“发生后的变化”表单填写；数值前置条件另在高级条件生成器设置。

重复行为如果所有配置奖励都没有可用变化且没有新的可取得结果，不进入API候选。筛选与结算分别检查条件，多个事件同批到达边界时也不越界；结算时前置条件已变化的结果记录为未应用奖励。结算账本保存实际before→after，有限奖励记录影响限值的实际数值来源，选择性回退这些来源时也撤销其受影响的结算。

“用可重复送礼示例创建规则”创建可改名、可改归属的数值载体，以及每轮+4、该行为最多加到70的规则；不再顺带创建永久FLOWER_ACCEPTED。删除事件不会删除通用数值载体。

## 短编号与兼容

手动新建节点、行为事件和事件包使用N1、E1、P1等短号；新分析/整理节点使用N1/N2，绑定阶段事件使用E1/E2。分配器检查已有编号并保留分配计数，避免复用已预留短号。项目、修订和结算事务的内部标识保持原机制。

已有节点、事件、包和结果ID不重写，避免断开条件或旧进度。关系图对旧长节点/事件/包编号使用短展示别名，详情仍保留真实内部ID。图中优先显示名称，下一行显示短号；展示别名不是可替换原条件的真实ID。

## 结果删除与遗留定义

在解锁后的关系图点击结果，再点“删除结果”，先预览引用此结果的节点入口、出口、行为条件、事件包触发/持续条件、结果前提/互斥和获取效果。可以跳转修改每个关联内容，然后返回处理。

确认删除时有三种方式：

1. 默认禁止所列关联入口，保留正文供后续编辑；不会自动开放依赖它的内容。
2. 用另一个已定义结果替换条件；获取旧结果的效果会移除，不自动获得替代结果。
3. 明确移除相关条件项；会改变解锁逻辑，可能提前解锁，最后确认会再次说明。

已取得或被结算来源依赖的结果先要求备份、回退相关结果；旧基线来源不明时需恢复合适备份。删除定义与撤销游戏结算分别操作。确认取消保持定义和引用不变。删除完成立即刷新关系图、诊断和旧错误提示；被禁止入口造成的其他不可达依赖仍需作者修改，不伪装成已解决。

删除事件时预览并清理其输出中未取得、无其他来源或引用的结果，保留数值载体。有其他引用的结果继续保留，仍缺来源时在图中按上述方式处理。已有事件结算或其他条件引用会阻止直接删除，避免破坏历史来源。不要把遗留定义标为external来伪造获取来源。

## 分析提示词与真实请求

“分析 → 查看与修改分析提示词”直接显示可编辑的分析与跨段合并system文本，与API页共用同一设置。恢复默认先填入文本，保存后生效；保存一处会清除另一处的旧提示词草稿，其他未保存字段保留。

发送前预览使用已保存的提示词与当前原文/要求，分块实际数据在发起请求后查看。最近一次整理或分析按请求保留实际system/user消息，包括分块与合并；校验失败也保留已发消息和收到的正文。没有真正发起的无效配置不会记作已发请求。请求消息总保留上限200万字符，超过时明确标记展示不完整；记录不包含请求头、API配置或密钥。自定义提示词保持原样，输出仍需符合JSON结构与证据校验。


## v1.5.1：输入栏布局修复

选项栏放在输入表单前独立占位，不再向宿主输入区域追加padding，避免反复开启/关闭累计高度。固定或绝对定位的输入栏单独对齐浮层；普通布局由页面自然分配高度。当前阶段和行动区不随子菜单滚动，🎒/⚙️内容单独滚动。主动收起行动后打开菜单会临时显示行动，关闭菜单恢复原折叠设置。

更新前备份、停用旧实例，导入v1.5.1后刷新页面，清除旧版残留的内联样式。测试包含桌面/390/320px、两种输入布局各20次开关、缩小窗口、宿主更换输入表单及卸载还原；没有改剧情、条件或奖励流程。
