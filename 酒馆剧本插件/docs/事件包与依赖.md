# 条件事件包、交叉推进与完成关系（更新至v1.4.1）

【身份：gpt｜日期：2026-10-07｜类型：实现说明】

本版继续使用原有节点、数值变量和紧凑结果 ID，新增 `packages` 剧情事件包。原来的 `events` 仍是“确认送花 → 好感度增加”等行为识别规则，两者可以一起使用。旧剧本没有事件包时按原流程运行，不会被自动改写。

v1.4.1长文条件分析见[长文条件分析](长文条件分析.md)。v1.4.0玩家面板、🎒完成记录、数值载体、行为奖励边界及确认删除见[玩家面板与数值事件](玩家面板与数值事件.md)。

## 从界面开始

1. 在“数据 → 变量与收集项”定义变量和结果，例如 `trust`、`b2`、`c1`、`a4`、`d1`。结果有固定含义，`a`、`a1`、`ab` 必须完整相等，不按前缀或拼接推导。
2. 在“剧本 → 剧情节点”编辑阶段、完成标准、预设效果与出口。节点的 `entry_condition` 控制能否进入；出口只连接同一事件包内的节点。
3. 在“剧本 → 剧情事件包”确认解锁，添加事件包，选择包内节点、起点与终点，配置触发条件、优先级和持续条件。数值条件可通过表单生成；复杂条件可编辑 JSON。“打开交叉依赖示例”创建完整的测试项目，保留原项目草稿或世界书。
4. 在“记录 → 完成与解锁关系”独立确认解锁，查看箭头、前提、结果与完成状态。该锁与运行区、剧本编辑区分别有效；取消/Escape 继续隐藏，重新上锁、刷新、换聊天或新项目后隐藏。锁定内容不可聚焦，对屏幕阅读器隐藏，操作处理器也会拒绝图内操作。
5. 启用剧本，输入栏显示包内行动和其他可继续的事件包。点击仅填入草稿，发送后才记录选择和更新同轮注入。自主输入从当前候选识别，歧义保持当前阶段。回复生成结束后核验实际完成，按本地预设效果结算，再更新选项。

## 分析结果转化为剧本、事件和分支

分析或恢复草稿后，顶部显示“转化为剧本、事件与分支”，核对后点击。转化无需API请求，保留nodes/routes/packages/collections及原条件，打开“剧本→剧情节点”；新项目先关闭注入。已保存草稿刷新仍可转化，旧剧本与进度保留。

非补充构想且有明确完成标准的节点，会生成绑定事件`completion_node_id`，只适用对应节点，`repeat_policy:once`、`effects:[]`。完成标准与排除项由节点维护，奖励仍只在节点。阶段完成同时增加对应事件计数；事件人工确认也走同一节点回执，只结算一次。没有标准的节点仍需作者编辑，不推测规则。

“事件”页可查看共享规则、打开对应节点编辑和查看记录，也可新建独立行为事件。关系图显示阶段→完成事件箭头；阶段与事件在普通撤销、实际依赖回退时一起恢复。绑定事件不能复制节点奖励、重复绑定或改为每轮奖励。需要删除对应节点前，先解除其事件及其他条件/出口引用，已有进度仍可能阻止删除。

## 事件包的数据

```json
{
  "id": "verify_case",
  "title": "档案核验",
  "node_ids": ["A_1", "A_2"],
  "start_node_id": "A_1",
  "completion_node_ids": ["A_2"],
  "condition": {"all": [{"collected": "b2"}, {"collected": "c1"}]},
  "continue_condition": true,
  "priority": 20,
  "role": "main",
  "enabled": true,
  "auto_start": true,
  "interrupt": false
}
```

`condition` 只控制首次解锁；启动后即使数值回落，仍可继续。需要途中暂停时，配置 `continue_condition`。`enabled:false` 关闭该包；`auto_start:false` 只等待玩家选择。`interrupt:true` 允许可用的更高优先级包打断当前主包；否则当前包继续，待完成或等待条件时再按优先级安排。相同优先级按定义顺序。被打断的包保留游标和短摘要，选择回来即可继续。显式“返回主线”会保持主线，直到另作选择或更高优先级打断。

每节点只属于一个包。跨包出口禁止直接跳转，使用结果条件和事件包选择连接。包运行到终点并实际完成终点节点才算结束；到达终点不代表完成。

每轮最多注入一个主要阶段和一个 `role:side` 的可用支线阶段。支线默认不参与主要安排，只有本轮正文实际涉及其标准才应判定推进。作者用持续条件限制支线适用时机；不用并行支线时全部设为 `main`。辅助核验逐个阶段进行，主包和支线可能分别产生一次请求。不会把刚解锁的新包加入本轮旧回复的核验名单。

## b2+c1 → a4 → d1

```json
[
  {"id":"b2","title":"取得维修房卡"},
  {"id":"c1","title":"取得身份线索"},
  {"id":"a4","title":"档案核验成功","requires":{"all":[{"collected":"b2"},{"collected":"c1"}]}},
  {"id":"d1","title":"真相已确认","requires":{"collected":"a4"}}
]
```

档案事件包的触发条件设为 `b2 AND c1`，核验节点的完成效果设为 `{"collect":"a4"}`；真相事件包以 `a4` 触发，实际确认节点才产生 `d1`。结果 `requires` 再在结算时检查，作为第二道约束。得到 `b2+c1` 不会直接写入 `a4`，得到 `a4` 不会直接写入 `d1`。

`exclusive_with:["另一个结果ID"]` 声明互斥，取得前检查双向声明及同一笔效果中的冲突。物品“曾取得”适合结果 ID；物品当前是否仍持有、数量或可消耗状态使用变量，避免把永久历史事实当成持有量。

数值条件示例：`{"variable":{"id":"trust","op":"gte","value":30}}`。支持本地 number/boolean/string 定义。外部数值可在数据页映射只读的聊天变量路径，如 `stat_data.信任`；插件发送玩家消息前读取该路径并核对类型/范围。它不写回外部数据，也不自动识别 MVU、角色卡状态栏或消息变量协议。高级 JSON 中可用 `binding:{"type":"chat","path":["stat_data","信任"]}` 明确路径；包含点的键请使用路径数组。

## 检查和回退

启用前检查未定义 ID、缺少来源、没有入口的正向循环依赖、简单 AND 数值矛盾及明确互斥；OR 有可达入口时允许展开。暂时关闭的包仍按其定义检查结构，不把“关闭”误当成永久不可达。复杂否定、语义互斥、玩家行为是否可能和外部数值是否真的会改变仍需作者核对，静态检查不是完整剧情证明。

每次结算保留实际前提及本地效果，OR 记录本次满足的分支。关系图点击已取得的结果，可以预览并确认“回退此结果及其后续”。撤销该结果的来源结算，按保留来源重算，撤销实际依赖它的后续；保留独立来源。`b2` 回退示例撤销 `b2/a4/d1`，保留独立的 `c1`。回退会暂停剧本、清空旧待检任务、工作摘要和最近操作记录，防止旧异步回复再次结算；核对后继续。

若 OR 当时使用的是 `b2`，即便后来也取得 `c1`，回退 `b2` 仍撤销当时依赖它的结算。另一条前提可重新开放阶段，但不能替代旧实际经历。若有独立来源仍能提供同一前提，则保留依赖它的有效记录。

请先备份进度。新版以前取得的结果被视为基线，没有可追溯的来源，不能选择性回退；需恢复旧备份或用仍在最近 25 次内的普通回退。原来的“回退最近一次”仍用于逐步撤销近期操作。结算字典和来源记录会随已完成项目增长，保存紧凑元数据而不是长篇递归摘要；不承诺无限游玩占用恒定。改动旧结果/变量定义可能使重算不再安全，插件会拒绝该回退并提示恢复对应备份。

## 分析出错后的恢复

所有整理/分析请求在校验前保留收到的原始文本，最新一轮记录持久化。分析页“从后台 JSON 恢复分析草稿”可选择全文、分块或整合回复，读取、导出、修改 JSON，再本地校验，不额外请求 API。失败后自动展开已收到的回复。成功草稿需确认应用，当前运行项目不会被替换。

`completion_criteria` 应为字符串，`completion_exclusions` 应为字符串数组。可安全地把文本标准数组合为换行字符串、把排除项换行字符串拆为数组，并提示核对；对象、数字或混合数组拒绝，错误包含节点与字段。证据、摘录和 ID 校验仍执行，不由模型添加任意奖励。更新只迁移完全匹配旧默认的提示词，自定义提示词保留；自定义提示词须自行补入新版字段约定。

`finish_reason:length` 表示输出预算截断，与 600 秒等待限制不同；请在 API 页提高对应分析/整理输出 Token 或减少单次原文。截断内容保留供排查，不可作为完整草稿恢复。没有返回文本时，记录无法创造正文；空输入提示先粘贴或选择已保留回复。

单块恢复明确标记“部分草稿”，不等同于全篇。整合回复恢复会利用同次分块骨架并检查节点完整性；缺少本次上下文则拒绝误用。原文和处理方式须与选择的记录一致。分块沿用已核验结果和变量定义，合并保留条件证据。原始文本总保留上限 200 万字符，整合上下文过大时标记不可直接恢复；不会自动重试付费请求。导出原始记录不包含 API 设置、请求头或密钥。

## 验证范围

116 项单元测试通过。浏览器使用构建后的实际安装 JSON，在 1366px/390px/320px 验证事件包编辑、独立锁、确认/取消/Escape、筛选/缩放和滚动、发送后选择、完整 b2/c1/a4/d1 链、连带回退及失败原始回复修改恢复。原有七页布局、短摘要与 a/b/a1/ab 全流程、长文本等待和七类启动场景通过。全部使用模拟宿主和模拟 API，未调用用户付费服务；真实模型对故事的语义划分仍需安装后用用户原文验证。
