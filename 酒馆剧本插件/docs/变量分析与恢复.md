# 变量分析与恢复（v1.4.5）

旧提示“分析变量缺少包括初始值的原文依据”把四种问题混在一起：缺evidence、摘录不匹配、缺type/default、初始值与类型不符。新版分别显示变量名称、ID和字段原因。截图只能证明校验失败，不能确定其中哪一种。

## 自动分析

变量evidence和bounds_evidence仅差空白、Markdown标题或平衡粗体，并且连续文字唯一一致时，本地取回真实原文。文字、标点、数值变化或不连续拼接仍拒绝。明确type:number且default:"0"这类有限、可安全转换的数字字符串恢复为JSON数字；type缺失且已有JSON初始值时按其类型补齐。这不修改数值，不把空值变成0。不影响其他运行规则的精确证据校验。

既有known_variables直接沿用：跨块省略的初始值/类型/边界/依据使用已校验定义，不重新创造；明示冲突仍拒绝。

仍缺变量依据、原文初值字段或边界依据时，集中向辅助模型请求指定变量的证据；只允许补evidence、bounds_evidence及原定义缺失的type/default。已有默认值和上下限、节点条件、事件、次数及奖励不会被模型补修覆盖。回复须complete:true、指定ID全部且各一次，之后完整校验。节点与变量共用每片段/每次手动操作最多两次补修预算；两种错误交替也不能无限重试。真实调用次数记入分析记录。

补修模型返回complete:false则保留原始JSON与错误为“待配置”，不生成可执行草稿，不再重试猜值。只写了“达到60改变行程”，没有初始值，不能擅自当作0，也不能把60当初值；作者需补充明确规则。初始值缺失应在主分析报告uncertainties中保留变量及依赖它的数值原句，相关入口暂用false；模型若仍生成无依据变量，本地会拦截，原始回复不会丢失。

## 修复已有失败回复

更新完整安装JSON，确认标题v1.4.5。分析 → 恢复后台结果 → 选择失败回复 → 读取这份原始回复 → 校验后台结果并生成草稿（0API）。

回复列表区分正式分析、分段分析、节点来源补修和变量依据补修。补修回复只包含专用字段，缺少variables属正常；读取时可展开“补修前的变量定义（供排查）”查看原始变量。用户这次贴回的JSON是node_sources来源补修，不能据此确认alertness具体问题。

若仍是变量依据问题，点“补修来源或变量依据并恢复（必要时调用 API）”。不用重做整篇，原始失败回复与新补修回复都保留。成功后核对初始值、边界、奖励和条件，再点“转化为剧本、事件与分支”。分块恢复仍只代表该块。

类型非法、初始值与类型不符时，错误明确对应字段，作者可修改JSON后再本地校验。原文确实没有初始值时，应先在原文补充设计规则再分析，不伪造证据。截断输出不作为草稿；其他条件/完成/奖励证据错误、网络拒绝和取消不伪装成变量补修。

补修只属于作者的分析/恢复流程，不增加游玩每轮API。跨块补修用全篇依据，保存回复仍保留本块来源上下文；全篇超过输入预算会明确提示，不能悄悄裁掉规则。旧默认提示词精确迁移到新版，自定义提示词保留。
