# 分散证据与作者复核（v1.5.0）

## 分散证据

两处相隔的原文不能用省略号拼成一条连续引用。使用数组，逐条对应原文：

```json
"completion_evidence": [
  "信封里是一张临时访客凭证，背面写着今晚的日期。",
  "我拿起门卡时，他按住了我的手。"
]
```

完成、条件、奖励、结果、事件等证据字段支持1～8条连续引用。数组每条必须能精确匹配原文；节点完成依据还须对应所属分段。真正在原文连续存在的省略号无需拆开。

旧结果出现「原句……另一原句」时，本地先检查整句。如果不连续，只有拆出的每个片段均精确匹配原文，才恢复为引用数组。记录字段路径、原值和恢复值，规则不变。若片段改字、为空、找不到、超过数量或属于错误分段，拒绝放行。不会简单删除省略号，不把条件改成无条件。

错误一次列出所有相关节点/事件、字段及原因，区分拼接、原文未匹配、引用格式、数量等。需要修复时，模型只接收指定证据路径和原文；返回 complete:true、路径和值。未知、重复路径被拒绝；模型顺带改奖励、条件、编号的内容不执行。节点来源、变量依据和分散证据共享最多两次补修预算。

「恢复后台结果」先本地检查，能恢复时0次 API。原始回复在校验前保存，可导出；修复后的草稿与原始输出分别保存。截断的半份 JSON 仍不能当作完整剧本。

用户实际上传的 analysis-raw (1).json 验证：回复 stop 正常结束、7个节点、3处拼接证据本地恢复，其中2处完成依据、1处条件依据，0额外请求。此结果只证明格式恢复成功，不证明整个故事的规则语义都正确。

## 作者侧工作流

默认：规划分段 → 每段提取 → 每段独立复核 → 多段整合 → 本地转化 → 转化后复核 → 作者确认应用。作者阶段允许多次 API 调用，以发现遗漏与模型格式错误。

分析顶部先显示预计次数，正文编辑后更新：按当前字数估计段数N，有规划时加规划调用，N次提取、N次独立复核、多段时整合、最后复核。每段约3000字符，建议2000～4000字；全文建议每批2万～10万字，硬上限100万字符、512段。模型实际规划、缩段及复核分组会改变次数，实际与额外修补单独显示。

规划、提取、独立复核、合并、转化复核、来源/变量/证据补修使用不同且可编辑的提示词。可以设置独立复核模型；不填写则用同一服务模型进行独立调用，两次调用不是独立可信来源。

复核检查原文与规则的对应：完成/结束动作、分散证据、替代路径、AND/OR/NOT、互斥、代价、数值初值/边界/增减、可重复次数和停止门槛、节点及主体引用。缺规则不猜0、不编奖励。

每段发现语义错误，只重新提取该段并再次独立复核，最多两轮，计入额外调用。合法分段仍保留。长篇最终复核按输入预算分组，完整检查节点、事件、数值、结果、事件包和转换后的规则；单项超限停止，不截断规则。分组复核只能覆盖提供的局部与目录，跨全文复杂语义仍需作者核对。

复核输出必须完整且包含 complete:true 和 issues 数组。error 阻止应用；warning 留给作者核对。转化复核失败保留草稿及原始结果，当前剧本不替换；可编辑草稿后点击重新复核。修改草稿后旧复核签名失效，应用前再检查；已通过且未修改的草稿使用复核缓存，不重复调用。

复核报告不是剧本结果，恢复页应选择正式分析或补修回复。未完成全部分段、整合、复核的保留草稿明确标记 partial，不能说已完成整篇。
