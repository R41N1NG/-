## 1. 项目与用户目标

仓库：**`R41N1NG/-`，分支 `main`，私有仓库**。

这是供 **SillyTavern（酒馆）+ 酒馆助手（Tavern Helper / JS-Slash-Runner）** 使用的脚本插件，名称为“分支剧本与事件引擎”。用户最初要求参考原有 `tse_engine_tavern_helper_import.json` 的结构；该原文件一直保留，未改动。

自然语言中的实际行为由一个独立的辅助 API 判断。例如“请允许我为您把花插在头上”是否已经构成送花，不能靠关键词可靠判断。辅助模型核验发生情况并返回证据，脚本按预设规则执行好感度、收集等奖励。用户已经放弃部署本地小模型，不要再次把本地模型作为默认方向。

## 3. 用户特别强调的界面约定

### 入口与移动端

入口是可拖动的**铅笔图标**，支持鼠标和触摸。位置保存为归一化坐标，并约束在可视窗口内。拖动不会打开面板，拖动后的下一次点击能正常打开。桌面支持 `Alt+B`；宿主提供对应接口时可用 `/bse`。

面板含七页：运行、剧本、事件、记录、API、分析、数据。移动端要保证可滚动、无横向溢出、可视高度变化时仍可操作，按钮至少约 44px。

### 防剧透：运行区与剧本节点区分别锁定

“剧本”页只锁工具栏下方的**节点列表与节点编辑区**。v1.1.3 按用户新截图要求，在“运行”页另外锁定**接下来的分支、已收集、关系与状态**区。两个区域分别确认解锁，解锁一个不会自动解锁另一个。顶部导航、导入导出工具栏、运行页当前节点和完成/暂停等操作、API/事件等页面照常使用，不能锁住整个插件。

点击 🔒 显示剧透风险说明，确认后解锁，取消继续隐藏。两个锁定区均使用 blur、`inert` 和 `aria-hidden`，防止误点击、键盘进入和屏幕阅读器读取。解锁只在当前脚本运行期间对当前项目有效，刷新或新项目重新隐藏两个区域。解锁后分别可点击“🔒 隐藏节点”或“🔒 隐藏分支与状态”重新锁定；取消或 Escape 保持隐藏。

### 输入框上方直接显示分支

用户要的是“查看走廊”“搜寻阳台”这类**直接可点击的行动选项**，不是“分支剧本面板”这个打开管理界面的按钮，也不是带条件说明和“进入分支”的整张管理卡片。

当前实现（v1.1.3 开始提供）：点击“启用剧本”同时开启输入栏行动选项，运行页新增直接开关，数据页仍可设置；关闭管理面板后，只显示当前节点中无条件可用或已满足条件的出口标签。未解锁的选项不显示。暂停、关闭注入、没有可选出口时隐藏整行。

v1.2.0 点击后将行动文字加入酒馆输入草稿，可以改写或撤销，尚未发送时不推进。发送后按最终文字识别选择、重新验证本地条件、记录选择并注入目标节点用于同轮生成；不会自动发送。自由输入可识别，普通聊天或歧义保持当前阶段。初始快捷选项仍关闭；用户点击“启用剧本”会同时开启它。刷新/升级保留已保存的关闭设置，不会在初始化时强制改写。若旧设置中剧本已启用而选项关闭，点击运行页“显示输入栏选项”即可。

输入栏隐藏后恢复、被宿主重新创建或样式变化时，会重新检查可见输入区域并恢复/定位选项；插件卸载会清理观察器和待执行帧。

旧的酒馆助手快捷按钮“分支剧本面板”已移除；启动时只清理本脚本同名按钮，保留其他按钮。导入 JSON 中 `button` 为 `{ "enabled": false, "buttons": [] }`。

### “事件”页的意义

事件页用于“聊天中发生什么 → 更新什么”，例如实际送花且被接受 → 好感度 +1、获得收集记录。它包含发生标准、排除情况、前置条件、适用节点、主体对象、效果和重复策略。

已新增清晰步骤、效果文字预览、“用送花示例创建规则”和查看识别记录的入口。示例会创建数值变量、收集项和可编辑规则；手动确认直接执行本地变化，不调用 API；一次性规则完成后禁用再次确认按钮。

## 4. 已实现的核心功能与边界

| 项目 | 当前行为 |
| --- | --- |
| 剧本节点 | 稳定 ID、标题、短指引、详细原文、边界、出口、完成效果、相关变量 |
| 分支条件 | `all`、`any`、`not`、收集、完成/访问节点、事件完成、变量比较 |
| A/B 条件 | 示例支持 A+B → C，仅 A → D，仅 B → E；四种组合已有测试 |
| 完成节点 | 有完成标准时回复后辅助 API 自动核验，可关闭自动结算；人工确认仍可用；效果只执行一次 |
| 变量 | 数值、布尔、字符串；数值支持上下限；本地 `add`/`set` |
| 事件识别 | 辅助模型返回状态和连续原文证据，脚本验证引用及主体，再按配置结算 |
| 重复与回退 | 一次性或每条已接受回复一次，按来源去重；最多 25 条近期逆向操作用于回退 |
| 会话隔离 | 进度按聊天和项目保存；请求绑定 epoch、版本和来源指纹，旧结果不污染新状态 |
| 回复确认 | 阶段核验在生成结束后自动进行；独立事件仍默认手动识别与接受，事件自动模式在用户接话后检查上一条 |
| 导入导出 | 剧本内容 JSON 与聊天进度备份分开；均不导出 API 密钥 |
| 基础拆分 | API 按原文整理为编辑草稿，显式应用后才切换项目 |
| 长文分析 | 阶段、分支、结局、伏笔埋设/回收、待核对事项；长文自动分块后整合 |
| 状态栏接入 | 已有状态通知/读取和事件提交接口；没有实现通用酒馆状态栏渲染插件 |

辅助模型仅判断语义，不决定奖励。实际执行依赖本地预设规则。原文证据校验可以拦截虚构引用，不能保证语义理解完全正确。

大量事件先按启用状态、节点范围、条件和已完成记录筛选，再按预算分批发送；不应默认把所有事件设为全项目候选。默认每批 4 个、每轮最多 3 批，输入默认最多 16000 字符，识别输出默认 1024 Token。字符预算不是 Token 预算；无法保证每次只有极少 Token。

原文和事件库扩大主要影响读取、编辑与候选筛选。进度主要保存 ID、变量、短证据和变化，长期去重标记仍会增长，不能宣称存档永远恒定大小或完全没有性能成本。

### 长文本分析的具体约束

- 默认 `faithful` 忠于原文；`expand` 才允许建议性补写。
- 原文节点详细正文须为输入中的非空连续摘录。补写节点须 `suggested=true` 且详细原文留空。
- 原文有连续引用依据的结果定义、完成标准和条件保留为草稿，确认应用后可执行；缺少条件依据的出口被阻止并提示核对。未定义结果、虚构摘录拒绝；任意数值奖励和代码仍不应用。
- 节点和分析报告引用全部重映射，检查未知、重复和遗漏 ID。
- 最大 20 万字符、32 块、256 个节点。预算包含系统提示词、用户要求、JSON 转义后的实际消息内容。
- 分块分析后用一次全局合并请求联结走向、结局、伏笔；原文保存在本地。
- 支持进度、取消、草稿保存/编辑/导出。不会自动替换当前剧本。
- 伏笔答案和未来结局保留在分析报告中，不自动注入前期节点指引。

## 6. 历史讨论：时点、多事件与跨事件结果

用户提出：开局后，时点 1 注入事件 A，A 有多个分支与结局；时点 2 注入事件 B，B 的分支依赖 A 的完成情况；后续继续，并且事件可关联不同角色、地点和物品。

已讨论的方向是“**剧情阶段/时点 → 剧情事件 → 分支节点**”。前一事件保存紧凑的完成与结果事实，后一事件引用这些事实，而不是重新向主模型发送前一事件的全文。角色、地点、物品可作为触发条件；本地调度选择候选，辅助模型只需帮助确认正文中的相关变化。

建议把“时点”视作剧情进度阶段，而不是每收到一条 LLM 回复就自动推进。还要确定未满足触发条件时的策略：延期、跳过并记录未发生，或在指定阶段强制安排；否则后续依赖可能永久等待。

此段记录v1.2.1时的边界。v1.3.0已新增条件事件包、独立进度和交叉调度（见第13节）；完整的角色/地点/物品语义上下文触发界面仍未实现。packages剧情包与events行为识别规则分别负责调度和行为结算。

用户最新已明确授权并完成上述条件事件包实现；其他新方向仍按用户讨论/实现模式区分。

### 避免回归的实现细节

- 浏览器可能有名为 `module`/`require` 的全局变量。UMD 只有在 `typeof window === 'undefined'` 时才走 CommonJS 分支。
- `TavernHelper._bind` 方法绑定到当前脚本窗口，不绑定父窗口。
- 面板入口先挂载，再等待异步初始化；初始化失败需可见，不能静默退出。
- Touch pointer capture 下，拖动后点击和合成 click 要去重；不要随意恢复旧的拖动处理。
- Shadow DOM host 的 hidden 状态需有 `:host([hidden]) { display:none!important }`，否则样式可能使空快捷栏仍显示。
- 文件导入处理要在 await 之前保存输入元素引用；之后访问 `ev.target` 可能已为空。
- 输入地址/密钥失焦时不要立即重建整个 API 表单，否则会吞掉紧接着的“获取模型”或“测试”点击。v1.1.2 已改为局部更新路径预览和移除旧选择框。
- 保留表单草稿、焦点、滚动和 details 展开状态；节点解锁要求不能影响其他表单。
- 不删除异步 epoch、来源指纹、去重与事务保护；不能把晚到的 API 结果用于当前新聊天。
- 长文合并必须覆盖所有输入节点一次，不能用省略节点的结果冒充完整整理。
