# 丹杏·后台接入5

身份：gpt。2026-10-27（Asia/Shanghai）。这是独立角色卡后台的第一版；此前中控修复4仅为HUD内的只读调度器。

## 使用

下载 `downloads/danxing-backend-v1.zip`，解压并导入里面的JSON角色卡。启用酒馆助手的角色卡脚本“丹杏·后台状态中枢”以及HTML前端渲染。保留原零楼身份选择和四个原开场，建议新聊天验证；旧聊天仅在零楼有可解析的原开场时回放，不猜测无锚点存档的日期。

若本地酒馆助手未自动导入脚本，在“角色卡脚本”中新建一条，将本目录 `后台脚本.js` 全文粘贴并启用；同一角色卡只保留一个本脚本实例。无需打开监牢触发后台。界面出现“后台已同步”才表示原生快照已关联；出现“后台未同步”时仅为模型回报，不视为结算成功。

## 实际链路

原生聊天事件 → 宿主适配 → 纯回放引擎 → 各楼 `message.extra.zyx_backend` 与当前候选备份 → 聊天变量投影与当前真值注入 → HUD只读校验并展示。

- 八个专属state字段逐人监听。明确“在押”进入监牢，明确释放/脱困等移出；未知保留最后明确状态。传闻、计划、全局事件中偶然出现人名不会自动收监。
- 绝对时间从选定开场锚定，每楼只接受相对elapsed作为耗时申报，脚本累计；后续模型time不直接覆盖时钟。删楼、编辑、换候选按当前聊天重新回放，因此不会重复计时。模型仍负责申报“本轮经历了多久”，本版不是固定动作成本引擎，不能承诺模型不会谎报耗时。
- 原卡30日/月、12月/年，酉时/申时没有具体分钟时以时辰起点17:00/15:00锚定。半刻为450秒。五幕起始dayIndex为1/50/110/170/230，遵守原卡代码和日期，原注释的“第一幕50天”实际差一天。
- 情报暂为18件原卡信物的已确认件数。`clue_obtained=1`加`clues_gained`确切名称/ID数组才能入账；重复不增加，不自动领取第一个目标，未来幕次信物不提前登记。跨幕的本楼按行动开始幕次校验获取，再推进时钟。不包含未提供规则的可消费PI点数。
- 大势由后台日期决定，只注入当前幕正文。旧世界书保留，聊天变量 `zyx_time/zyx_clues` 同步供原EJS读取；新增后台系统注入提供当前真值。
- 18个原有场所节点可查阅，条件状态随后台重新派生。无明确数值条件的原卡描述标“条件待确认”。原卡相互矛盾的旅行耗时未任意择一，不点击即旅行，不附加虚构奖励。
- 地图仍为图包接口，不改成拓扑图；立绘配置原样保留。

## 文件职责

| 文件 | 责任 |
|---|---|
| 入口.js | 独立角色卡脚本启动、销毁 |
| 宿主适配.js | 宿主发现、聊天隔离、事件串行、原生落盘、变量merge、提示注入 |
| 引擎.js | 当前候选按序回放、羁押/时间/信物/节点状态派生 |
| 时钟.js | 耗时解析、年月日进位和五幕切换 |
| 规则.json | 原卡大势、18信物、18场所的配置数据 |
| 指纹.js | 原始正文/候选/开局与聊天前缀的陈旧检查，非密码学签名 |
| build.cjs | 静态CommonJS打包，生成后台脚本.js，无远程运行时依赖 |
| ../状态栏/后台投影.js | 校验chatId、候选指纹和前缀后读取快照，拒读旧候选或前序编辑后的旧状态 |
| ../状态栏/后台中控.js | 继续承担局部HUD调度，游戏状态写入在独立后台完成 |

节点gate支持 `startDay/endDay/minIntel/all/any`，all/any的每项可用 `{clue:"clue_1_1"}` 或 `{prisonControl:"掌控"}`。可同时限制日期、件数、持有物；endDay之后为expired。当前原卡没有完整日期/积分解锁表，生产配置未擅自套用测试里的示例门槛；也没有事件节点的进入、分支、结束、奖励事务。后续须补实际规则后实现，不能把场所查阅表称为完整事件链。

## 接口与存档

聊天变量合并写入 `zyx_time / zyx_clues / zyx_intel / zyx_nodes / zyx_custody / zyx_backend_current`，保留其他扩展变量。逐楼原生extra与当前swipe_info保留后台快照，随聊天原生导出；不修改剧情正文，不追加用户消息，不写共享世界书。候选/聊天切换后重算，不把旧页面写回新聊天。

调试：在后台脚本自身iframe的控制台查看 `DanxingBackend.getState()`、`getDiagnostics()`，可 `await DanxingBackend.sync()`。HUD iframe中的 `ZYX.runtime.getSnapshot()` 为本楼绑定数据。找不到Helper API、缺锚点或写后核验失败都保留诊断，不假称保存成功。

生成开始前同步并注入已完成前缀；生成时不读取新流式正文，结束/停止后再处理完整报告。Helper写消息使用普通message+extra分支且refresh:none，避免仅extra被忽略或swipes分支错用。
