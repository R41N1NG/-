## 使用

下载downloads/danxing-start-map-fix3.zip，解压导入JSON，选名字末尾“开场地图修复3”的卡并新建聊天。启用角色正则与酒馆助手HTML前端。

零楼选身份、修改配置后，点击“确认身份 · 进入开场”，直接切换真实第0楼到卡内对应候选，不再只把设置填进输入栏。不自动发送玩家消息或调用模型生成开场。对应关系：锦衣缇骑→候选1、黑狱恶差→候选2、江湖任侠→候选3、身世自设→候选4（候选0仍为菜单）。四段开场原文作为卡内候选保留，运行时只展开user/char宏并在选中那段后附折叠卷宗。

姓名、年龄、身份、境界、掌握武学与场景设置随选中候选保存。当前身份原规则从四个确切身份条目按名称核实，只选中者写入该卷宗，供模型读取；不再在选身份过程中修改共享变量或世界书。原47条世界书含四身份条目的原disabled状态不变，避免其他聊天被串改。

HUD可从第0楼已提交卷宗和同候选extra重建主角初始信息，重新加载后仍生效；随后玩家的新开局登记可重新建立基线。不会把任意AI正文里的开局字符串当已提交设置。

地图入口现在是图片查看器。大地图、黑狱图默认未配文件，显示“地图图包尚未接入”；已删除拓扑节点、路线与建筑示意。后续AI填写状态栏/地图配置.json的baseUrl、images（id/label/file），或同源宿主ZYX_DANXING_MAPS。仅按显式图片地址加载，不猜文件、不生成替代图、不推进地点或时间。人物立绘与地图图包的实际文件仍待后续接入。

## 开场切换边界

只允许新聊天尚只有菜单第0楼时提交。页面安装即绑定chatId与原零楼指纹；旧A页面不能在切到B后把B的新菜单覆盖。确认、重试和写入前都核对绑定，不在确认时懒绑新聊天；安装时接口不可用则要求重载。提交锁阻止双击；已有剧情、正在生成或零楼被编辑时拒绝覆盖。

使用真实Helper的swipes/swipe_id分支，连同swipes_info与swipes_data写入；不混传message/data（会让Helper走错误分支）。写后核对实际mes、候选与索引。刷新抛错时先回读判断是否已写入，不自动重复覆盖或回滚；保存走Helper正常流程，不宣称磁盘原子持久。输入框草稿不动、发送0次。
