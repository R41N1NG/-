## 文件与接入

- `预览.html`：可直接打开的离线交互页面。演示数据是明确标注的虚构测试快照，不代表当前存档。
- `状态栏实拍.png` / `状态栏展开.png`：真实Chromium桌面root截图。
- `状态栏正则.json`：两条按顺序使用的显示层规则（正常渲染、异常完整记录保护）。
- `样式.css` / `模板.html` / `build.cjs`：可维护源文件，执行`node build.cjs`重建导出正则与预览。
- `apply.cjs`：应用到用户这张CCv3卡的工具，输出新文件，拒绝覆盖输入或已存在的输出。

在本目录运行：

```sh
node apply.cjs "原卡.json" "丹杏-状态栏版.json"
```

工具只替换唯一的`ZYX_02_状态栏HUD渲染`，保留原ID，在其后插入/重定位`ZYX_02B_状态栏异常记录保护`；重复应用不重复插入。原零楼网关、世界书、提示词、首条消息和其它规则保持原样。需保留原卡03流式隐藏规则。没有把零楼HTML顺手装入原卡，因为其网关仍为原有HTML_SOURCE占位入口，属于另一项接入任务。

也可在酒馆正则编辑器中替换原02，并将02B放在其后；不要在原02后重复追加另一个正常渲染规则。导出的JSON是两规则列表，不假定所有插件版本都支持整列表导入；不支持时分别复制配置，或使用apply工具生成完整卡。

两条新增规则均为AI输出位置、仅显示层（markdownOnly=true，promptOnly=false），不把大量界面HTML传入模型上下文。新卡中的03/04规则原样保留；本轮未重写历史状态栏清理策略。角色卡正则导入后还需在实际酒馆确认角色正则启用和HTML样式保留；浏览器检查不能代替实际宿主验收。

## 协议与边界

按照原卡FORMAT_RULE顺序读取字段，可缺项，不支持任意重排、重复标签或在字段内夹杂HTML。普通字段仅接受纯文本；副人物只提取五个白名单子标签。有效记录转换为原生HTML/CSS，完整异常块转换为固定提示，不把异常载荷放进模板。未闭合流式片段仍由原卡03规则隐藏。宿主仍应保留自身消息净化；这不是通用HTML净化器，不处理剧情正文中的任意HTML。

原卡EJS读取`zyx_time`、`zyx_clues`等变量，但上传卡内没有提供参考的完整HUD核心、后台日历引擎或地图桥。本轮只显示已有状态栏字段：不心算日历、不补造幕次倒计时、不根据clue_obtained=1猜信物名称、不建立新持久化真值。参考中的daqian变量、GM写入、升级算法、人物名册及立绘URL不移植。待后续明确后台方案后再接真实变量及地图。

原始两份附件及其完整内容没有提交到Git；仓库交付本次界面、适配代码、虚构示例、有限测试与截图。
