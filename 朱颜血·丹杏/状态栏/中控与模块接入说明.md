# 中控与模块接入

身份：gpt。当前为中控修复4。

每个HUD只创建一个局部runtime，统一消费当前聊天/楼层并调度数据模块；不跨iframe复制中控实例，不往父窗口覆盖全局状态。代码按职责分开，build.cjs只负责按依赖顺序打包，不承载剧情状态判断。

| 文件 | 责任 | 依赖/边界 |
|---|---|---|
| 羁押名册.json | 八人key/name/tag/alias/立绘键/原设资料 | 不存本次在押事实，无初始true |
| 羁押追踪.js | 明确专属字段的时序折叠、筛选在押 | 纯函数；不吃全局传闻、不写变量 |
| 玩家武学回放.js | 主角开局与明确境界/技能 | 不混入NPC或把练习算掌握 |
| 状态记录回放.js | 33字段白名单、截至本楼回放/时间日志 | 历时各楼独立，不沿用最后一楼 |
| 宿主桥.js | 聊天/楼层绑定、宿主事件与回退轮询 | 只读、事件可解绑 |
| 后台中控.js | create/register/start/refresh/subscribe/stop/dispose | scope/view/live明确分离；快照只读 |
| 交互控制器.js | 按钮/弹窗/立绘加载/数据渲染 | 从runtime拿数据，不另算羁押 |
| 本地图包.js + 立绘配置.json | 明确人物图片地址 | 不猜目录/扩展名，不扫描图包 |
| 地图组件.js + 地图配置.json | 图片地图查看 | 不画拓扑、不移动/推进时间 |
| 模板.html + 各CSS | 呈现 | 不混业务判断 |
| 核心输出协议.txt | 每轮模型状态明报格式 | 当前标识ZYX_STATUS_PROTOCOL_V6 |

构建顺序：静态JSON配置→武学→羁押→状态记录→立绘→地图→宿主桥→中控→界面，共9个data脚本。改字段必须同时更新核心协议、build字段列表、隐藏快照与解析；只改UI或一个encoded模块会断链。

runtime.register接收唯一名字及derive(context)，可选dispose；context包含source/chat/cutoff/snapshot/get。已注册数据模块是martial和status，注册顺序决定get能读取的前序模块。刷新返回冻结的scope/view/live；getFullRoster和getImprisonedList给副本，不允许查询方修改权威状态。subscribe返回解绑函数，dispose清理模块与宿主监听。

当前接口是只读调度，不等于GM写入、独立全酒馆后台服务或MUV结算。将来需要修改状态，先定义可回放的授权输入协议，再接写入命令；不要仿照旧setPrisonerOverride只发未被监听事件却声称完成改值。
